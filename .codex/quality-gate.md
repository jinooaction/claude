# Codex 품질 관문

이 점검표는 `AGENTS.md`의 작업 운영 규칙을 실제 작업 표면에 강제하기 위한 로컬 기준이다. 중요한 변경을 완료했다고 말하기 전에 이 순서로 확인한다.

## 1. 문제 정의

- 요청을 한 문장으로 설명할 수 있는가.
- 실제 목표가 요청 문구와 다를 수 있는지 확인했는가.
- 이번 작업의 비목표를 정했는가.
- 잘못 바꾸면 깨지는 안전장치, 자동화, 인계, 배포, 돈 경로를 확인했는가.
- SDD 적용 판단을 했는가: 새 기능이면 `/speckit-*` 흐름, 기존 기능 보정이면 원래 스펙·테스트·PR 본문 중 어디에 판단 기록을 남길지 정했는가.
- 완료 기준이 검증 가능한 형태인가.

## 2. 위험 등급

- 등급 0: 실행 동작이 바뀌지 않는 설명, 조사, 단순 문서 오탈자.
- 등급 1: 일반 코드나 테스트 변경.
- 등급 2: 훅, 설정, 워크플로, 운영 문서, 스킬, 인계, 머지 흐름 변경.
- 등급 3: 헌법, 커널 목록, 위험 게이트, 주문 제한, 감사 로그, 비밀값, 배포 제한, 외부 API 안전장치 변경.
- 등급 4: 실제 주문, 실거래 전환, 자본 배분, 계좌 노출, 라이브 전략 교체, 운영자 비용 가능성.

애매하면 더 높은 등급을 적용한다.

## 3. 탐색

- 관련 파일을 실제로 읽었는가.
- 설정이나 훅을 바꾸면 입력, 실행 경로, 출력, 대체 수단을 확인했는가.
- 기능 코드를 바꾸면 호출부, 테스트, 설정, 문서, 명령줄 진입점을 확인했는가.
- 제거·축소라면 무엇을 없애고 무엇이 대체하는지 확인했는가.
- SDD 산출물을 생략하거나 줄였다면, 그 이유가 위험 등급과 새 동작 여부 기준으로 설명되는가.

## 4. 내부 역할 점검

- 구현자: 요청을 작고 정확하게 구현했는가.
- 검토자: 반례, 빠진 호출부, 중복, 오래된 문서, 깨지는 흐름은 없는가.
- 안전 담당자: 안전 경계, 돈 경로, 감사 가능성, 되돌림 가능성은 보존됐는가.
- 인계 담당자: 다음 세션이 상태와 이유를 재구성할 수 있는가.

## 5. 검증

- 코드 변경: 관련 테스트와 필요한 경우 `uv run pytest`.
- 린트 대상 변경: `uv run ruff check src tests`.
- 문서·설정 변경: 형식 검증, 참조 경로 확인, 중복·충돌 확인.
- 등급 2 이상: 실제 적용 경로 확인.
- 등급 2 이상: `uv run python scripts/agent_harness_probe.py --strict`로 기본 운영 통제,
  첫 판단 품질 과제, 레드팀 과제, HANDOFF 사실 검증이 함께 살아 있는지 확인한다.
- 등급 2 이상: `uv run python scripts/check_handoff_facts.py`로 `HANDOFF.md` 요약표가
  실제 `origin/main`과 맞는지 별도 확인하고 PR 본문 `## 하네스 검증`에 두 결과를 남긴다.
- 실행하지 못한 검증은 최종 보고에 남긴다.

## 6. 완료 관문

- 요청을 정확히 만족했다.
- 변경 범위가 목표에 충분하고 과하지 않다.
- 위험 등급에 맞는 탐색과 검증을 했다.
- 제거한 기능의 대체 수단 또는 의도적 제거 이유가 분명하다.
- 사용자 변경을 되돌리지 않았다.
- 다음 세션이 같은 파일과 기록을 보고 같은 상태를 이해할 수 있다.
