# 스펙 040 — 라이브 캐너리 포트폴리오 가드형 무장 채널

## 문제

스펙 039 가 보수적 라이브 포트폴리오 설정(`canary-live-portfolio.toml`)을 준비했지만, 그걸
실거래로 *실행*하는 안전한 채널이 없었다. 운영자: "지금 소액 라이브 캐너리 무장 ($500)."
실제 실행은 돈이 움직이는 되돌릴 수 없는 행동이라, 다중 안전장치를 갖춘 가드형 채널이 필요하다.

## 목표

고도화(추세 방어 포트폴리오)를 *소액 실거래*로 운용하되, **기본은 드라이런 미리보기**(주문
0건)이고 운영자가 명시 무장(센티넬 `armed: true`)할 때만 실주문이 나가는 가드형 워크플로.

## 한 일

- **`.github/workflows/rebalance-live-canary.yml`** — 가드형 실거래 채널:
  - 트리거: `workflow_dispatch` + `automation/rebalance-live.request` 센티넬 push.
  - **기본 드라이런 미리보기**(`rebalance-once --dry-run`, 주문 0건) — "실거래로 무엇을 살지"만
    보여줌. 실주문은 센티넬 `armed: true` 일 때만(`--mode live --confirm-live`).
  - **자본 상한 $1,000 하드 가드**: 이 설정의 캡은 소액($500)에 맞춰 큼(%)이라 capital>$1,000
    이면 무장 거부(footgun 차단).
  - 라이브 트랙 측정(NAV 스냅샷 + `forward-verdict --mode live` + 칼마) → 실거래도 같은 잣대로.
  - 사이드카 `automation/rebalance-live-canary-last-run` 에 미리보기·결과 발행.
- **`automation/rebalance-live.request`** — 무장 센티넬, **기본 `armed: false`**(미리보기 전용).
- 센티넬 기본 비무장 안전 회귀 테스트.

## 안전장치 (다중)

1. **기본 드라이런** — 머지해도 실주문 0건(미리보기만). 실주문은 명시 `armed: true`.
2. **자본 상한 $1,000** — 워크플로가 초과 시 무장 거부.
3. **`--confirm-live` 인터록** — CLI 가 강제(없으면 라이브 거부).
4. **K1 캡 천장** + **스펙 014 손실 서킷 브레이커**(halt_gate → 한도 초과 시 주문 거부, 킬스위치).
5. **추세 필터**(스펙 036) — 추세 아래면 현금(드로다운 방어).
6. **라이브 거래 집합 무확대** — SPY·MSFT·AAPL 만(헌법 II).

## ⚠ 무장 전 운영자 체크리스트 (이 슬라이스에 포함 안 됨)

- 사이드카 드라이런 미리보기 확인(무엇을 사고팔지 납득).
- **룰 워커 충돌 해소**: 같은 실계좌에 `canary-live-rules.toml` 워커가 돌면 포트폴리오 재조정과
  충돌(스펙 039 블로커). 무장 전 룰 워커를 비활성으로 전환.
- 그 뒤 `armed: true` 로 센티넬 머지.

## 안전 경계

- **이 머지는 드라이런 미리보기만 발화**(`armed: false`) — 실주문 0건, 돈 0 이동.
- **Kernel 터치 0건.** 워크플로 + 센티넬 + 테스트. 기존 라이브 워커·페이퍼 트랙 무변경.
- 헌법 X.4: 라이브 전환은 운영자 결정. 소액 캐너리 무장 전용, 풀라이브 아님.

## 합격 기준

- **SC-040-1** 워크플로 YAML 유효, 실주문 스텝은 `armed == 'true'` 게이트.
- **SC-040-2** 커밋된 센티넬은 기본 `armed: false`(안전 회귀 테스트).
- **SC-040-3** 전체 테스트·린트 통과.
