# Feature Specification: 급락 후 회복 확인 단타 연구

**Feature Branch**: `codex/191-shock-recovery-research`  
**Created**: 2026-09-21  
**Status**: 사전등록  
**Input**: 기존 한국투자 계좌용 단타 실사용 프로그램의 막힘을 해결하고 대안을 검증한다.

## User Scenarios & Testing

### User Story 1 - 결과를 보기 전에 연구 가설을 고정 (Priority: P1)

운영자는 이미 실패한 조건을 유리하게 고치는 대신, 급락 이후 회복 확인이라는
구별되는 가설을 유한한 후보군으로 검증하고 싶다.

**Why this priority**: 기존24후보는 가혹 체결비용에서 수수료를 제거해도 손실이다.
**Independent Test**: 사전등록이 정한4후보만 생성되고 과거 입력만으로 신호가 결정된다.

**Acceptance Scenarios**:
1. **Given** 미개봉 후보 성과, **When** 연구 조건을 등록하면, **Then** 후보4개·기간·비용·판정 기준의 지문이 고정된다.
2. **Given** 완결된 과거 봉, **When** 미래 봉의 값을 바꾸면, **Then** 기존 시점의 진입·청산 신호는 바뀌지 않는다.

### User Story 2 - 실제 개발 자료로 탈락 여부 확인 (Priority: P1)

운영자는 고정 후보의 비용 후 수익·거래 수·미청산 수를 실제 장부와 함께 확인한다.

**Independent Test**: 개발 자료만 제공해4후보의 두 비용 조건을 재생하고 동일 결과를 재현한다.
**Acceptance Scenarios**:
1. **Given** 정확한 개발1645일, **When** 실행하면, **Then**4후보의 기준/가혹 비용 성과와 장부를 모두 보존한다.
2. **Given** 전 후보가 최소 조건 미달, **When** 판정하면, **Then** 선택 없음과 개별 탈락 이유를 기록한다.
3. **Given** 개발 조건을 넘은 후보, **When** 표시하면, **Then** 확인검증 필요 상태이며 실거래 가능으로 표시하지 않는다.

### User Story 3 - 결과를 재계산하고 검증 자료 보호 (Priority: P2)

운영자는 결과가 바뀌거나 탈락 자료가 반복 덮어써지는 것을 막고 싶다.

**Independent Test**: 변조 결과·장부·계약·다른 기간 입력을 거부하고 원본 재계산과 일치 여부를 확인한다.
**Acceptance Scenarios**:
1. **Given** 저장된 결과, **When** 원본에서 재계산하면, **Then** 결과와 장부가 정확히 같아야 한다.
2. **Given** 이미 있는 출력 경로, **When** 다시 실행하면, **Then** 기존 결과를 보존하고 실패한다.
3. **Given** 이 연구 도구, **When** 어떤 결과가 나오더라도, **Then** 새 확인495일을 읽거나 주문·자금 배정을 수행하지 않는다.

### Edge Cases

급락만 있고 회복이 없는 날, 회복했지만 상승 여유가 없는 날, 임계값과 같은 가격,
조기 폐장·불완전 봉, 다음봉 갭 상승, 손절선 아래 갭 하락, 부분체결·거래량0,
마지막봉 진입, 재진입, 청산 실패, 조정가격과 실행가격 불일치, 비유한 값.

## Requirements

### Functional Requirements

- **FR-001**: 후보는15/30분 × 앵커 도달/장마감 청산의4개로 사전 고정한다.
- **FR-002**: 당일 첫 봉 시가를 앵커로 고정한다. 직전 완결봉 종가가 앵커 대비124bp 이상 하락하고 현재 완결봉 종가가 직전 고가를 초과하며 앵커/현재종가−1이82bp 이상일 때만 진입 신호를 낸다.
- **FR-003**: 두 청산 방식 모두 진입 기준가격 대비82bp 이상 하락한 완결봉 종가에서 손절 신호를 낸다. 앵커형은 앵커 이상 종가에서 추가로 청산한다. 모든 체결은 다음봉이며 손절가격 보장은 없다.
- **FR-004**: 종목별 하루 한 번의 매수 시도만 허용하고, 종가 전 청산할 다음봉을 확보한다. 진입 미체결도 시도를 소비한다.
- **FR-005**: 기존177의 종목·자본·비용·참여율·다음봉 체결·당일 청산 의무를 유지한다. 기존177/190 후보 결과에 영향을 주지 않는다.
- **FR-006**: 이미 관측된2013-08-23~2020-03-06의 정확한1645일 입력만 개발로 사용한다. 다른 자료·합성·불완전 입력은 거부한다.
- **FR-007**: 개발 후보는 기준/가혹 비용 순수익 모두 양수, 기준 청산200개 이상, 양쪽 미청산0을 모두 충족해야 확인검증 대기 후보가 된다. 선정 순서는 기준 Sharpe 내림차순·낙폭·회전금액·식별자 오름차순이다.
- **FR-008**: 모든 결과는 실거래 부적격·자본0·주문0이다. 개발 선정은 최종 합격이 아니며 기존177/181 합격·전진관찰·실행 동등성 조건을 대체하지 않는다.
- **FR-009**: 후보·계약·입력·코드·결과·장부 지문을 보존하고 원본부터 재계산 검증한다. 기존 출력과177/190 결과를 덮어쓰지 않는다.
- **FR-010**: 새495일은 이 기능에서 읽지 않는다. 향후 확인검증은 선택 고정, 기존18+190의6+신규4=28시도 이상 보정, 시간 분리, 기존 합격 기준을 별도 구현·검증한 후에만 허용한다.
- **FR-011**: 신호 시 상승 여유와 다음봉 실행 시 여유는 구별해 표시한다. 기존 시뮬레이터의 체결봉 전체 거래량 사용과 조정가격 한계를 기록한다.

### Key Entities

- 사전등록: 후보4개, 신호/청산 정의, 개발 자료 지문, 변경 불가 비용과 판정 조건.
- 개발 결과: 후보별 두 비용 성과, 탈락 이유, 선택 여부, 여전히 남은 확인검증 의무.
- 연구 장부: 신호·기준가격·체결·비용·수량·청산 손익과 지문.

## Success Criteria

### Measurable Outcomes

- **SC-001**:4후보 모두 두 비용 결과를 재현하고 실패를 누락하지 않는다.
- **SC-002**: 미래 값 변경, 임계값, 재진입, 청산 실패, 변조에 대한 반례 검사를 통과한다.
- **SC-003**: 실제 개발 자료로 결과/장부의 원본 재계산 일치를 확인한다.
- **SC-004**: 새 확인 자료 접근0, 주문0, 자금 배정0을 유지한다.

## Assumptions

124bp는 기존 기준 편도31bp의4배,82bp는 가혹 편도40bp의 왕복 손익분기80.3213bp를
넘기는 정수 폭이다. 최적 추정치나 수익성 증거가 아니다. 가설이 틀리면 탈락을 보존한다.
수수료 확인은 선행 차단 조건이 아니며 기존25bp를 그대로 쓴다.
연구 기능 완성은 전체 단타 실사용 목표 완료가 아니다.
