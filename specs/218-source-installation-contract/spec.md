# Feature Specification: 검토 소스·설치 입력과 고정 이미지의 연결 계약

**Feature Branch**: `codex/218-source-installation-contract`  
**Created**: 2026-10-17 KST  
**Status**: 설계 문서 검토 대상  
**Input**: 216 뒤 원래 검토 소스·정확 Git ROOT/HEAD·의존성 lock/설치 입력과 고정 이미지의 연결을 먼저 설계한다.

## User Scenarios & Testing

### User Story 1 - 원래 검토 소스를 보존한다 (Priority: P1)
운영자는 같은 파일처럼 보이는 복사본과 정확히 검토한 저장소를 구분할 수 있어야 한다.
**Why this priority**: 기존 등록의 정확 코드 커밋을 다른 값으로 바꾸면 관찰 기간의 의미가 달라진다.
**Independent Test**: 계약의 입력·검증·거절 표로 동일 내용/다른 커밋과 Git 정보가 없는 복사본을 구분한다.
**Acceptance Scenarios**:
1. 검토 입력이 정확하고 전체 소스가 같으면 원래 저장소·기존 실행 지문·전체 파일 지문을 각각 연결하도록 요구한다.
2. 내용은 같아도 커밋이 다르거나 저장소가 외부에 의존하면 연결 불가로 남기고 등록을 변환하지 않는다.

### User Story 2 - 설치 입력과 결과를 따로 연결한다 (Priority: P2)
운영자는 의존성 목록, 실제 받은 설치 파일, 설치된 내용, 이미지의 서로 다른 역할을 볼 수 있어야 한다.
**Why this priority**: 버전 이름이나 이미지 지문 한 개로 공급망·설치 결과 전체를 증명할 수 없다.
**Independent Test**: 같은 소스·목록에서 설치 파일 또는 이미지 하나가 바뀐 반례가 거절 표에 있다.
**Acceptance Scenarios**:
1. 직접·간접 의존성, 빌드 도구, 기반 실행환경을 각 원래 입력과 연결하도록 요구한다.
2. 원래 설치 바이트·출처·플랫폼 증거가 없으면 현재 설치 폴더 비교 성공과 무관하게 미평가로 남긴다.

### User Story 3 - 설계 완료와 실제 실행을 구분한다 (Priority: P3)
다음 세션은 비밀 없는 합성 실험부터 구현하고 이번 문서를 실제 후보 설치 허가로 쓰지 않는다.
**Why this priority**: 현재 실주문 복구 초안과 별개로 연구 환경의 안전한 구현 순서를 유지해야 한다.
**Independent Test**: 입력 한도·후속 시험·중단 조건·되돌림과 현재 승인 대기 작업이 명확하다.
**Acceptance Scenarios**:
1. 216의 끝난 합성 실험을 재실행하지 않고 새로운 연결 반례를 별도로 구현하도록 요구한다.
2. 실제 후보 설치·등록·인증 수집·실주문은 이번 완료 대상에서 제외한다.

### Edge Cases
외부 Git 포인터, 숨긴 수정, 얕은 복제, 누락 객체, 과거 비밀이 든 이력, 설치 파일 바꿔치기,
소스 배치 변경, 지문만 위조한 선언, 검사 후 변경, main 동시 배포를 quickstart의 반례로 검토한다.

## Requirements

### Functional Requirements
- **FR-001**: 이번 산출물은 명세·계획·작업·자료 구조·증거 계약·후속 시험표다. 새 설치기/검증기/실행기/등록 소비자는 만들지 않는다.
- **FR-002**: 독립 검토 입력, 원래 저장소 전체 내용, 기존 실행 소스 지문, 설치 입력, 설치 결과, 기반 이미지·실행 설정을 서로 다른 식별자로 연결해야 한다.
- **FR-003**: 정확 후보 ROOT와 원래 커밋을 유지한다. 전체 내용이 같다는 이유로 다른 커밋을 받거나 main HEAD로 대신하지 않는다.
- **FR-004**: 비밀·계좌·운영 장부·캐시·인증 설정을 포함한 운영 폴더나 운영 `.git`의 통째 복사를 금지한다. 저장소 이력의 비밀 여부도 별도 검토하며 미확인이면 반입하지 않는다.
- **FR-005**: 저장소의 독립성·분리된 HEAD·깨끗한 전체 바이트 상태를 새 연결 조건으로 요구한다. 이를 기존 등록기가 이미 검증한다고 쓰지 않는다.
- **FR-006**: 의존성 목록과 실제 설치 입력의 지문·출처·플랫폼·전이 관계 및 설치 결과의 전체 내용 연결을 요구한다. 버전 문자열이나 자체 보고만으로 인증하지 않는다.
- **FR-007**: 원래 관측·원본 지문·검토 입력과 출력의 정확 연결을 보존하고 누락은 null/미평가로 남긴다. 소급 서명·자동 재등록·관찰 시계 초기화는 없다.
- **FR-008**: 후속 구현의 비밀 없는 GitHub 합성 입력·호출·출력 한도와 거절 반례를 고정한다. 실제 후보 코드·키·가격·계좌는 입력하지 않는다.
- **FR-009**: 기존 등록 HMAC·독립 재계산·90초·60세션·31/40bp·200거래·현금/정산/부분체결·최소36시도·495미개봉을 보존한다. 실제 자격 소비는 별도 안전 경계 변경이다.
- **FR-010**: 216 완료와 현재 main/실제 서버 관측/PR895 승인 대기를 구분해 인계한다. 문서 반례를 실행 통과 개수로 집계하지 않는다.

### Key Entities
독립 검토 입력, 원래 저장소 증거, 설치 입력 명세, 설치 결과 증거, 이미지 연결 영수증.
각 지문은 내용 일치의 식별자이며 그 자체로 작성자·출처·권한 인증은 아니다.

## Success Criteria
- **SC-001**: FR-001~010 모두 계획·계약·후속 반례로 추적 가능하다.
- **SC-002**: 열여섯 후속 반례의 기대 거절/미평가와 보존할 원래 증거가 빠짐없이 정의된다.
- **SC-003**: 소스/설치 입력/설치 결과/이미지/권한 중 하나만 확인한 경우를 전체 인증으로 표시하지 않는다.
- **SC-004**: 정확 검토 문서의 형식·참조·하네스·GitHub 전체 회귀·린트와 종료 원본을 재현 가능하게 남긴다.
- **SC-005**: 실행 기능 제거0, 기존 돈/등록/수집 경로 변경0이며 후속 구현의 착수·중단 조건이 분명하다.

## Assumptions
이번은 등급3 안전 경계 설계이며 실행 권한 확장이 아니다. 실제 공급망 진위·후보 환경·기반 전범위·지속 불변은 미평가다.
전체181 미완료와 goal usageLimited를 유지한다. 실주문 경로 PR895의 별도 승인 대기를 이 문서로 해소하지 않는다.
