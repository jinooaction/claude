# 검토 소스·설치 입력 연결 계약

## 1. 독립 기대값과 원래 입력
검토된 정확 commit/tree와 전체 경로별 바이트·Git 모드 기대값을 먼저 고정한다.
기존 source_identity는 별도로 그대로 계산하며 전체 tree 지문으로 대체하지 않는다.
각 lock/원래 배포 파일/빌드 도구·명령·전이 관계·대상 플랫폼을 별도 지문으로 묶는다.
검토 입력의 신뢰 주체/인증이 없으면 선언 미인증을 남긴다. 자체 생성한 이미지 metadata를 기대값으로 삼지 않는다.

## 2. 저장소 경계
후보 모듈의 기존 ROOT 계산식이 후보의 원래 Git 저장소를 가리켜야 한다.
main과 같은 절대 경로를 강제하지 않는다. wheel로 소스를 옮겨 ROOT가 site-packages를 가리키면 거절한다.
HEAD는 정확 원래 commit이고 tree도 일치해야 한다. 같은 tree/다른 commit은 계속 거절한다.
detached/clean은 새 조건이며 기존 등록기 자체의 검사라고 부르지 않는다.
전체 추적 파일 바이트와 Git 모드를 원래 tree/blob에 재대조하고 추가/누락/수정 파일도 거절한다.
인덱스만 믿지 않고 assume-unchanged/skip-worktree·필터/줄바꿈 변환·sparse 은폐를 거절한다.
초기 지원 범위에서 shallow/partial clone·누락 객체·gitlink/submodule·외부 .git 포인터/
symlink/hardlink·alternates·replace/graft·실행 hook·인증/remote 설정 반입을 거절한다.
검사 시 Git 환경 주입·외부 설정·fsmonitor·필터 등 보조실행을 차단하고 원래 대상 저장소만 읽는다.
구현이 임의 사용자 저장소 설정/refs/훅을 고치거나 정리하는 기능을 제공하면 안 된다.
후속 초기 실험은 새 생성한 단일 초기 커밋만 사용한다. 실제 프로젝트 소스와 전체 이력은 반입하지 않는다.
실제 이력/소스 지원은 비밀·라이선스·완전성의 별도 검토 없이는 열지 않는다.

## 3. 설치 입력과 이미지
pyproject·lock·설치 파일·빌드 도구·기반 환경의 역할을 분리한다.
원래 바이트 지문 없는 파일, 미고정 전이 의존성, 플랫폼 불일치는 거절한다.
후속 초기는 장난감 비실행 입력만 사용하고 실제 패키지 설치/빌드 스크립트를 실행하지 않는다.
실제 wheel/sdist를 지원할 후속 단계는 빌드 격리·네트워크 차단·전체 설치 결과 비교를 별도로 구현해야 한다.
그 단계에서는 해시를 고정해도 악성 입력 실행 위험이 사라지지 않음을 유지한다.
기반 manifest/platform·빌드 imageID·containerID/config는 서로 다른 필드다.
정확 이미지 내부의 소스/저장소/설치 입력을 독립 기대값에 대조한 원래 출력을 남긴다.
216 Python 기반에 Git이 있는지 이번에 실행 확인하지 않았다. Git 없이 가짜 HEAD 응답기를 넣지 않는다.
실제 Git/loader/native를 쓸 단계는 검토된 원래 실행파일·의존성·출처를 고정하기 전 기동하지 않는다.
확인 전 입력 변조/검사 후 바꿔치기/main 동시 갱신은 독립 이미지 경계를 다시 검증해야 한다.
동일 imageID만으로 hostkernel·mount·관리자 변경·공급망 진위/지속 불변을 인증하지 않는다.

## 4. 후속 합성 구현의 한도와 거절
GitHub Linux 비밀 없는 runner만 사용하고 Mac에서는 작은 순수 검증만 한다.
초기 새 생성 장난감 저장소는 추적64파일·합계1MiB, 생성 Git 객체 포함8MiB, 독립 입력선언64KiB,
가짜 설치 입력16파일·합계1MiB, 한 명령20초/이미지 준비180초, 출력64KiB/영수증32KiB,
전체 lab12분을 최대값으로 둔다. 이를 실제 프로젝트 지원 한도로 해석하지 않는다.
한도 초과·타입 불일치·누락·외부 의존/동시변경이면 원래 실패를 보존하고 start0 또는 연결불가를 기록한다.
비밀 없는 새 생성 fixture 외 임의 경로·이미지·실행파일·원격 주소를 입력받는 범용 도구를 만들지 않는다.
기동은 기존216의 create→같은 containerID의 created inspect→start 규칙을 보존한다.
오류 출력에 경로·환경·키·계좌·원문 명령 전문을 싣지 않는다. 실패/cleanup 실패 시 성공 영수증0.

## 5. 기존 안전 경계 / 되돌림
정확 code_commit/기존 ROOT/서버 HMAC/독립 연구 재계산·60세션/90초·등록 시간은 그대로다.
새 계약을 등록/forward/권한 소비자에 연결하거나 기존 등록을 변환·재서명하지 않는다.
기존 전략/예산/계좌/수집기/시각기록기/장부세대/실제 자동배포·예약·주문은 변경0.
되돌림은 독립 문서·포인터·새 CI 경로 제거 PR이며 원래 장부/등록/고정 자산을 수정하지 않는다.
FR-001/007/009/010→본 절, FR-002/003/005→1·2절, FR-004→2절, FR-006→3절, FR-008→4절.
