# 스펙 032 — 검증 교리: 최근 데이터 백테스트(발굴) + forward 페이퍼(확인)

## 운영자 원칙 (2026-06-01, 두 번의 대화로 정련)

1차 지적: "2026년인데 너무 과거 데이터만 쓰는 것 아닌가? 폭락장(2008·2000)도 결국 과거다."
2차 교정: **"옛 데이터로 전략을 찾는 것도 중요하다. 다만 너무 과거가 아니라 최근 5개년처럼
기준만 명확히 하면 되는 것 아닌가?"**

이 교정이 핵심이다. **백테스트는 전략을 발굴·적합하는 일급 도구다 — 폐기 대상이 아니다.**
문제는 백테스트 자체가 아니라 *너무 오래된* 데이터를 쓰는 것이었다. 해법은 백테스트를
"필터로 강등"하는 게 아니라, **데이터 최근성 기준을 명확히 못 박는 것**이다.

## 기준 1 — 데이터 최근성 (명확하게 코드로 강제)

`backtest/recency.py` + 모든 평가 CLI 의 `--trailing-years N`(기본 5).

- **트레일링 창**: 평가 구간을 임의로 잡지 않고 "가용 데이터의 가장 최근 N년"으로 고정한다
  (`to` = 가장 최근 세션, `from` = `to` − N년). "최근 5개년"이 기계적으로 강제된다.
- **신선도 등급(오늘 대비 가장 최근 바의 나이)**: fresh(≤6개월) / aging(≤2년) / stale(>2년).
  CLI 는 매 실행마다 신선도 배너를 출력하고, **stale 이면 큰 경고**를 단다("이 데이터는 옛
  regime 을 측정한다"). 운영자 우려를 막연한 철학이 아니라 *명확한 신호*로 만든다.

예: 현재 적재된 2013-2018 데이터셋은 2026 기준 ~3,000일(8년) 전 → **stale 경고**가 뜬다.
즉 "최근 5개년" 원칙상 이 데이터는 발굴용으로도 부적합하다 — 더 최근 데이터가 필요하다.

## 기준 2 — 과적합 방어 (최근 데이터 안에서도)

최근 데이터라도 한 기간에 과적합할 수 있다. 그래서 발굴 단계 자체에 가드를 둔다:
`portfolio-walk-forward` 가 표본 외(워크포워드) 구간 분할 + 디플레이티드 샤프(시도 횟수
보정, 스펙 027)로 평가한다. "여러 설정 돌려 제일 좋은 걸 골랐다"를 통계로 처벌한다.

→ **1·2 기준을 통과한 백테스트 결과는 진지한 후보다.** "필터일 뿐"이 아니라, *최근 데이터에서
표본 외·다중검정 보정을 통과한 전략* 이라는 일급 증거다.

## 기준 3 — forward 페이퍼 확인 (배포 전 마지막 관문, 보완재)

백테스트가 아무리 최근이어도 결국 과거다. 그래서 *배포 전에* 현재 데이터로 한 번 더 확인한다
— 대체가 아니라 보완이다. `rebalance-once --mode paper` 를 인스턴스에서 주기 실행(워크플로
`rebalance-paper-forward.yml`)해 라이브 시세로 가상 체결(ORDER_PAPER_FILLED)을 누적하고,
성과 엔진(스펙 011) + 디플레이티드 샤프(스펙 027)로 *시간상 미래* 표본에서 엣지를 재확인한다.
돈은 움직이지 않는다.

## 기준 4 — 라이브 캐너리 (운영자 게이트, 실제 돈)

1~3 을 통과하고 *나서야* 라이브 캐너리. 헌법 X.4 + go-live-canary 채널 + 운영자 명시 게이트.
자율 승격 0건(스펙 026 게이트 + IX.B-2).

## 이 컨테이너의 데이터 제약 (정직한 한계)

네트워크 정책상 라이브 시세 API(KIS·Yahoo·Stooq)는 막히고, github raw 공개 데이터셋은 전부
옛것(2018까지)이다. 즉 **이 컨테이너에서는 진짜 "최근 5개년(2021-2026)" 데이터를 받을 수
없다.** 최근 데이터의 출처는 둘뿐이다:
- **라이브 인스턴스가 자체 적재한 최근 바**(워커가 매일 수집) — 인스턴스에서 `ingest`/백테스트.
- **forward 페이퍼 트랙**(기준 3) — 현재 데이터로 앞으로 쌓임.

따라서 "최근 5개년 백테스트"의 운영 위치도 라이브 인스턴스다(이 컨테이너는 옛 데이터로
*도구를 만들고 검증*하는 곳). recency 가드가 stale 데이터에 경고를 달아 이 한계를 가시화한다.

## 무엇이 바뀌나 (이전 over-correction 교정)

- 백테스트는 **여전히 전략 발굴의 1차 도구**다. 직전 문서가 이를 "필터일 뿐"으로 깎았던 것은
  과한 반대였다 — 운영자 교정으로 바로잡는다.
- 바뀐 것은 단 하나: **데이터에 명확한 최근성 기준(트레일링 N년 + stale 경고)을 강제**한다.
  너무 과거 데이터로 맞춘 전략은 recency 가드가 걸러낸다.
- forward 페이퍼는 백테스트의 *대체*가 아니라 배포 전 *확인 관문*이다.
