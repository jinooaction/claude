# 기능 명세: 읽기 전용 모바일 운영자 앱

**기능 브랜치**: `codex/178-flutter-operator-mobile`  
**작성일**: 2026-09-02  
**상태**: 구현·자동 시험·시뮬레이터 검증 완료, 실제 iPhone 설치는 무료 프로필 한도 대기
**입력**: 운영자가 자동매매 프로그램을 모바일에서 이용하고, 선택한
`Claymorphism + Vibrant & Block-based` 스타일로 디자인 설계와 1차 앱을 이어서 진행해 달라고 요청함.

## 문제 정의

현재 자동매매 시스템은 서버와 GitHub 자동화에서 동작하며 모바일 상태판과 텔레그램 알림도
있다. 그러나 운영자가 휴대폰에서 전체 상태, 실제 돈 경로, 다음 자율 작업, 개입 필요 여부와
각 자동화의 신선도를 빠르게 이해할 수 있는 전용 앱은 없다. 첫 버전은 공개된 정제 상태만
읽어 보여주고, 휴대폰에서 주문이나 안전 중단 해제를 수행하지 않는다.

## 사용자 시나리오 및 시험 *(필수)*

### 사용자 이야기 1 - 지금 상태를 한눈에 확인 (우선순위: P1)

운영자는 앱을 열어 자동매매 전체 상태, 실제 돈 경로, 돈 경로 정렬, 다음 자율 작업,
개입 필요 여부와 마지막 갱신 시각을 한 화면에서 확인한다.

**이 우선순위인 이유**: 모바일 앱의 첫 가치는 복잡한 자동화 기록을 읽지 않고도 현재 상황을
몇 초 안에 이해하는 것이다.

**독립 시험**: 정상·주의·위험 예제 상태를 각각 열고 5초 안에 전체 판정과 다음 행동을
찾을 수 있는지 확인한다.

**인수 시나리오**:

1. **Given** 신선하고 정상인 상태가 발행됨, **When** 운영자가 앱을 엶,
   **Then** 전체 상태와 네 개 핵심 요약, 마지막 갱신 시각이 정상으로 표시된다.
2. **Given** 개입 필요 상태가 발행됨, **When** 운영자가 홈을 봄,
   **Then** 원인과 다음 행동이 최상단에서 색상 외 문구·아이콘으로 함께 표시된다.
3. **Given** 실제 주문 경로가 무장 상태임, **When** 운영자가 홈을 봄,
   **Then** 이를 단순한 “정상”으로 축약하지 않고 주의 상태와 확인 대상을 보여준다.

---

### 사용자 이야기 2 - 자동화 세부 상태를 확인 (우선순위: P2)

운영자는 핵심 자동화와 보조 보고를 구분해 각 항목의 상태, 마지막 실행 시각, 허용 신선도,
설명과 근거 기록 링크를 확인한다.

**이 우선순위인 이유**: 문제가 있을 때 원인을 찾을 수 있어야 앱이 단순 신호등을 넘어
실제 운영 도구가 된다.

**독립 시험**: 일부 정상, 일부 지연, 일부 누락인 예제에서 위험도가 높은 항목이 먼저
노출되고 각 상세 내용과 원본 기록 링크를 열 수 있는지 확인한다.

**인수 시나리오**:

1. **Given** 자동화 상태가 섞여 있음, **When** 운영자가 자동화 목록을 봄,
   **Then** 핵심 항목이 보조 항목보다 먼저 나오고 위험·지연 항목이 명확히 구분된다.
2. **Given** 근거 기록 주소가 있음, **When** 운영자가 기록 보기를 선택함,
   **Then** 앱 밖 읽기 전용 원본 페이지가 열리고 앱에서 외부 변경은 수행되지 않는다.

---

### 사용자 이야기 3 - 오래되거나 끊긴 정보에 속지 않기 (우선순위: P1)

운영자는 네트워크가 끊기거나 상태 발행이 늦었을 때 마지막으로 받은 값을 현재값으로
오해하지 않고, 자료가 언제 생성됐으며 왜 신뢰할 수 없는지를 확인한다.

**이 우선순위인 이유**: 금융 운영에서 오래된 정상 표시는 명확한 실패 표시보다 위험하다.

**독립 시험**: 네트워크 끊김, 최초 실행 실패, 30시간 이상 지난 상태, 깨진 상태 문서를
각각 주입하고 어떤 경우도 초록색 정상으로 표시되지 않는지 확인한다.

**인수 시나리오**:

1. **Given** 이전에 받은 상태가 있고 현재 네트워크가 끊김, **When** 앱을 다시 엶,
   **Then** 마지막 상태는 볼 수 있지만 오프라인과 생성 시각이 고정 표시된다.
2. **Given** 한 번도 정상 상태를 받은 적이 없음, **When** 조회가 실패함,
   **Then** 빈 값을 정상으로 추측하지 않고 “상태를 확인할 수 없음”을 보여준다.
3. **Given** 상태 형식이 손상되거나 알 수 없는 상태값이 포함됨, **When** 앱이 읽음,
   **Then** 해당 항목을 주의 이상으로 표시하고 원문을 정상값으로 바꾸지 않는다.

---

### 사용자 이야기 4 - 친근하지만 정확한 금융 화면 사용 (우선순위: P2)

운영자는 선택한 클레이모피즘 스타일의 큼직한 카드와 선명한 정보 위계로 작은 휴대폰에서도
상태를 읽는다. 장식 때문에 숫자와 경고 의미가 가려지지 않는다.

**이 우선순위인 이유**: 선택한 개성은 유지하되 금융 상태는 빠르고 정확하게 읽혀야 한다.

**독립 시험**: 작은 화면, 글자 확대, 밝은 환경, 색각 구분이 어려운 조건에서 핵심 문구와
상태 의미가 유지되는지 확인한다.

**인수 시나리오**:

1. **Given** 기본 글자 크기와 작은 휴대폰, **When** 홈을 스크롤함,
   **Then** 잘린 핵심 문구나 겹친 카드가 없다.
2. **Given** 글자 크기를 크게 설정함, **When** 모든 화면을 탐색함,
   **Then** 상태, 제목, 다음 행동과 시간 정보가 읽을 수 있게 재배치된다.
3. **Given** 색상을 구분하기 어려움, **When** 정상·주의·위험 상태를 봄,
   **Then** 문구, 아이콘, 테두리 형태만으로도 상태를 구분할 수 있다.

### 경계 상황

- 전체 상태와 개별 자동화 상태가 서로 모순되면 개별 위험을 숨기지 않고 모순을 표시한다.
- 생성 시각이 미래이거나 해석할 수 없으면 신선하다고 판단하지 않는다.
- 일부 상태만 누락되면 남은 값을 보여주되 전체를 정상으로 단정하지 않는다.
- 새 상태값이 추가되어 구버전 앱이 모르면 원문과 “알 수 없음”을 함께 표시한다.
- 예제 자료와 실제 공개 자료는 명확한 배너로 구분하며 예제 금액을 실제 자산으로 표시하지 않는다.
- 외부 기록 링크가 잘못됐거나 열리지 않아도 앱 상태 화면은 유지된다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 기존 모바일 상태판과 동일한 정제된 공개 운영 상태를 읽어야 한다.
- **FR-002**: 시스템은 전체 판정, 한글 요약, 다음 행동, 기준 시각과 기준 변경 식별자를 표시해야 한다.
- **FR-003**: 시스템은 실제 돈 경로, 다음 자율 작업, 돈 경로 정렬, 개입 필요의 네 핵심 영역을 표시해야 한다.
- **FR-004**: 시스템은 핵심 자동화와 보조 보고를 구분하고 각 항목의 상태, 설명, 생성 시각,
  경과 시간과 허용 신선도를 표시해야 한다.
- **FR-005**: 시스템은 정상·주의·행동 필요·위험·지연·누락·알 수 없음 상태를 색상 외 문구와
  아이콘으로도 구분해야 한다.
- **FR-006**: 시스템은 마지막 성공 자료를 기기에 보관하고 네트워크 실패 시 오프라인 표시와 함께 제공해야 한다.
- **FR-007**: 시스템은 자료 생성 후 30시간을 넘었거나 생성 시각을 신뢰할 수 없으면 전체 상태를
  신선한 정상으로 표시하지 않아야 한다.
- **FR-008**: 시스템은 최초 조회 실패, 손상된 문서, 필수 필드 누락과 알 수 없는 상태값을
  실패 폐쇄 방식으로 표시해야 한다.
- **FR-009**: 시스템은 사용자가 직접 새로고침하고 갱신 성공·실패와 최종 성공 시각을 확인할 수 있게 해야 한다.
- **FR-010**: 시스템은 홈, 자동화, 설명의 세 탐색 영역을 제공해야 한다.
- **FR-011**: 시스템은 근거 기록을 읽기 전용 외부 페이지로 열 수 있게 하되 앱 안에서 원격 변경을 수행하지 않아야 한다.
- **FR-012**: 시스템은 주문, 실거래 활성화, 안전 중단 해제, 자본 배분, 전략 변경,
  허용 종목·한도 변경 기능을 포함하지 않아야 한다.
- **FR-013**: 시스템과 발행 자료는 KIS 비밀값, 계좌번호, 접근 토큰, 서버 SSH 정보와
  원시 거래 데이터베이스 내용을 포함하지 않아야 한다.
- **FR-014**: 시스템은 공개 자료에 없는 실제 잔고, 보유종목과 손익을 추측하거나 예제 값으로 대체하지 않아야 한다.
- **FR-015**: 예제 자료를 사용하는 미리보기는 모든 화면에 “예제 데이터” 표시를 유지해야 한다.
- **FR-016**: 화면은 따뜻한 아이보리 배경, 진한 남색 윤곽, 일관된 오프셋 그림자,
  연분홍·하늘색·초록 강조색과 둥근 블록 카드를 사용해야 한다.
- **FR-017**: 모든 핵심 터치 영역은 최소 44×44 논리 픽셀이며, 글자 확대와 화면 읽기 도구에서
  핵심 정보 순서와 의미를 유지해야 한다.
- **FR-018**: 시스템은 자료 형식 버전을 확인하고 지원하지 않는 상위 버전을 정상으로 해석하지 않아야 한다.
- **FR-019**: 공개 상태 발행은 기존 HTML 상태판을 유지하면서 앱용 구조화 문서를 함께 제공해야 한다.
- **FR-020**: 구조화 문서의 내용은 같은 실행에서 생성된 HTML 내 상태와 의미상 동일해야 한다.

### 핵심 개체

- **모바일 상태 묶음**: 형식 버전, 생성 시각, 기준 변경, 출처와 읽기 전용 안전 선언을 가진 최상위 자료.
- **운영자 요약**: 전체 판정, 한글 제목, 다음 행동, 핵심 운영 영역과 알림 판정.
- **자동화 상태**: 자동화 식별자, 중요도, 상태, 마지막 실행 시각, 경과 시간, 허용 신선도와 설명.
- **캐시 상태**: 마지막 성공 자료, 저장 시각, 온라인 여부와 예제 자료 여부.
- **디자인 토큰**: 색상, 글꼴 역할, 간격, 모서리, 윤곽, 그림자와 상태별 표현 규칙.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 정상·주의·위험 예제에서 운영자가 5초 안에 전체 상태와 다음 행동을 찾는다.
- **SC-002**: 자료 누락·손상·30시간 초과·미래 시각 시험의 100%가 신선한 정상 이외 상태로 표시된다.
- **SC-003**: 발행된 HTML과 구조화 문서의 전체 판정·자동화 수·운영 요약이 100% 일치한다.
- **SC-004**: 앱과 구조화 문서에서 비밀값·계좌번호·접근 토큰 검출 건수가 0건이다.
- **SC-005**: 앱이 발생시키는 주문·자본·전략·허용 종목·안전 중단 해제 변경은 0건이다.
- **SC-006**: 지원 대상 작은 화면과 200% 글자 크기에서 핵심 상태 문구가 잘리거나 가려지는 경우가 0건이다.
- **SC-007**: 모든 핵심 상태가 색상을 제거해도 문구와 아이콘으로 구분된다.
- **SC-008**: 네트워크가 끊긴 재실행에서 마지막 성공 자료와 오프라인·생성 시각 표시가 함께 보인다.
- **SC-009**: 전체 자동 시험, 정적 검사, 운영 하네스와 인계 사실 검사가 모두 통과한다.

## 가정

- 첫 사용자는 한 명의 운영자이며, 첫 버전은 공개되고 정제된 운영 상태만 소비한다.
- 기존 모바일 상태판 주소와 자동화 사이드카가 첫 버전의 유일한 원격 자료 원천이다.
- 첫 릴리스는 iPhone을 우선 검증하되 같은 화면 코드는 Android에서도 실행 가능하게 유지한다.
- 실제 잔고·보유종목·손익은 인증된 비공개 자료 경로를 별도 설계한 뒤 후속 기능으로 추가한다.
- 긴급 중단도 서버 인증·감사·재전송 방지 계약을 별도 명세로 만든 뒤 후속 기능으로 추가한다.
- 앱 표시명은 `오토 인베스트`, 내부 패키지명은 `auto_invest_mobile`을 기본값으로 한다.

## 비목표

- 자동매매 엔진을 휴대폰에서 실행하거나 KIS에 직접 연결하지 않는다.
- 휴대폰에 KIS·GitHub·서버 자격증명을 저장하지 않는다.
- 수동 주문, 실거래 재무장, 중단 해제, 자본 사다리나 전략 변경을 지원하지 않는다.
- 공개 자료에 없는 실제 자산·손익·체결 내역을 표시하지 않는다.
- 기존 웹 상태판이나 텔레그램 알림을 제거하지 않는다.

## 위험 등급과 안전 의미

이 기능은 운영자가 현재 상태를 해석하는 새 운영 표면과 상태 발행 자동화를 추가하므로
**등급 2(운영 체계 변경)**다. 브로커 호출, 실제 주문, 자본 배분, 안전 경계 변경은 없으므로
등급 3·4에는 해당하지 않는다. 기존 HTML·텔레그램 경로를 그대로 남겨 앱 장애가 거래 엔진이나
기존 관측 수단을 막지 않게 한다.

## 되돌림

앱용 구조화 문서 발행을 중단하고 앱 배포를 철회해도 기존 HTML 모바일 상태판, 텔레그램 알림,
자동매매 worker와 돈 경로는 그대로 동작해야 한다. 되돌림은 브로커 상태, 자본, 전략, 데이터베이스,
비밀값 또는 헌법을 수정하지 않아야 한다.
