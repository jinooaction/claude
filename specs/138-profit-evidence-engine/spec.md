**Feature Branch**: `codex/profit-engine-redesign`
**Created**: 2026-08-16
**Status**: Complete
**Input**: User description: "시스템을 뿌리까지 다시 설계해도 되니 돈 벌 수 있는 상황과 방법을 찾아내고, 목표 기능으로 만들어라."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 실제 수익 후보를 시간 분리로 찾기 (Priority: P1)

운영자는 설명용 후보가 아니라, 개발에 쓴 과거와 최종 평가 구간이 분리되고 비용까지 차감된 투자 방법 중에서 실제로 벤치마크보다 더 벌면서 덜 잃은 후보를 보고 싶다.

**Why this priority**: 현재 시스템은 후보 계약을 계속 만들었지만 검증 가능한 전략 설정으로 컴파일하지 못해 `NO_EDGE_YET`를 반복했다.

**Independent Test**: 고정된 공개 월간 데이터와 사전등록 후보 집합을 입력하면 개발 구간에서 하나의 후보만 선택하고, 선택에 쓰지 않은 2007년 이후 구간에서 수익·샤프·낙폭·비용 후 성과를 한 번 평가한다.

**Acceptance Scenarios**:

1. **Given** 1971년 이후 정렬된 주식·채권·금 월간 데이터, **When** 수익 증거 엔진을 실행하면, **Then** 후보 선택 구간과 최종 검증 구간은 겹치지 않고 선택된 설정과 전체 시행 횟수가 기록된다.
2. **Given** 최종 검증에서 후보의 비용 후 연복리와 샤프가 벤치마크보다 높고 최대낙폭이 벤치마크의 80% 이하인 경우, **When** 인접 추세 창에서도 같은 위험조정 우위가 유지되면, **Then** 엔진은 `HOLDOUT_EDGE`를 보고한다.
3. **Given** 최종 검증 조건 중 하나라도 실패한 경우, **When** 엔진을 실행하면, **Then** 엔진은 수익 엣지를 확정하지 않고 실패 조건을 항목별로 남긴다.

---

### User Story 2 - 장기 우위와 최근 부진을 섞어 폐기하지 않기 (Priority: P2)

운영자는 한 전략이 장기 역사 검증에서는 통과했지만 최근 전진 검증에서는 아직 기준 미달일 때, 이를 완전 실패로 오해하지 않고 다음 관찰 단계로 분리해 보고 싶다.

**Why this priority**: 현재 후보 결과 실행기는 여러 명령의 결과를 하나로 합치면서 최근 실패가 장기 `RETURN_EDGE`를 덮어쓴다.

**Independent Test**: 장기 검증 `pass`와 최근 검증 `fail`을 함께 입력하면 각 증거 축이 그대로 보존되고 전체 상태는 `pending`이 된다.

**Acceptance Scenarios**:

1. **Given** 장기 검증은 통과하고 최근 검증은 실패한 후보, **When** 후보 결과를 집계하면, **Then** `historical_backtest=pass`, `recent_oos=fail`, `walk_forward=fail`, 전체 `pending`을 반환한다.
2. **Given** 모든 필수 증거가 통과한 후보, **When** 결과를 집계하면, **Then** 전체 `pass`를 반환한다.
3. **Given** 모든 필수 증거가 실패한 후보, **When** 결과를 집계하면, **Then** 전체 `fail`을 반환한다.

---

### User Story 3 - 검증 후보를 자동 관찰 경로에 연결하기 (Priority: P3)

운영자는 가장 유망한 실제 설정이 예약 실행에서 다시 평가되고, 전진 관측의 확률 기준을 통과하기 전까지는 실주문으로 넘어가지 않기를 원한다.

**Why this priority**: 일회성 로컬 분석은 다음 세션과 자동화가 재현할 수 없으며, 현재 후보 이력 수집은 `globalfixed` 설정을 누락한다.

**Independent Test**: 예약 실행 정의와 이력 지원 명세를 검사하면 `global-trend-fixed-portfolio.toml`의 읽기 전용 이력 수집과 수익 증거 보고서 생성이 연결되어 있고 거래 명령은 존재하지 않는다.

**Acceptance Scenarios**:

1. **Given** 예약 실행 환경, **When** 수익 증거 엔진이 실행되면, **Then** 공개 데이터와 최신 forward leaderboard를 읽어 기계 판독 JSON과 한글 보고서를 발행한다.
2. **Given** 최종 검증이 통과했지만 forward PSR 또는 다중검정 기준이 미달인 경우, **When** 보고서를 발행하면, **Then** 상태는 `FORWARD_VALIDATION`이고 실제 주문·자본 배분은 허용하지 않는다.
3. **Given** 후보 이력 수집 명세, **When** 지원 목록을 생성하면, **Then** `global-trend-fixed` 데이터베이스와 포트폴리오가 포함된다.

### Edge Cases

- 공개 데이터의 날짜가 서로 정렬되지 않으면 평가하지 않고 명시적 입력 오류를 낸다.
- 개발 구간 또는 최종 검증 구간이 최소 120개월보다 짧으면 수익 엣지를 판정하지 않는다.
- 후보 점수가 같은 경우 더 단순하고 회전이 적은 설정을 결정론적으로 선택한다.
- 비용 차감 후에만 통과 여부를 판정하며 비용이 0이어도 시행 횟수와 가정을 기록한다.
- 최신 forward leaderboard가 없거나 후보 행이 없으면 역사 검증은 보존하되 `FORWARD_VALIDATION` 이상으로 올리지 않는다.
- 장기·최근 검증 명령 중 일부가 시간 초과되면 해당 축은 `pending`이고 다른 축의 결과는 보존한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사전등록된 추세 창 4개와 자산배분 3개 조합만 탐색하고 전체 시행 횟수를 기록해야 한다.
- **FR-002**: 시스템은 후보 선택용 개발 구간과 선택 후 단 한 번 평가하는 최종 검증 구간을 시간상 겹치지 않게 분리해야 한다.
- **FR-003**: 시스템은 모든 후보 수익률에서 연간 보수적 비용을 차감한 뒤 성과를 계산해야 한다.
- **FR-004**: 시스템은 최종 검증에서 비용 후 연복리·샤프·최대낙폭·칼마를 같은 벤치마크와 비교해야 한다.
- **FR-005**: `HOLDOUT_EDGE`는 비용 후 연복리와 샤프가 벤치마크보다 높고 최대낙폭이 벤치마크의 80% 이하이며 인접 추세 창에서도 샤프·낙폭 우위가 유지될 때만 허용해야 한다.
- **FR-006**: 시스템은 선택된 후보의 설정, 개발 점수, 최종 검증 지표, 벤치마크 지표, 통과·실패 조건, 인접 파라미터 결과를 기계 판독 형식으로 내보내야 한다.
- **FR-007**: 시스템은 장기 역사 검증, 최근 표본 외 검증, 전진 분할 검증을 서로 다른 증거 축으로 저장해야 한다.
- **FR-008**: 시스템은 증거 축이 섞인 경우 전체 후보를 실패로 폐기하지 않고 `pending`으로 보존해야 한다.
- **FR-009**: 시스템은 `global-trend-fixed-portfolio.toml`과 `data/forward_globalfixed.db`를 읽기 전용 후보 이력 지원 목록에 포함해야 한다.
- **FR-010**: 시스템은 최신 forward leaderboard에서 선택 후보의 PSR, 판정, 관측 수를 결합하되 역사 검증만으로 `EDGE_CONFIRMED`를 선언해서는 안 된다.
- **FR-011**: 예약 실행은 브로커 API, 주문, 자본 배분, 실거래 재무장, 라이브 전략 변경, whitelist/caps, 비밀값 변경을 수행해서는 안 된다.
- **FR-012**: 같은 입력에는 같은 후보와 같은 판정이 나와야 한다.
- **FR-013**: 단위·통합 테스트는 시간 분리, 비용 차감, 결정론적 선택, 혼합 증거 보존, 안전 명령 경계를 검증해야 한다.

### Key Entities

- **ProfitCandidate**: 자산배분 방식과 추세 창으로 완전히 정의된 하나의 사전등록 투자 방법.
- **TemporalSplit**: 후보 선택에 쓰는 개발 구간과 선택 후 평가하는 최종 검증 구간.
- **PerformanceEvidence**: 비용 후 연복리, 샤프, 최대낙폭, 칼마와 벤치마크 대비 통과 조건.
- **ProfitEvidenceReport**: 선택 후보, 시행 횟수, 시간 분리, 인접 설정 견고성, forward 관측, 안전 상태를 묶은 결과.
- **EvidenceAxis**: 역사 백테스트, 최근 표본 외, 전진 분할 검증 각각의 독립 상태.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 한 번의 실행이 정확히 12개 사전등록 후보를 평가하고 개발·최종 검증 구간 중복 0개월을 증명한다.
- **SC-002**: 실제 1971년 이후 데이터 실행에서 최소 한 후보의 통과 또는 실패 이유가 수익·샤프·낙폭·인접 파라미터 네 축으로 완전하게 설명된다.
- **SC-003**: 장기 통과·최근 실패 입력에서 세 증거 축의 상태가 100% 보존되고 전체 상태가 `pending`이 된다.
- **SC-004**: 수익 증거 예약 실행과 후보 이력 수집 경로에서 실주문 가능한 명령 수는 0개다.
- **SC-005**: 같은 고정 입력을 2회 실행했을 때 선택 후보와 모든 판정 필드가 동일하다.
- **SC-006**: 전체 회귀 테스트, 린트, 엄격 하네스, 인계 사실 검증이 모두 통과한다.

## Assumptions

- 공개 월간 주식·채권·금 데이터는 기존 스펙 047과 같은 원천과 파서를 재사용한다.
- 최종 검증 시작은 2007년으로 고정해 금융위기, 코로나 충격, 2022년 주식·채권 동반 약세를 포함한다.
- 거래비용과 상품 보수의 합산 보수값은 기본 연 50bp로 두며 결과에 명시한다.
- 이 기능은 수익 후보를 발견·검증·관찰 경로에 올리는 연구 기능이다. 기존 `Backtest -> Canary -> Full`과 자본 사다리 관문을 통과하기 전에는 실제 돈을 움직이지 않는다.
- 이번 변경은 헌법, 커널 목록, 손실 예산, 주문 한도, 허용 종목을 수정하지 않는다.
