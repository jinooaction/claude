# Feature Specification: Lot-Aware Execution Proxy

**Feature Branch**: `Codex/141-lot-aware-execution-proxy`
**Created**: 2026-08-16
**Status**: In Progress
**Risk Grade**: 4 - 실제 주문 종목과 정수 주 산정 경로 변경

## User Scenarios & Testing

### User Story 1 - 검증된 신호를 소액 정수 주 주문으로 표현하기 (Priority: P1)

운영자는 검증된 `SPY/IEF/GLD` 신호를 바꾸지 않으면서도 단 1 자본 293달러로 실제 시장
노출을 만들고 싶다. 고가 기준 ETF 때문에 주문이 영원히 0건이면 안 되며, 같은 경제적 노출의
사전 승인된 저가 ETF만 체결에 사용해야 한다.

**Independent Test**: 현재 신호 비중 `SPY=1/3`, `GLD=1/6`, 자본 293달러와 현재 대체 ETF
가격을 입력하면 캡 안에서 `SPYM`과 `GLDM` 주문이 각각 1주 계획되고 기준 ETF 주문은 나오지 않는다.

### User Story 2 - 실제 계좌만 보유 원본으로 사용하기 (Priority: P1)

운영자는 과거 모의 체결 장부의 `AAPL` 같은 종목을 실제 계좌 보유로 오인해 매도하는 일을
원하지 않는다. 라이브 미리보기와 실주문은 같은 KIS 보유·매수가능현금 스냅샷을 사용해야 한다.

**Independent Test**: 내부 DB에 모의 보유가 있고 KIS 스냅샷에는 `ORANY`만 있을 때, 모의
보유는 주문 계획에 나타나지 않고 `ORANY`는 비관리 보유로 보류되며 자동 매도되지 않는다.

### User Story 3 - 대체 체결이 전략 변경으로 번지지 않게 하기 (Priority: P1)

운영자는 저가 ETF가 신호 계산이나 자본 사다리 증거를 바꾸지 않고, 누락·중복·허용되지 않은
매핑이면 주문 전에 실패하기를 원한다.

**Independent Test**: 매핑 키 누락, 중복 체결 종목, 화이트리스트 불일치, KIS 시세·현금 조회
실패를 각각 주입하면 실주문이 0건이고 오류 또는 보류 증거가 남는지 확인한다.

### User Story 4 - 실제 주문 실패와 체결 증거를 정직하게 남기기 (Priority: P1)

운영자는 실주문 SSH 명령이 실패했는데도 마지막 로그 출력 명령 때문에 GitHub 단계가 성공으로
표시되는 일을 원하지 않는다. 주문 뒤에는 KIS 체결을 즉시 동기화하고 열린 주문·최근 체결·사후
잔고 측정 결과를 같은 실행 보고서에서 확인할 수 있어야 한다.

**Independent Test**: 실주문, 체결 동기화, 사후 측정 명령의 비정상 종료를 각각 주입하면 해당
단계가 실패하고, 항상 실행되는 sidecar 발행 단계가 각 결과와 가용한 로그를 보존하는지 확인한다.

## Edge Cases

- 미국 정규장이 닫혀 있으면 실주문을 제출하지 않는다.
- 기준 신호 종목과 체결 종목의 매핑은 정확히 1:1이어야 하며 빈 값·누락·중복을 거부한다.
- 목표 금액을 한 주 가격으로 나눈 값이 정확히 0.5 미만이면 0주를 유지한다.
- 가장 가까운 정수 주가 목표 오차를 줄여도 종목·주문·전체 노출 캡을 넘으면 기존 게이트가 줄이거나 거부한다.
- 매수가능현금이 부족하면 매도 대상이 없는 한 매수를 보류하며 비관리 보유를 자동 청산하지 않는다.
- 추세 신호가 0이면 해당 체결 ETF를 주문하지 않는다.

## Requirements

- **FR-001**: 신호 계산은 계속 `global-trend-fixed`, 균등가중, `SPY/IEF/GLD`, 추세창
  `[63,126,189,252]`를 사용해야 한다.
- **FR-002**: 체결 매핑은 `SPY→SPYM`, `IEF→IEF`, `GLD→GLDM`의 명시적 1:1 집합이어야 한다.
- **FR-003**: 대체 ETF는 각각 미국 대형주, 7~10년 미국 국채, 금 가격 노출을 나타내야 한다.
- **FR-004**: 체결 매핑은 신호 전략 지문과 자본 사다리 검증 지문에 포함되지 않아야 한다.
- **FR-005**: 라이브 미리보기와 실주문은 KIS 실제 보유와 매수가능현금을 사용해야 한다.
- **FR-006**: 내부 `current_positions`는 라이브 미리보기나 실주문의 보유 원본이 아니어야 한다.
- **FR-007**: 비관리 실계좌 보유는 명시적 청산 목록에 없으면 매도 주문에서 제외하고 보류 사유를 기록해야 한다.
- **FR-008**: 정수 주 산정은 0주와 1주 이상 중 목표 달러 오차가 더 작은 수량을 선택할 수 있어야 한다.
- **FR-009**: 반올림된 주문도 K1 종목별·주문별·전체 노출 캡, 현금 버퍼, 지정가, 정규장,
  손실 서킷 브레이커를 모두 통과해야 한다.
- **FR-010**: 매핑 누락·중복·화이트리스트 불일치·브로커 증거 실패는 fail-closed여야 한다.
- **FR-011**: 미리보기는 기준 신호 비중, 체결 비중, 매핑, 실제 보유 기준, 필요 현금을 함께 기록해야 한다.
- **FR-012**: 단 1 자본은 293달러를 유지하며 20% 상한이나 상위 단 승격 조건을 바꾸지 않아야 한다.
- **FR-013**: 실주문·체결 동기화·사후 측정 SSH 종료 코드는 각 GitHub 단계 결과에 그대로
  전파돼야 하며, 어느 단계가 실패해도 sidecar 발행은 가용한 로그와 단계별 결과를 남겨야 한다.
- **FR-014**: 실주문 직후 `fills --sync`를 짧은 제한 횟수로 실행해 KIS 체결을 추가-전용
  감사 장부에 반영하고 열린 주문·최근 체결 요약을 기록해야 한다. 이 단계는 주문·취소를 하지 않는다.

## Success Criteria

- **SC-001**: 293달러와 최신 공식 표시 가격 범위에서 현재 양수 신호를 최소 1개 이상 정수 주로 표현한다.
- **SC-002**: 현재 신호에서는 `SPYM` 1주와 `GLDM` 1주가 합계 293달러 및 기존 캡 안에서 계획된다.
- **SC-003**: 과거 내부 모의 보유 5종은 새 라이브 미리보기 결과에서 매도 후보로 0건 나타난다.
- **SC-004**: 전략 지문은 기존 검증 설정과 정확히 일치한다.
- **SC-005**: 전체 테스트, 린트, 엄격 하네스, HANDOFF 사실 검증, PR 품질 관문을 통과한다.
- **SC-006**: 배포 후 KIS 읽기 전용 미리보기가 실제 보유·현금과 1주 이상 주문 계획을 기록한다.
- **SC-007**: 워크플로 회귀 검사가 실주문·체결 동기화·사후 측정의 종료 코드 전파와 실패 시
  sidecar 발행을 고정한다.

## Assumptions

- State Street 공식 자료에서 SPYM은 S&P 500, GLDM은 금 가격을 추종하며 둘 다 NYSE Arca 상장이다.
- 기존 IEF는 그대로 유지하므로 채권 다리의 상품 변경은 없다.
- 최신 KIS 점검의 매수가능현금 934.27달러는 변할 수 있으므로 매 실행 때 다시 조회한다.
- 수익은 보장되지 않으며 이 기능의 성공은 검증된 위험 범위에서 실제 노출과 감사 가능한 체결 경로를 만드는 것이다.

## Safety And Rollback

이 변경은 라이브 주문 종목과 정수 주 산정을 바꾸므로 `this changes the safety perimeter` 커밋
문구를 남긴다. 문제가 생기면 센티넬을 단 0·비무장으로 내린 뒤 이 기능 커밋을 되돌린다.
기존 체결과 감사 로그는 삭제하지 않는다. 자본 20%, 손실 예산, 캡, 정규장, 지정가,
production 승인, 비밀값 분리, `Backtest -> Canary -> Full`은 유지한다.
