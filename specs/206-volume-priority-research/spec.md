# Feature Specification: 동시 신호의 개장 거래량 우선 처리 검증

**Feature Branch**: `codex/206-volume-priority-research`
**Created**: 2026-10-03
**Status**: 사전등록·순서·암호화 전달·재계산 명령 구현; 실제 원격 재생·전체 검증 미완료
**Input**: 기존 한국투자 단타 실사용 프로그램을 완성하고, 실패한 가설을 억지로 승인하지 않으며 다른 검증 가능한 대안을 진행한다.

## User Scenarios & Testing

### User Story 1 — 결과를 보기 전에 새 가설을 고정한다 (Priority: P1)

운영자는 제한된 연구 현금에서 동시에 나온 신호 중 어떤 종목을 먼저 처리할지 검증한다.
기존194는 알파벳순이었다. 새 후보는 같은 시각에 준비된 신호를 개장 상대거래량 내림차순,
동률이면 기존 종목명 오름차순으로 처리한다. 더 높은 거래량이 수익을 보장한다는 주장은 아니다.

**Why this priority**: 최대4보유와 공유 현금 때문에 처리 순서는 실제로 어떤 신호를 선택하는지 바꾼다.
**Independent Test**: 성과 조회 전에 규칙·원본·비용·기존 최소35시도와 새 한 후보의 계약을 커밋한다.
**Acceptance Scenarios**:
1. **Given** 동일 시각의 서로 다른 거래량 신호, **When** 예약 여력이 부족함, **Then** 높은 상대거래량부터 예약하며 선택 순서를 기록한다.
2. **Given** 동률, **When** 재생, **Then** 종목명으로 결정해 반복 실행 결과가 같다.
3. **Given** 다른 시각의 신호, **When** 처리, **Then** 미래 신호를 기다리거나 이미 소비한 시도권을 되살리지 않는다.

### User Story 2 — 기존 현금·누락·체결 제한으로 실제 개발 자료를 재생한다 (Priority: P1)

운영자는194와 동일한 원본·관측 시각·매수 전용·부분 체결·정산 모형에서 처리 순서의 효과를 확인한다.

**Why this priority**: 신호 순서가 좋아 보여도 비용·미체결·현금 부족을 없애면 실사용 근거가 되지 않는다.
**Independent Test**: 우선순위 반례, 불완전 개장/과거 구간, 미래 가격 변경, 부분 청산과 재계산을 자동 검사한다.
**Acceptance Scenarios**:
1. **Given** 누락된 개장 또는 직전14거래일 관측, **When** 신호 계산, **Then** 가격·거래량을 만들거나 날짜를 압축하지 않는다.
2. **Given** 매도대금 미결제 또는 청산 대기, **When** 새 신호, **Then** 기존 예약·노출·신규 매수 제한을 유지한다.
3. **Given** 기존194 실행, **When** 새 코드를 사용, **Then** 원래 알파벳순 결과와 장부를 보존한다.

### User Story 3 — 기기와 원본 공개 없이 원격 검증한다 (Priority: P1)

사용자 맥북은 화면 조작과 무거운 재생 없이 사용할 수 있어야 한다. 실제 재생과 전체 검사는 원격에서 수행한다.

**Why this priority**: 공개 저장소에 큰 원본 가격 묶음을 새로 공개하는 것은 연구 실행에 필요하지 않다.
**Independent Test**: 암호화 자료의 변조·잘못된 키·누락·과도한 크기·중복 출력 거부와 비밀값 비노출을 검사한다.
**Acceptance Scenarios**:
1. **Given** 봉인된 원본, **When** 원격 전달, **Then** 공개 저장소에는 암호문과 가격 없는 지문만 보존한다.
2. **Given** 개발 재생 성공, **When** 판정, **Then** 독립 재계산과 실제 코드·장부 지문을 기록하며 실주문 자격은 발급하지 않는다.

### Edge Cases

상대거래량의0·음수·비정상 값, 동일 시각 동률, 같은 종목 중복, 결제 전 현금,
휴장·반일장·일광 절약 시간, 누락된5분 구간, 가격 초과·거래량 부족·부분 체결,
잔량의 다음 세션 청산, 회사 연결 미확인 DD/UTX, 변조된 암호문과 입력 잠금,
기존 출력, 개발 기간 밖 원본, 연구 키와 증권사 키의 혼입.

## Requirements

### Functional Requirements

- **FR-001**: 194의 봉인 원본30종목·2014-03-01~2020-03-06·14거래일 준비 구간을 그대로 사용한다. 이미 관측한 개발 자료임을 표시한다.
- **FR-002**: 새로운 한 후보는 같은 시각의 준비된 매수 신호만 상대거래량 내림차순/종목명 오름차순으로 처리한다. 미래 시각의 신호·수익·거래량으로 순위를 만들지 않는다.
- **FR-003**: 194의 개장5분 양봉, 직전14거래일 대비 거래량2배, 완결5분 종가 돌파, 첫10분~마지막60분 신호, 하루 한 번 시도권을 유지한다.
- **FR-004**: 연구 초기현금10000달러, 거래·종목2000달러, 취득원가·예약8000달러, 최대4보유, 매도대금2거래일 뒤 사용 가능을 유지한다. 실제 계좌 자금은 변경하지 않는다.
- **FR-005**: 다음1분 양의 거래량에서 지정가 이하 시가·거래량1%·정수 수량·미체결 예약 해제와 기존 손절·장 마감 전 청산·잔량 재시도를 유지한다.
- **FR-006**: 편도 기준31bp/가혹40bp를 현금에 각각 한 번 반영하고 최소200완결거래·양비용 순이익 양수·미청산0을 유지한다. 조건 부족은 탈락이며 양수도 독립 검증 필요 판정에 그친다.
- **FR-007**: 이전 최소35시도와 이번 한 후보를 구분해 최소36시도를 기록한다. 기존 계약·탈락 결과를 수정하거나 재현을 새 후보로 중복 계산하지 않는다.
- **FR-008**: 기존194의 기본 실행과 장부를 바꾸지 않는다. 새 실행은 별도 계약·후보·코드·원본·장부 지문으로 식별한다.
- **FR-009**: 전체 입력 지문·순서·종목·기간을 확인하고 누락 관측을 보존한다. 회사 연결·용량·조정 가격·KIS 실행 동등성을 인증하지 않는다.
- **FR-010**: 새 원본 전달은 인증된 암호문으로 하고, 연구용 비밀 키는 비밀 설정에서만 읽는다. 계좌·증권사 키·이메일을 연구 작업에 주입하거나 로그에 출력하지 않는다.
- **FR-011**: 맥북은 화면 조작·전체 테스트·가격 재생을 수행하지 않는다. 필요한 파일 전달 준비는 낮은 우선순위·속도 제한으로 수행하고 실제 연구와 전체 검사는 원격에서 한다.
- **FR-012**: 기존 파일을 덮어쓰지 않고 결과·부분 실패·실행 지문을 보존한다. 최종 확인495세션·60세션 전진 관찰·실주문 자격을 이 작업의 성공으로 대체하지 않는다.

### Key Entities

봉인 후보, 동시 신호 묶음, 원본·암호문 지문, 연구용 비밀 키, 공유 연구 현금,
예약·부분 체결·정산 장부, 독립 재계산 결과, 원격 실행 증거.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 실제 성과 확인 전에 한 후보의 계약 커밋을 남긴다.
- **SC-002**: 동시 신호·동률·미래 정보·현금 부족·누락·부분 체결 반례에서 잘못된 처리0건이다.
- **SC-003**: 동일 봉인 입력의 원격 재생과 독립 재계산이 장부 지문과 판정을 재현한다.
- **SC-004**: 기존194 알파벳순 결과·검증 계약을 유지한다.
- **SC-005**: 새 공개 원본 가격·노출 비밀값·증권사 호출·실주문·자본 변경·맥북 화면 조작·무거운 로컬 재생0건이다.

## Assumptions

연구 후보는 실사용 전략을 찾기 위한 단계이며 합격을 보장하지 않는다. 논문의 약7천종목,
공매도·차입·ATR 손절·주당 비용·상위20개 전략을 재현한다고 주장하지 않는다.
194와 비용·신호·연구 현금은 같고 동시 신호 순서만 바뀐다. 공개 저장소의 원본 전달에
연구 키 분리가 필요하므로 위험 등급3으로 전체 명세 절차를 적용한다. 헌법·커널·
실주문 관문·계좌·허용 목록·운영 승인·자본·기존 수집 서비스는 변경하지 않는다.
206의 개발 탈락/성공 어느 쪽도 전체181 T013~T016의 완료를 뜻하지 않는다.
