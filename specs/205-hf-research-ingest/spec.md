# Feature Specification: 화면 없는 무료 연구 원본 취득

**Feature Branch**: `codex/205-hf-research-ingest`  
**Created**: 2026-10-02  
**Status**: 관련 검사 통과 / 보관 보완 전체 재검증 대기 / 인증 원본 취득 미완료
**Input**: 기존 무료 계정을 사용하고 맥북 화면을 방해하지 않으며 실제 자료 확보를 계속한다.

## 문제 정의와 안전 경계

현재 HF 원본은 화면을 통한 다운로드로 확보했으나 사용자는 맥북 화면 간섭을 금지했다.
공식 API는 무료 키를 사용하며 종목 전체 기간의 Parquet를 반환한다.
수집 성공은 전략 통과·실거래 자격이 아니다. 이번 위험 등급은 3이다. 새로운 외부 API와
비밀값 입력에 헌법 V(비밀값 분리), VII(장애 대응)를 적용하며 커널·돈 경로는 변경하지 않는다.
기존 자료와 감사 기록은 보존한다. 원격 수집 실행을 중단하면 되돌릴 수 있다.

## User Scenarios & Testing

### User Story 1 - 공개 자료 목록 확인 (Priority: P1)

운영자는 화면 없이 공식 목록을 취득하고 원본 지문·취득 시각을 확인한다.
**Why this priority**: 계정 키가 없어도 접근 여부를 독립적으로 확인할 수 있다.
**Independent Test**: 키 없는 모의 수집이 목록만 확정하고 `MISSING_KEY`를 보고한다.
**Acceptance Scenarios**:
1. 정상 목록은 원본 그대로 보존하며 개수·고유 종목·파일 크기·시각을 검증한다.
2. 잘못된 목록 또는 리디렉션은 완료 원본으로 확정하지 않는다.

### User Story 2 - 고정 두 종목 원본 취득 (Priority: P2)

운영자는 기존 무료 계정 키를 비밀 저장소에 넣고 AMZN/NVDA 원본을 원격 취득한다.
**Why this priority**: 실제 계정 접근과 파일 형식을 작은 범위에서 확인한다.
**Independent Test**: 모의 Parquet의 원본 지문과 행 수를 재현하고 부분 성공을 구별한다.
**Acceptance Scenarios**:
1. `version=raw` 원본의 전송 길이·구조·지문을 확인한 뒤 완료 기록을 마지막에 쓴다.
2. 403이면 남은 종목을 요청하지 않으며 오류본문·키를 출력·보존하지 않는다.
3. 한 종목만 성공했으면 전체 원본 취득 성공으로 표시하지 않는다.

### User Story 3 - 재실행에도 장애 차단 유지 (Priority: P1)

운영자는 수동 실행을 반복해도 요청 제한과 이전 실패를 유지한다.
**Why this priority**: 임시 실행기의 새 프로세스가 차단을 초기화하면 공급자 장애를 악화시킨다.
**Independent Test**: 이전 raw 실패 두 건과 새 실패 한 건이 공개 목록 성공과 무관하게 차단된다.
**Acceptance Scenarios**:
1. 최근 실패·취소 실행의 상태 산출물을 복원하며 처음 실행은 조회 성공과 빈 이력으로만 확인한다.
2. 이전 상태가 없거나 손상됐으면 이전 실행의 종료 시각부터 최소 15분 동안 요청하지 않는다.
   이후에도 실패 3회 상태의 반개방 검사로 시작한다. 조회 실패·미완료 실행·같은 실행 재시도는 거부한다.
3. 429의 숫자/날짜형 `Retry-After`가 실행 예산보다 길면 조기 재요청 없이 다음 실행까지 차단한다.

### Edge Cases

- 첫 요청에도 1초 대기. 각 요청의 실제 경과시간 20초, 전체 수집 180초, 최대 3회 시도.
- 느린 스트리밍, 길이 불일치, 128MiB 초과, 4MiB 초과 목록, 키 반사 응답, 심볼릭 링크,
  기존 출력 디렉터리, 취소, 완료 기록 쓰기 실패, 만료된 상태 산출물을 검증한다.
- 공식 원본의 2022년 3월 PiTrading/IEX 원천 전환과 거래 정정 한계를 기록한다.

### User Story 4 - 원본의 장기 보관 (Priority: P2)

운영자는 원격 산출물을 보존 기간과 무관한 새 연구 폴더로 보관한다.
**Independent Test**: 두 파일의 바이트를 그대로 복사·재검증하며 저장 실패는 완료로 보고하지 않는다.
**Acceptance Scenarios**:
1. 취득 결과 `COMPLETE`와 코드 지문이 있는 자료만 허용한다. 파일 지문을 재검증한다.
2. 새 폴더만 사용하며 기존 원본이나 보관본을 덮어쓰지 않는다. 부분 자료와 변조는 거부한다.
3. 파일과 디렉터리 저장을 동기화한 뒤 보관 영수증을 마지막에 쓴다. 실패 시 새 보관본을 정리한다.
4. 보관은 네트워크·키·가격 평가 없이 실행한다. 파일 무결성은 실제 취득·출처·전략 자격을 증명하지 않는다.

## Requirements

### Functional Requirements

- **FR-001**: 주소는 공식 `/v1/symbols`와 AMZN/NVDA `/v1/bars/*?version=raw`로 고정한다.
  외부 URL·종목·기간·정리본·서명 URL을 입력으로 받지 않는다.
- **FR-002**: 키는 자료 요청 단계의 `HF_DATA_API_KEY` 환경변수로만 받는다.
  SEC 연락처·KIS 키·계좌·SSH 환경을 사용하지 않는다. 키 부재는 인증 요청 0건이다.
- **FR-003**: TLS 검증, 프록시 환경 미사용, 리디렉션 금지, 직렬 요청, 최소 1초 간격,
  유한 재시도, 3회 실패 후 900초 차단을 적용한다. 원본과 목록의 실패 누적은 분리한다.
- **FR-004**: HTTP 상세 헤더·오류본문·예외 문자열을 기록하지 않는다. 허용 실패 코드만 남긴다.
  반사된 키를 저장 전에 청크 경계까지 검사하고 실패 임시 파일을 산출물에서 제거한다.
- **FR-005**: 원본 크기 상한은 종목당 128MiB, 목록 4MiB다. 새 출력 디렉터리만 사용한다.
  길이·형식·원본 SHA-256·행 수·열 구조를 확인하고 마지막 완료 기록을 확정한다.
- **FR-006**: 전용 수동 원격 작업은 직렬화한다. 이전 모든 결론의 실행 이력과 상태를 읽는다.
  상태 유실은 명시적 보수 차단으로 처리하며 최초 실행으로 숨기지 않는다.
- **FR-007**: 자료의 가격·수익률·최종 성과는 평가하지 않는다. 과거 종목 포함 시점,
  원천 동일성, 거래 가능성, 전략 자격은 모두 미확인/false로 남긴다.
- **FR-008**: 의미 있는 모의 반례 검사와 원격 전체 테스트·린트를 수행한다.
  실제 취득은 파일·목록별로 구별하며 키 부재/403을 취득 성공이라고 말하지 않는다.
- **FR-009**: 오프라인 보관 CLI는 검증된 전체 자료만 새 폴더에 복사한다. 원본 지문과
  보관 시각·입력/보관 manifest 지문을 영수증에 남기며 비밀값을 읽거나 출력하지 않는다.
  저장 실패에는 성공 영수증을 남기지 않고 기존 원본/보관본을 보존한다.

### Key Entities

- SourceReceipt: 고정 출처, 취득 시각, 원본 파일명·크기·지문·행 수, 연구 경계.
- CircuitState: 고정 범위, 목록/원본별 실패 수·차단 시각, 완료 상태.
- HistoryProof: GitHub의 이전 실행 여부·종료 상태·종료 시각·현재 재시도 번호.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 키 없는 실행은 화면 간섭과 인증 자료 요청 없이 공개 접근 결과를 재현한다.
- **SC-002**: 정상 두 파일은 원본 지문이 같고 오류/부분/취소 파일은 전체 성공으로 오인되지 않는다.
- **SC-003**: 실행을 바꿔도 3회 실패·429·이력 유실 뒤의 대기시간이 단축되지 않는다.
- **SC-004**: 전체 회귀와 비밀 노출 반례를 통과하며 KIS 주문 요청과 자금 배정은 0건이다.

## Assumptions

- 기존 무료 계정은 등록됐으나 현재 GitHub 비밀 목록에는 HF API 키가 없다.
- 공식 키는 30일 만료하며 자동 갱신 API가 문서화되지 않았다. 인증 실패는 중단하고 수동 갱신한다.
- AMZN/NVDA는 접근·형식 시험용이다. 과거 전략 종목 구성이나 투자 추천이 아니다.
- 181 T013–T016과 200 T017은 이번 자료 수집 기능의 완료로 닫지 않는다.
