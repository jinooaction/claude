# Feature Specification: 소스·설치 입력의 합성 검증
**Feature Branch**: `codex/219-source-input-lab`
**Created**: 2026-10-17
**Status**: 구현 중
**Input**: “전체 완성할때까지 멈추지마” — 218 계약의 비실행 입력 검사부터 구현한다.

## User Scenarios & Testing
### US1 — 변경된 입력 거절 (P1)
운영자는 검토한 정확 commit/tree와 원래 파일을 바꾼 입력이 거절되는 것을 확인한다.
독립 시험: 새 단일 초기 커밋의 정상 입력은 합성 일치, 동일 tree의 다른 commit·숨긴 변경·추가 이력은 거절.
### US2 — 설치 입력 연결 (P2)
동일 lock 또는 버전 표기만으로 바뀐 설치 입력을 받아들이지 않는다.
독립 시험: 원래 toy 입력·전이 관계·플랫폼·도구 선언 변경은 거절. 실제 설치는 0회.
### US3 — 증거의 한도 (P1)
합성 성공을 실제 후보/이미지/권한 검증으로 오해하지 않는다.
독립 시험: 모든 결과에서 인증·실거래·이미지 연결·지속 불변은 false. 실패·정리 실패에는 성공 보고서 없음.

## Requirements
- FR-001: 새 생성한 고정 toy fixture만 사용한다. 임의 저장소·이미지·실행파일·URL 입력을 받지 않는다. 실제 소스·역사·비밀·가격 입력을 반입하지 않는다.
- FR-002: 독립 controller가 만든 기대값과 검사 대상의 전체 파일·모드·원래 .git 바이트를 대조한다. 이 선언은 인증되지 않았음을 기록한다.
- FR-003: 안전한 입력의 .git을 먼저 확인한 뒤 원래 Git으로 정확 detached HEAD/tree, 단일 이력, 원래 blob/모드를 확인한다. 인덱스만 믿지 않는다.
- FR-004: 외부 .git, 링크, 추가/누락, 객체·설정·인덱스·refs 변경, 필터·remote·hooks·shallow·alternates 등의 혼입을 Git 호출 전에 거절한다. 검사 대상은 수정하지 않는다.
- FR-005: 빈 명시 환경과 고정 /usr/bin/git을 사용한다. 외부 설정·프로토콜·보조 실행을 막고 timeout/output/파일수/바이트 한도를 강제한다.
- FR-006: toy 설치 파일·lock·전이/도구/플랫폼 선언을 각각 비교한다. 설치 결과·이미지·native 신뢰를 검사했다고 주장하지 않는다.
- FR-007: GitHub Linux 비밀 없는 실행만 허용한다. 로컬에서는 순수 작은 단위 시험만 실행한다. 명령20초·출력64KiB·전체12분·보고32KiB 한도.
- FR-008: 원래 출력의 지문과 고정 결과 코드를 남기며 경로/환경/원문 오류를 공개하지 않는다. 정리가 끝난 뒤에만 새 보고서를 생성한다.
- FR-009: 기존 216 create→created inspect→start, 등록/HMAC/60세션/90초, 실제 실행/수집/예산/주문 경로 변경0.

## Success Criteria
- SC-001: 정상 양성과 구체적인 변조 반례가 원격 실제 Git에서 모두 기대 결과를 낸다.
- SC-002: 관련 시험과 정확 HEAD 전체 회귀·린트·하네스·인계 검사 통과를 원래 artifact로 보존한다.
- SC-003: 218 C01~10/C16의 입력 단계 근거와 C11~15의 미평가 한도를 구분한다.

## Scope and risk
등급3으로 보수적으로 검토한다. 새 입력 검증 실험이며 생산 안전 경계/커널 변경 없음.
218 전체 구현 완료가 아니다. 이미지 내부 Git/native/원래 ROOT·실제 설치 결과·바꿔치기 격리는 후속이며 true로 만들지 않는다.
기존 기능 제거0. 되돌림은 새 lab/workflow/tests/spec/포인터만 되돌리는 PR이다.
