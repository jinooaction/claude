# 스펙 035 — forward 엣지 자동 판정 (돈 버는지 판정하는 폐회로)

## 문제 (왜 이게 세계 최고 수준의 다음 병목인가)

이 시스템은 알파 도구(팩터·최적화기·재조정)와 검증 도구(워크포워드·디플레이티드 샤프·
거래비용·체결품질)를 세계 최고 수준급으로 갖췄다. 그런데 **"실제로 돈을 버는가"를 판정하는
폐회로가 끊겨 있다.** 구체적으로:

1. **NAV 시계열이 기록되지 않는다.** 스펙 029 의 `compute_nav`(시가평가 순자산)와
   `read_nav_points`/`compute_growth`(순자산 시계열 → 성장 지표)는 **만들어졌고 테스트도
   됐지만, 어떤 CLI 에도·어떤 실행 경로에도 배선돼 있지 않았다.** 즉 시간에 따른 순자산이
   아무 데서도 기록되지 않아, "시간상 미래에 돈을 벌었는가"를 잴 입력 자체가 없었다.
2. **디플레이티드 샤프가 forward 트랙에 적용되지 않는다.** 스펙 027 의 디플레이티드/확률적
   샤프(다중검정·과적합 보정)는 백테스트(`portfolio-walk-forward`)에만 연결돼 있고, 현재
   데이터 forward 페이퍼 트랙(`rebalance-paper-forward.yml`)에는 적용되지 않았다.
3. **forward 트랙은 체결만 쌓고 판정을 안 한다.** 트랙은 살아서 `fills_count` 만 늘리지,
   "이게 단순 보유를 이기는, 우연이 아닌 엣지인가"를 자동으로 답하지 않는다. 판정은 산문
   TODO("관측이 충분히 쌓이면 디플레이티드 샤프로 판정하라")로 남아 있었다.

이건 이 프로젝트의 반복 실패 패턴(도구는 만들고 실제 경로엔 안 꽂힘)의 가장 비싼 사례다.
**돈을 버는지 자체를 판정할 수 없으면 세계 최고 수준은 불가능하다.** 그리고 검증 데이터가
컨테이너에 없는 상황에서 새 알파를 또 만드는 건 함정이다 — 검증 못 한 기계만 늘린다. 가장
레버가 큰 일은 이 폐회로를 잇는 것이다.

## 목표

쌓인 시가평가 NAV 시계열을 받아 위험조정 성과를 **단순 보유(buy-and-hold) 벤치마크와
비교**하고, **디플레이티드/확률적 샤프(스펙 027)로 우연·과적합을 처벌**한 뒤
`EDGE_CONFIRMED / NO_EDGE / INSUFFICIENT_DATA` 한 줄 판정을 자동으로 내는 폐회로를 완성한다.
스펙 011(성과)·027(유의성)·029(NAV)를 하나로 연결한다.

## 기능 요구 (FR)

- **FR-V01** 생산자: `nav-snapshot` CLI 가 장부 보유(fills 재구성)를 현재 KIS 시세로 시가평가해
  순자산을 내고, `--snapshot` 이면 `PORTFOLIO_NAV_SNAPSHOT`(스펙 029, K4 추가-전용)으로 1건
  append 한다. 시세 실패는 평균단가로 폴백(거래 무중단). 기본은 순수 계산(미기록), read-only.
- **FR-V02** 소비자: `forward-verdict` CLI 가 모드별 NAV 시계열(`read_nav_points`)을 읽어 기간별
  수익률 → 연율 샤프·PSR·DSR·MinTRL(스펙 027 재사용)을 계산한다.
- **FR-V03** 벤치마크: 포트폴리오 `[portfolio].universe` 의 균등가중 단순 보유 곡선을 **같은
  NAV 일자 격자**에서 `price_bars` 로 구성해(스펙 032 잣대) 전략과 위험조정으로 비교한다.
- **FR-V04** 판정 규칙: 전부 만족해야 `EDGE_CONFIRMED` — ① 관측 ≥ `min_obs`, ② 초과수익>0 이고
  전략 샤프>벤치 샤프(단순 보유를 이김), ③ PSR(벤치 기준) ≥ 임계치(우연 아님), ④ 시도>1 이면
  DSR ≥ 임계치(과적합 아님). 하나라도 미달이면 `NO_EDGE`. 관측 부족·분산 0 이면 보수적으로
  `INSUFFICIENT_DATA`.
- **FR-V05** 배선: `rebalance-paper-forward.yml` 에 `nav-snapshot --snapshot`(생산자) 단계와
  `forward-verdict`(소비자) 단계를 추가하고, 사이드카 `LAST_RUN.md` 에 판정·NAV 섹션을 찍는다.

## 안전 경계 (비협상)

- **Kernel 터치 0건.** 신규 모듈 `portfolio/edge_verdict.py` + CLI 2개 + 워크플로 YAML + 테스트.
  `compute_nav`·`read_nav_points`·`significance`·`price_bars` 리더·`_fetch_marks` 를 **재사용만**
  한다. `risk/gates.py`·캡·whitelist·워커·감사 스키마 무변경.
- **돈 0 이동.** NAV 스냅샷은 읽기 전용 측정(주문 0건). 판정은 순수 분석. 워크플로는 PAPER 전용.
- **라이브 자동 승격 0건.** `EDGE_CONFIRMED` 는 운영자 라이브 게이트(헌법 X.4 / 스펙 026)에 올릴
  *증거*일 뿐, 자동 배포가 아니다. 자율 튜너는 이 판정으로 라이브를 못 켠다(헌법 IX.B-2 불변).
- **보수적 fail-safe.** 모르면(데이터 부족·분산 0·통계 불가) 절대 EDGE 를 선언하지 않는다 —
  "모르면 엣지 없음" = 돈을 잃지 않게 막는 헌법 X 의 직접 구현.

## 합격 기준 (SC)

- **SC-V01** 생산자 `nav-snapshot --snapshot` 이 `PORTFOLIO_NAV_SNAPSHOT` 1건을 정확히 쓴다(통합).
- **SC-V02** 관측 < min_obs 면 `INSUFFICIENT_DATA`(보수적, 통합·단위).
- **SC-V03** 전략이 위험조정으로 벤치마크를 이기고 PSR 합격이면 `EDGE_CONFIRMED`(통합·단위).
- **SC-V04** 전략이 벤치마크에 지거나 우연과 구별 안 되면 `NO_EDGE`(단위).
- **SC-V05** 시도 횟수·시도 샤프 분산이 크면 DSR 이 깎여 EDGE 가 막힌다(과적합 처벌, 단위).
- **SC-V06** 같은 입력 → 같은 판정(결정론, 단위). 전체 테스트·린트 통과.

## 한계 (정직)

- NAV 기반 수익률은 트랙의 자본 투입이 거의 고정(캐너리가 고정 목표자본으로 재조정)임을 가정한다.
  큰 자본 투입/인출이 섞이면 시간가중수익(time-weighted return)으로의 정밀화가 필요하다 — 후속.
- 이 컨테이너는 현재 데이터가 없어 판정은 **라이브 인스턴스 forward 트랙**에서만 진짜 값이 난다.
  여기서는 합성 NAV/가격으로 판정 로직을 검증한다. 트랙이 쌓이면 코드 수정 없이 자동 전환된다.
