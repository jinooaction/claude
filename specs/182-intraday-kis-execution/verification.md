# 실행·복구 검증 기록

## 현재 결과

600a161 실행 코드에서 `uv run pytest` 전체3500 passed/8 skipped(799.45초), 실패0이다.
8개 제외는 실제 KIS 읽기 시험7개와 이미 가동된 사다리의 가동 전 전용 조건1개다.
앞선 부분 회귀 결과를 최종 증거로 사용하지 않았다. 관련67개와 전체 ruff도 통과했다.
실제 단타 주문은 실행하지 않았다. 병합·배포 증거는 HANDOFF에 추가한다.

## 구현자 관점

신호 계산은 177의 사전등록 함수를 공유한다. 181의 서버 수집/진단 모의 운용은 유지한다.
실행은 별도 IntradayExecutor가 실제 체결에 귀속된 보유량을 읽고 기존 주문 라우터를 호출한다.
외부 관측 함수와 실거래 권한 제공자가 없는 기본 구성은 증권사 조회부터 거절한다.
배포만으로 새 단타 주문이 시작되는 서비스나 명령은 없다.

## 검토자 관점

- 동일 봉·종목·방향의 영속 선점은 프로세스 재시작 뒤에도 재사용하지 않는다.
- 선점 직후 중단, 제출 응답 유실, 취소 업무 거절과 응답 유실을 시험했다.
- 부분2주@99 뒤 누적3주 평균99.30이면 총체결금액297.90으로 일치한다.
- 취소 접수 뒤 추가 체결을 반영한 다음 확정 보유량만 매도한다.
- 취소 전 계좌/배포 잠금을 얻지 못한 경우와 쓰기 이후 불명확한 경우를 구별한다.
- 매수·매도 모두5분 미체결 시 취소 확인을 기다린다. 종료 청산 재시도는 원래 가격으로
  최대3개 주문까지이며, 확정 취소 없이 잔량 주문을 만들지 않는다.
- 공식 체결 조회 페이지의 원문 커서를 유지하고 반복·누락·오류를 거절한다.
- 원주문과 취소 요청이 다른 행이어도 처리완료·종목/방향·남은 수량을 함께 확인한다.
- 취소 접수를 최종 종료로 보던 기존 워커 동작을 제거한 만큼 공통 조회 경로도 보완했다.

## 안전 담당자 관점

주문/종목20%·전체80%와 기존 허용목록·중단·유지보수·위험 관문을 유지한다.
단타 별도 자본은 기본0이며 기존 저빈도 자본 승인을 가져오지 않는다.
각 주문과 취소 전송 직전에 권한·장 상태·계좌 관측 신선도를 확인한다.
추가 전용 감사 및 선점 테이블의 수정/삭제 거부를 시험했다. 원본 루트 작업 트리는 보존했다.
오프라인 CLI는 고정 MockTransport와 임시 장부만 사용하고 실제 환경 키를 읽지 않는다.
새 단타 기록은 시간대가 불명확한 주문접수 시각으로 추정 복구하지 않는다.

공급자/실행 동등성, 단타 전략·자본 승인, 별도 반복 실주문 권한 경계와 생산 관측 진입점,
실제 소액 주문·체결·청산·대사 증거가 필요하다. 현재 시험으로 대체할 수 없다.
KIS 단독으로 약1개월보다 오래된 분봉을 확보할 수 있다는 근거는 없었다.
