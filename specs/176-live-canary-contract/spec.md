# 기능 명세: 증거 수렴형 실거래 검증 캐너리

**기능 브랜치**: `Codex/176-live-canary-contract`  
**작성일**: 2026-08-31  
**상태**: 확정  
**위험 등급**: 4 - 실제 자본 배분과 라이브 주문 경로 변경  
**입력**: "모든 기능·전략·데이터·배포·주문 경로 오류를 해결하고, 자동매매가 실제로 정상 매매를 수행할 때까지 완수한다."

## 문제 정의

현재 상태는 단순히 "합격 전략이 없다"가 아니다.

- 정확 배포 전략 `globalfixed-ensemble-3-6-9-12`는 개발 431개월과 홀드아웃 235개월을
  분리한 장기 검사에서 연 50bp 비용 후 연복리 8.68%, 샤프 1.83, 최대 낙폭 5.58%로
  기준 포트폴리오보다 위험 조정 성과가 좋았다.
- 이 전략은 2026-08-16에 20% 탐색 캐너리로 무장됐으나, 당시 42~47개 전진 표본의
  페이퍼 장부가 의도치 않은 차입을 포함한 사실이 발견되어 표본이 폐기됐다. 현재 깨끗한
  전진 장부는 4개 관측부터 다시 쌓이고 있다.
- 장기 홀드아웃의 벤치마크 초과수익 PSR은 약 0.612이고 연 100bp 비용에서는 초과수익이
  음수이므로, 이 전략을 확정 알파 또는 20% 이상 승격 후보로 소급 인정할 수 없다.
- 반면 실제 계좌 주문 배관은 KIS 읽기 6/6, 현재 NAV·현금 조회, 정확한 체결 대리 ETF,
  정수 주 미리보기, 지정가·정규장·서명·nonce·정합성 경로를 갖추고 있다. 전략의 알파
  승격 자격과 소액 실거래 운영 검증 자격을 하나로 묶어 자본을 항상 0으로 만드는 것은
  단계적 출시의 목적과 맞지 않는다.
- 전략 연구 진단과 자본 진입 증거가 같은 최신 sidecar 파일을 덮어쓴다. 진단 전용 PEAD
  결과가 최신이면 자본 판정기가 그 파일만 읽어 다른 증거의 역할과 신선도를 잃는다.

따라서 `10% 운영 검증 캐너리`와 `20% 이상 알파 승격`을 분리한다. 10%는 장기 시간 분리
검증과 정확한 주문 구현성을 갖춘 기존 전략으로 실제 주문·체결·감사 경로를 검증하는 단계다.
20% 이상은 깨끗한 전진 표본, 확률 신뢰도, 칼마 우위, 전체 경로 교정을 계속 요구한다.

## 목표와 비목표

### 목표

- 전략의 운영 가능성과 시장 초과수익 확정 여부를 서로 다른 상태로 판정한다.
- 진단 전용 연구 결과가 자본 진입 증거를 덮어쓰지 못하도록 역할과 저장 경로를 분리한다.
- 정확한 `globalfixed` 전략이 현재 계좌 NAV의 10%까지만 실거래 검증 캐너리에 진입하게 한다.
- 첫 실제 주문 전에 최신 장기 증거, 강화 검사, 전략 지문, 체결 대리 등가성, 정수 주 구현성,
  계좌 정합성, 킬스위치와 손실 차단을 다시 확인한다.
- 실제 KIS 주문 요청, 체결 동기화, 추가 전용 감사 기록, 사후 계좌 정합을 하나의 실행 증거로 남긴다.
- GitHub 예약 한 건의 지연·누락에 의존하지 않고, 같은 뉴욕 거래일의 중복 주문은 서버에서
  원자적으로 막으면서 정규장 안에 여러 번의 자동 실행 기회를 둔다.
- 20% 이상 승격 기준과 하향 위험 방어를 그대로 유지한다.

### 비목표

- `globalfixed`를 확정 알파, 벤치마크 초과 전략 또는 수익 보장 전략으로 표시하지 않는다.
- 깨끗한 전진 관측 40개, PSR 0.80, 칼마 우위, 전체 경로 교정 없이 20%로 올리지 않는다.
- PEAD를 종목별 시점 기준 구성 종목과 실행 설정 없이 실거래 전략으로 바꾸지 않는다.
- 외부 보유 `ORANY`를 자동 매도하지 않는다.
- 손실 예산 20%, K1 포지션 한도, K2 허용 종목, 지정가, 정규장, 비밀값 분리,
  추가 전용 감사 로그, 배포 장중 금지를 낮추거나 우회하지 않는다.
- 시장이 닫혔거나 전략 목표 주문이 0건이면 주문을 억지로 만들지 않는다.

## 사용자 시나리오와 테스트

### 사용자 이야기 1 - 운영 가능성과 알파 승격을 정직하게 분리한다 (우선순위: P1)

운영자는 안전하게 자동 주문을 검증할 수 있는 전략이 있는데도, 시장 초과수익 확정 기준을
아직 못 넘었다는 이유만으로 주문 배관이 영원히 검증되지 않는 상태를 원하지 않는다.

**독립 테스트**: 장기 시간 분리 검증은 통과하지만 깨끗한 전진 관측이 4개인 정확 배포 전략을
입력하면 10% 운영 검증은 준비되고 20% 알파 승격은 차단되는지 확인한다.

**인수 시나리오**:

1. **Given** 정확한 장기 홀드아웃·강화 검사·실행 등가성·정수 주 구현성이 모두 통과한 단 0 전략,
   **When** 자본 사다리가 판정하면, **Then** 실계좌 NAV의 10%까지만 무장한다.
2. **Given** 같은 전략의 깨끗한 전진 관측이 40개 미만이거나 PSR 0.80 미만,
   **When** 20% 진입을 판정하면, **Then** 10%를 넘기지 않는다.
3. **Given** 운영 검증 자격만 있는 전략, **When** 보고서를 생성하면, **Then** 이를 확정 알파나
   벤치마크 초과 확정으로 표시하지 않는다.

---

### 사용자 이야기 2 - 연구 진단과 자본 증거를 서로 덮어쓰지 않는다 (우선순위: P1)

운영자는 최신 연구가 진단 전용이라는 이유만으로 이전 전략의 별도 운영 증거가 사라지거나,
반대로 오래된 합격 파일이 최신 연구 실패를 숨기는 것을 원하지 않는다.

**독립 테스트**: PEAD 진단 결과와 자본 진입 증거를 같은 실행에서 발행하고, 각 소비자가
자기 역할의 파일만 읽으며 두 파일의 코드 커밋과 생성 시각을 독립 검증하는지 확인한다.

**인수 시나리오**:

1. **Given** 진단 전용 PEAD 결과가 최신, **When** 자본 판정기가 실행되면, **Then** PEAD 파일을
   10% 자본 증거로 오인하지 않고 운영 검증 증거를 별도로 읽는다.
2. **Given** 운영 검증 증거가 누락·오래됨·다른 커밋, **When** 자본 판정기가 실행되면,
   **Then** PEAD 또는 오래된 파일로 대체하지 않고 단 0을 유지한다.
3. **Given** 두 역할의 증거, **When** 운영 보고서를 만들면, **Then** 역사적 유망성·운영 검증
   자격·알파 승격 자격을 각각 표시한다.

---

### 사용자 이야기 3 - 실제 10% 캐너리 주문과 감사를 끝까지 닫는다 (우선순위: P1)

운영자는 코드와 미리보기만 통과한 상태가 아니라, 정규장에서 실제 주문이 접수되고 체결 또는
미체결 상태가 동기화되며 사후 계좌 정합과 감사 기록까지 재현되는 상태를 원한다.

**독립 테스트**: 현재 NAV의 10% 센티넬을 무장한 뒤 정규장 예약 실행에서 서명된 지정가 주문,
체결 동기화, 전략 범위 성과 측정, 계좌 정합, sidecar 감사가 순서대로 완료되는지 확인한다.

**인수 시나리오**:

1. **Given** 무장된 10% 캐너리와 열린 미국 정규장, **When** 예약 실행이 시작되면,
   **Then** 최신 증거를 다시 검사한 뒤에만 실제 주문을 요청한다.
2. **Given** 주문이 접수 또는 체결, **When** 실행이 끝나면, **Then** 주문·체결·잔고·정합 결과를
   추가 전용 감사 장부와 최신 실행 sidecar에 남긴다.
3. **Given** 휴장, 0개 목표 주문, 시세 실패, 계좌 불일치, halt, 서명 실패 중 하나,
   **When** 실행하면, **Then** 실제 주문을 만들지 않고 정확한 차단 이유를 남긴다.
4. **Given** 첫 매수 뒤 위험 축소 매도 필요, **When** 연구 증거가 오래됐더라도,
   **Then** 기존 손실·정합·허용 종목 게이트 아래 위험 축소 매도는 막지 않는다.
5. **Given** GitHub 예약 실행이 매시 정각 혼잡으로 반복 지연된 이력, **When** 실거래 예약을
   구성하면, **Then** 정각을 피한 뉴욕 현지 장중 시각을 사용하고 운영 보고서도 같은 다음
   실행 시각을 표시한다.
6. **Given** 예약 실행이 장 마감 뒤까지 지연되거나 휴장일에 도착, **When** 실주문 CLI가
   시작되면, **Then** 데이터베이스 변경과 브로커 접근 전에 XNYS 정규장 검사를 다시 수행하고
   다음 개장 시각을 포함한 차단 이유를 남긴다.
7. **Given** 실주문 CLI가 정규장 안에 시작했지만 시세·계좌 조회나 앞선 주문 처리 중 장이 마감,
   **When** 다음 주문을 중개사에 제출하려 하면, **Then** 실행 권한 잠금을 얻은 뒤 실제 중개사
   쓰기 직전에 다시 XNYS 정규장을 검사하고 거부 사실을 감사 장부와 종료 코드 75로 전파한다.
8. **Given** GitHub가 한 예약을 지연하거나 누락할 수 있는 운영 이력, **When** 같은 뉴욕 거래일의
   후속 예약이 도착하면, **Then** 아직 실행되지 않은 날에는 한 번만 주문 경로를 열고 이미 선점된
   날에는 브로커 호출·sidecar 덮어쓰기 없이 원래 실행 증거를 보존한다.

### 사용자 이야기 4 - 실패 시 즉시 축소하고 20% 이상은 다시 번다 (우선순위: P2)

운영자는 운영 검증 캐너리가 손실 한도를 넓히거나 이후 승격을 자동 정당화하지 않기를 원한다.

**독립 테스트**: 10%에서 손실·정합 실패·킬스위치와 승격 입력을 각각 주입해 즉시 0% 강등과
20% 승격 차단을 확인한다.

**인수 시나리오**:

1. **Given** 10% 캐너리의 낙폭이 예산 절반 이상, **When** 사다리가 판정하면,
   **Then** 즉시 단 0으로 강등한다.
2. **Given** 10% 캐너리의 라이브 관측이 충분하지만 깨끗한 전진 알파 증거가 부족,
   **When** 승격을 판정하면, **Then** 10%를 유지하고 20% 이상으로 올리지 않는다.
3. **Given** 킬스위치 또는 미해결 계좌 불일치, **When** 주문 실행이 시작되면,
   **Then** 신규 주문을 제출하지 않는다.

### 경계 사례

- 현재 NAV 10%가 정수 주 최소 금액보다 작아 구현성 기준을 못 채우면 단 0을 유지한다.
- 주문 목표가 0이면 체결을 만들기 위해 신호나 지정가를 변경하지 않는다.
- 부분 체결은 체결된 수량만 장부에 추가하고 나머지는 미체결로 보존한다.
- sidecar 생성 시각은 신선하지만 코드 커밋이 현재 `main` 계보가 아니면 차단한다.
- 진단 전용 연구가 `PUBLISHED_EDGE`여도 선택 배포 설정이 없으면 자본 자격은 항상 거짓이다.
- 10% 센티넬이 무장됐지만 서버 배포 코드가 서명 커밋과 다르면 주문을 거부한다.
- 외부 보유는 계좌 정합 기준선에는 포함하지만 전략 주문과 손익에서는 제외한다.
- 예약 이벤트가 정상 장중 시각으로 구성됐어도 실제 시작 시각이 정규장 밖이면 실주문 CLI가
  실패 폐쇄한다. 종이매매와 주문 없는 미리보기는 장외에도 계속 허용한다.
- 같은 날 여러 예약이 한꺼번에 지연 도착해도 서버의 거래일 선점 장부는 한 실행만 허용한다.
- 선점 뒤 프로세스가 불명확하게 종료되면 같은 날 자동 재주문하지 않고 다음 거래일로 넘긴다.

## 기능 요구사항

- **FR-001**: 시스템은 `운영 검증 자격`, `연구 알파 자격`, `20% 이상 승격 자격`을 서로 다른
  기계 판독 상태로 기록해야 한다.
- **FR-002**: 운영 검증 자격은 기존에 기록된 정확 배포 후보에만 허용하며, 새로 결과를 본 뒤
  고른 후보를 소급 적용해서는 안 된다.
- **FR-003**: 운영 검증 자격은 개발·홀드아웃 무중복, 개발 120개월 이상, 홀드아웃 120개월 이상,
  연 50bp 이상 비용, 양의 홀드아웃 연복리, 홀드아웃 샤프 1.0 이상, 홀드아웃 최대 낙폭 10% 이하,
  기준 대비 샤프 우위와 낙폭 80% 이하를 모두 요구해야 한다.
- **FR-004**: 보고서는 벤치마크 초과수익 PSR과 100bp·150bp 비용 민감도를 차단 여부와 별개로
  공개해야 하며, 약한 초과수익을 확정 알파로 표현해서는 안 된다.
- **FR-005**: 첫 자본은 실계좌 최신 NAV의 정확히 10%를 내림한 금액이어야 하며 10%를 넘길 수 없다.
- **FR-006**: 운영 검증 진입은 정확한 라이브 전략 지문, 최신 강화 검사 PASS, 체결 대리 ETF
  등가성 PASS, 10% 자본 정수 주 구현성 PASS를 모두 요구해야 한다.
- **FR-007**: 정수 주 구현성은 양의 목표 종목 시세 100%, 양의 목표 다리 66% 이상 자금 배치,
  전체 비중 오차 25% 이하, 종목별 오차 15% 이하를 기존 계약과 동일하게 요구해야 한다.
- **FR-008**: 진단 연구 증거와 자본 진입 증거는 별도 파일과 명시적 역할 식별자를 가져야 하며,
  한 파일이 다른 역할의 최신 증거를 덮어쓰거나 대체해서는 안 된다.
- **FR-009**: 모든 자본 진입 증거는 생성 시각, 코드 커밋, 후보 ID, 전략 지문, 입력 지문을 가져야
  하며 누락·오래됨·현재 `main` 비계보이면 실패 폐쇄해야 한다.
- **FR-010**: 첫 실제 주문 직전 운영 검증 증거, 전략 지문, 강화 검사, 실행 등가성, 구현성,
  계좌 정합, halt, 킬스위치, 자본 센티넬을 다시 검사해야 한다.
- **FR-011**: 실제 주문은 기존 production 환경의 짧은 수명 서명과 nonce를 사용하고, 지정가·정규장·
  허용 계좌·허용 종목·K1 한도를 모두 통과해야 한다.
- **FR-012**: 10%에서 20% 진입은 깨끗한 전진 40관측 이상, PSR 0.80 이상, 칼마 우위,
  정확 전략 지문, 강화 검사와 전체 경로 교정을 계속 요구해야 한다.
- **FR-013**: 20% 초과는 기존 `EDGE_CONFIRMED`와 현재 단의 라이브 관측·기간·낙폭 요건을
  계속 요구해야 하며 운영 검증 자격만으로 승격할 수 없다.
- **FR-014**: 손실 예산 절반에서 하향, 손실 예산에서 정지, 미해결 정합 불일치에서 신규 주문 정지,
  `AUTOARM_DISABLED` 킬스위치를 유지해야 한다.
- **FR-015**: 주문 시도 뒤 KIS 체결을 동기화하고 전략 범위 성과와 계좌 정합을 측정해 주문·체결·
  취소·오류를 추가 전용 감사 장부와 공개 정화된 sidecar에 기록해야 한다.
- **FR-016**: 실제 체결 전에는 사용자가 요청한 완료 상태를 선언해서는 안 되며, 휴장 또는 0개
  목표 주문이면 다음 정규장 관찰을 계속해야 한다.
- **FR-017**: 자동 자본 사다리가 `GITHUB_TOKEN`으로 센티넬 PR을 만들고 머지하더라도, 일반
  `pull_request`·`push` 이벤트가 재귀 발화하지 않는 특성을 보완해야 한다. 자동 PR은 머지 전에
  전체 테스트·린트·엄격 하네스·PR 본문 관문을 직접 통과하고, 직접 머지 뒤에는 해당 merge
  commit의 수익 증거를 먼저 갱신한 다음 주문 없는 수동 사전점검을 명시적으로 실행해야 한다.
- **FR-018**: 실거래 예약은 GitHub Actions가 혼잡하다고 명시한 매시 정각을 피하고,
  `America/New_York` 현지 시각으로 미국 정규장 초반에 실행해야 한다. 운영 상태의 다음 실행
  시각도 같은 예약을 UTC로 환산해 표시해야 하며, 다른 라이브 전략의 기존 예약은 바꾸지 않는다.
- **FR-019**: 운영 상태는 생산 라이브 sidecar의 첫 체결 전 재검증 JSON을 읽어 `allowed`와
  `state`를 마지막 preflight 결과로 표시해야 한다. 표에 적힌 작업 성공 문자열만으로 통과를
  추론해서는 안 되며, JSON이 없거나 손상되면 기존처럼 증거 없음으로 실패 폐쇄해야 한다.
- **FR-020**: 첫 운영 매수 직전 라이브 설정의 `canary_capital_pct`는 운영 증거가 선언한 단 1
  자본 비율 10%와 정확히 같아야 한다. 이 값은 센티넬·최신 NAV·정수 주 미리보기를 대신하지
  않는 이중 선언이며, 누락·파싱 실패·불일치이면 신규 주문을 실패 폐쇄해야 한다.
- **FR-021**: `rebalance-once --mode live --confirm-live`의 주문 실행은 GitHub 이벤트의 예정
  시각을 신뢰하지 말고 서버의 실제 시작 시각을 XNYS 달력으로 검사해야 한다. 정규장 밖이면
  데이터베이스 마이그레이션·브로커 조회·주문 전에 임시 실패로 종료하고 다음 개장 시각을
  기록해야 한다. 시작 때 열린 장도 계좌 실행 권한 잠금을 얻은 뒤 각 실제 중개사 쓰기 직전에
  다시 검사하고, 도중 마감이면 `market_hours_gate` 감사 거부와 종료 코드 75를 호출 워크플로까지
  전파해야 하며, 이를 우회하는 명령줄 옵션을 제공해서는 안 된다.
- **FR-022**: 라이브 캐너리는 뉴욕 정규장 안에 서로 떨어진 복수의 비정각 예약 기회를 가져야 한다.
  production 서버는 서명·센티넬·배포 정합을 검증하고 XNYS 정규장임을 확인한 뒤, 뉴욕 거래일별
  실행권을 파일 잠금 아래 추가 전용으로 한 번만 선점해야 한다. 이미 선점된 거래일의 후속 예약은
  `rebalance-once`와 브로커를 호출하지 않아야 하며, 무장된 미리보기나 중복 실행이 최초 실제 실행의
  정화 sidecar를 덮어써서는 안 된다. 수동 `workflow_dispatch`는 계속 주문 0건이어야 한다.

## 핵심 개체

- **운영 검증 증거**: 기존 정확 배포 전략의 장기 시간 분리 성과, 비용 민감도, 설정 지문과
  자본 사용 목적을 묶은 자본 진입 입력.
- **연구 진단 증거**: PEAD 등 새 연구 가족의 역사 결과와 결함을 기록하지만 자본을 열지 않는 입력.
- **실거래 검증 캐너리**: 실계좌 NAV 10% 이하에서 주문·체결·감사·정합 배관을 검증하는 상태.
- **알파 승격 증거**: 깨끗한 전진 표본과 교정된 확률 기준으로 20% 이상을 허용하는 별도 입력.
- **실행 증거**: 주문 요청, 브로커 응답, 체결, 성과, 정합과 차단 이유를 한 실행 단위로 묶은 기록.

## 성공 기준

- **SC-001**: 동일 입력에서 운영 검증 자격은 참, 20% 승격 자격은 거짓으로 100% 재현된다.
- **SC-002**: 진단 전용 PEAD 결과가 최신이어도 자본 판정 결과가 역할 혼동 없이 동일하다.
- **SC-003**: 누락·오래됨·다른 커밋·지문 불일치·강화 검사 실패·구현성 실패의 모든 시험에서
  신규 주문과 자본 증가는 0건이다.
- **SC-004**: 현재 계좌에서 10% 자본은 기존 정수 주 구현성 계약을 통과하고 10%를 초과하지 않는다.
- **SC-005**: 미국 정규장 예약 실행에서 실제 지정가 주문이 브로커에 접수되고, 체결 또는 미체결
  상태와 사후 계좌 정합이 같은 실행 증거에 기록된다.
- **SC-006**: 실제 체결이 발생하면 체결 수량과 가격이 추가 전용 감사 장부와 KIS 조회에서 일치한다.
- **SC-007**: 깨끗한 전진 알파 증거가 부족한 동안 자본은 10%를 넘지 않는다.
- **SC-008**: 전체 테스트, 린트, 엄격 하네스, HANDOFF 사실 검사, PR 품질 관문과 배포 상태 검사가
  모두 통과한다.
- **SC-009**: 라이브 캐너리의 최초 예약은 정각이 아닌 뉴욕 현지 10:17로 구성되고, 후속 기회는
  11:17·12:17·13:17이다. 운영 보고서는 현재 시각 뒤의 가장 가까운 후보를 서머타임까지 반영해
  UTC로 표시한다.
- **SC-010**: 성공한 생산 첫 체결 전 재검증은 운영 보고서에서 `ok=True`, `reason=ENTRY_READY`로
  재현되고, 같은 표에 `success`가 있어도 기계 판독 JSON이 없으면 `ok=None`을 유지한다.
- **SC-011**: 운영 증거가 10%를 선언할 때 라이브 설정의 `canary_capital_pct`가 5%이거나
  누락되면 첫 주문은 `operational_canary_capital_contract` 사유로 차단되고, 10%일 때만 다른
  모든 관문과 함께 통과한다.
- **SC-012**: 정규장·장 마감 뒤·휴장일 고정 시각 시험에서 실주문은 정규장에만 허용되고,
  닫힌 장에서는 데이터베이스 파일과 브로커 호출이 0건인 채 종료 코드 75와 다음 개장 시각을
  남긴다. 첫 주문 뒤 장이 마감되는 고정 시계 시험에서는 두 번째 중개사 호출이 0건이고
  `ORDER_REJECTED_BY_GATE/market_hours_gate`와 종료 코드 75가 남는다. 모든 실주문 워크플로는
  이 종료 코드를 단계 실패로 전파하되 후속 측정·보고는 항상 실행하고, 앞선 `SUBMITTED` 주문이
  있으면 부분 실행으로 표시해야 한다. 종이매매와 `--dry-run`은 영향을 받지 않는다.
- **SC-013**: 한 뉴욕 거래일에 예약이 여러 번 도착해도 서버 실주문 명령은 정확히 한 번만
  `rebalance-once`에 도달한다. 첫 예약이 누락돼도 뒤 예약은 실행 기회를 제공하고, 중복 예약은
  원래 run ID를 보고하며 주문·체결 측정과 production sidecar를 다시 쓰지 않는다.

## 가정과 의존성

- 사용자의 현재 지시는 실거래 검증 캐너리와 계좌 NAV 10% 자본 배분에 대한 명시적 운영자 결정이다.
- 현재 계좌, KIS production 환경, 주문 서명 키와 SSH 경계는 기존 운영 설정을 재사용한다.
- 현재 라이브 포트폴리오는 `globalfixed` 신호를 `SPY→SCHX`, `IEF→SPTI`, `GLD→IAUM`으로
  1:1 매핑하고 `ORANY`를 비관리 외부 보유로 유지한다.
- 장중 배포 금지를 유지하므로 예약 신뢰성 보정은 장 마감 뒤 exact-main 배포가 확인된 다음
  거래일부터 효력을 갖는다. 이미 배포된 단일 예약은 그 전까지 기존 정규장 게이트 아래 감시한다.
- 실거래 검증은 수익 보장이 아니라 운영 배관과 작은 실제 노출을 검증하는 단계다.

## 되돌림과 실패 영향

- 문제가 생기면 센티넬을 단 0·`armed:false`로 내리고 기능 커밋을 되돌린다.
- 이미 접수·체결된 주문과 감사 행은 삭제하거나 고치지 않는다. 필요하면 기존 허용된 위험 축소
  경로로만 정리한다.
- 진단 연구 sidecar와 과거 오염 장부는 포렌식 증거로 보존한다.
- 이 기능은 헌법 X.4의 첫 자본 진입 경로를 추가하므로 헌법 버전을 올리고 전용 커밋에
  `this changes the safety perimeter`를 기록한다.
