# 기존 체결 전략의 서버 예약 계약 (2026-10-16)

위험 등급4. 실제 배포로 기존 예약의 주문 가능성이 바뀌므로 운영자 명시 승인 전에는
병합·배포·타이머 실행을 하지 않는다. 코드/합성 검사/초안 PR 준비는 먼저 끝낸다.

## 입력과 상태
기존 live_entry_revalidation_probe의 종료코드0과 schema_version=1.0,
allowed=true(불리언), fills_count(0 이상의 정수)를 모두 요구한다.
ENTRY_READY는 fills_count=0, ACTIVE_LIVE_TRACK은 fills_count>0에서만 허용한다.
문자열/불리언/분수/음수/누락 수량, 다른 상태, allowed=false, 비정상 종료는 거절한다.
ACTIVE_LIVE_TRACK은 기존 전략에 실제 체결 이력이 있다는 기존 평가기의 뜻이며
새 전략 합격·수익성·추가 자본 허가가 아니다.

## 출력과 권한
기존 summary1.1 entry_state에 실제 평가 상태를 남긴다. ENTRY_READY로 바꾸어 쓰지 않는다.
조회 소비자는 두 허용 상태를 읽되 나머지 닫힌 스키마·실패 처리를 유지한다.
이전 ENTRY_READY 요약도 읽는다. 기존 same-session retry는 ENTRY_READY 전용을 유지한다.
ACTIVE_LIVE_TRACK 요약으로 복구 기회나 추가 슬롯을 열지 않는다.

## 보존할 경계
현재 main/배포 일치, 배포 감사, 정규장, 기존143달러 센티넬/한도, 계좌 대사,
손실 브레이커, 허용 종목, 지정가, 공유 거래일1회 선점, 내부 systemd-order 재검사,
권한·비밀·추가 전용 감사는 변경하지 않는다. 수동 주문/타이머 시작은 없다.

## 반례와 완료
원래 평가기의 ACTIVE_LIVE_TRACK 출력을 실제 shell 함수에 넣어 기존 거절을 재현한다.
상태/수량/allowed/종료코드 반례, 실제 summary 생성 및 조회, 기존 중복/리비전/위험 검사,
전체 회귀/린트/강화 캐너리·하네스/인계를 통과해야 한다.
승인 전 완료는 검토 가능한 초안이다. 승인 뒤 정상 장외 배포 감사와 기존 예약 관측을
구분하며 주문 또는 체결을 인위적으로 만들지 않는다. 전체181의 완료는 별개다.

## 되돌림
정상 revert PR로 기존 거절을 복원하고 장외 배포한다. 원래 주문·감사·선점·체결 기록은
지우거나 재시도용으로 초기화하지 않는다. 기존 GitHub 경로와 손실/대사 관문은 계속 유지한다.
