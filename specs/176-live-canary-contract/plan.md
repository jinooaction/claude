# 구현 계획: 증거 수렴형 실거래 검증 캐너리

**브랜치**: `codex/176-server-scheduler-deploy-equivalence` | **작성일**: 2026-09-02
**명세**: [spec.md](spec.md) | **위험 등급**: 4 - 실제 자본·주문 경로 변경

## 요약

장기 시간 분리 검증과 정확한 배포 지문을 통과한 기존 `globalfixed` 전략에 대해 실계좌 NAV의
10%까지만 운영 검증 캐너리를 허용한다. 이 상태는 주문·체결·감사·정합 배관을 검증하기 위한
것이며 확정 알파가 아니다. 20% 이상 승격은 기존 깨끗한 전진 표본·PSR·칼마·전체 경로 교정
요건을 그대로 유지한다. 연구 진단 결과와 자본 진입 증거는 별도 파일과 역할로 발행한다.
GitHub 예약 공급자가 모든 후보를 장 마감 뒤에 만들 수 있는 생산 실패를 제거하기 위해,
GitHub를 주 경로로 유지하면서 root 소유 production systemd timer를 독립 fallback으로 추가한다.
두 경로는 같은 XNYS 거래일 선점으로 수렴해 실제 주문 시도는 하루 한 번만 허용한다.
정수 주 구현성은 모든 양의 목표를 시세·비중 오차에 유지하되, 목표금액으로 최소 1주를 살 수
있는 목표에만 기존 66% 자금 배치 비율을 적용해 소액 계좌의 기계적 전체 차단을 제거한다.
독립 서버 타이머는 문서 전용 main 진행을 미배포 코드로 오인하지 않도록, 실제 배포 커밋의
감사 완료와 현재 main 증거 커밋을 분리해 검증한다. 두 커밋 사이가 기존 고정 비실행 경로만일
때만 운영 동등성을 인정하고 다른 변경은 계속 실패 폐쇄한다.

## 기술 배경

- **언어/런타임**: Python 3.11, Bash, GitHub Actions, production systemd
- **주요 의존성**: NumPy, Pydantic, `exchange_calendars`, KIS REST 경계
- **상태 저장**: sidecar 브랜치의 추가 전용 JSON, 서버의 SQLite 주문·체결·감사 장부,
  root 소유 거래일 선점과 정화된 fallback 실행 증거
- **실행 경로**: `Backtest -> 10% Operational Canary -> 20% Exploration -> Full`
- **주문 제약**: KIS production, 정수 주, 지정가, 미국 정규장, GitHub 서명·nonce 또는 고정
  root systemd 신원, 공통 일일 선점, K1/K2
- **기본 검증**: `uv run pytest`, `uv run ruff check src tests`

## 헌법 점검

### 구현 전 관문

- K1 포지션 한도와 K2 허용 종목은 낮추지 않는다.
- 연 20% 손실 예산, 절반 하향, 전액 정지, 킬스위치를 유지한다.
- 비밀값은 GitHub Actions와 서버 비밀 경계 밖으로 노출하지 않는다.
- 주문·체결·오류 감사 로그는 추가 전용으로 유지한다.
- 외부 API 장애, 정합 불일치, 오래된 증거는 실패 폐쇄한다.
- 장중에는 배포하지 않고, 주문은 정규장 자동 예약 실행만 사용한다.
- `Backtest -> Canary -> Full` 단계를 생략하지 않는다.
- 독립 서버 fallback의 운영 리비전 의미를 바꾸므로 헌법 X.4를 14.0.0으로 별도 커밋한다.

### 설계 후 관문

- 운영 검증 자격과 알파 승격 자격은 다른 필드와 파일로 분리된다.
- 운영 증거 소비자가 원시 월별 수익률을 재계산해 제작자의 자기 판정을 신뢰하지 않는다.
- 10% 운영 캐너리는 센티넬에 진입 출처를 기록하고, 그 출처만으로 20%에 오를 수 없다.
- 첫 매수 직전에 코드 커밋·전략 지문·강화 검사·체결 대리·정수 주·정합·halt를 재검사한다.
- 위험 축소 매도는 오래된 연구 증거 때문에 막히지 않는다.
- 실제 체결이 없으면 완료로 선언하지 않는다.
- GitHub와 server timer는 같은 거래일 선점 파일과 잠금을 사용하고, 선점 뒤 실패도 재주문하지 않는다.
- server timer는 배포 커밋→현재 main 조상 관계와 고정 비실행 경로 동등성, 첫 진입 재검증 전에
  선점을 소비하지 않으며 원격 주문 명령으로 노출되지 않는다.

## 구현 순서

1. 명세·계획·과제와 계약을 먼저 커밋한다.
2. 헌법 X.4에 10% 운영 검증 캐너리를 추가하고 버전을 올려 전용 안전 경계 커밋을 만든다.
3. 운영 증거 검증, 역할 분리, 10% 진입, 20% 승격 차단, 첫 주문 재검사의 실패 테스트를 먼저 만든다.
4. 원시 월별 요인과 진단값을 포함한 운영 검증 증거 제작기·독립 검증기를 구현한다.
5. `strategy_factory.json`의 혼합 역할을 진단 파일과 `capital_entry_evidence.json`으로 분리한다.
6. 자본 사다리와 첫 주문 재검사기가 운영 증거를 명시적으로 소비하게 한다.
7. 센티넬에 `entry_route`를 기록하고 운영 경로가 단 1을 넘지 못하게 한다.
8. 전체 테스트·린트·엄격 하네스·HANDOFF 사실 검사·PR 품질 관문을 통과시킨다.
9. 커밋·푸시·PR·머지 뒤 main 배포와 sidecar 증거 발행을 확인한다.
10. 최신 NAV의 10%로 단 0에서 단 1까지 무장됐는지 확인한다.
11. 다음 미국 정규장 예약 실행에서 실제 주문·체결·정합·감사 기록을 확인한다.
12. 최종 운영 상태를 `HANDOFF.md`에 기록하고 다시 검증한다.
13. 실제 예약 지연 이력과 GitHub 공식 권고에 따라 라이브 캐너리만 뉴욕 현지 10:17 비정각
    예약으로 바꾸고, 운영 화면의 다음 실행 시각을 같은 계약으로 맞춘다.
14. 예약이 장 마감 뒤 도착해도 주문되지 않도록 `rebalance-once` 실주문 진입점이 서버 실제

    4xx 즉시 실패와 실제 응답 거래소 기반 주문 코드 매핑을 유지한다.

    `auto-invest-live-canary.timer`를 독립 fallback으로 추가한다. 실패 시험을 먼저 작성해 root·systemd
    신원, exact-main, 첫 진입 재검증, XNYS, 10% 센티넬, 공통 거래일 선점, 선점 뒤 무재시도,
    사후 체결·측정·정합 증거와 고정 읽기 전용 상태 조회를 잠근다. GitHub가 서버 선점 뒤 늦게
    도착하면 broker call 없이 최초 서버 실행을 sidecar에 발행하게 한다.
21. 생산 run `33540003731`에서 1주 미만 IAUM 목표가 전체 양의 목표 분모에 포함되어 SCHX의
    안전한 계획까지 차단한 사실을 고정 입력으로 재현한다. 전체 목표 진단과 정수 주 표현 가능
    목표 진단을 분리한 새 증거 계약을 먼저 시험하고, 표현 가능 목표 66%·전체 오차 25%·종목
    오차 15%·기존 노출 한도를 모두 통과할 때만 비어 있지 않은 부분 구현을 허용한다.
22. 2026-09-02 독립 server timer가 설치·활성 상태에서도 실행 요약을 남기지 못한 원인을,
    직전 exact deploy 뒤 `HANDOFF.md` 전용 main 머지와 서버 경로의 문자열 동등성 검사로 재현한다.
    기존 GitHub 주문 경계의 고정 비실행 경로 목록보다 넓히지 않고, 배포 커밋 조상 관계·경로
    분류·현재 main 재확인·실제 배포 감사·두 커밋 증거를 scheduler와 내부 주문 경계에서 잠근다.
23. 생산 가동성 보정이 뉴욕 13:59 뒤 배포되면 당일 독립 후보가 없어 또 하루를
    기다리게 되는 회복 공백을 없앤다. GitHub 후보와 새 수동 경로는 늘리지 않고, root
    systemd fallback만 15:35까지 12분 간격으로 연장한다. 여러 후보는 기존 공유 거래일
    선점으로 주문 1회로 축약하고, 마감 25분 전 이후에는 새 기회를 만들지 않는다.
24. GitHub 예약이 늦을 때 독립 서버 timer의 실행 여부를 같은 공급자의 다음 예약까지 기다리지
    않고 확인한다. 기존 forced-command의 `live-canary-scheduled-status`만 호출하는 수동 읽기 전용
    워크플로를 추가하고, 닫힌 summary 1.1 검증과 정화 sidecar만 허용한다. 주문·서비스·timer를
    실행하는 명령은 넣지 않고 유효한 요약이 없으면 실패 폐쇄한다.
25. 생산에서 `scheduled-status`가 종료 코드 2만 반환해 타이머 미발화와 선점 전 실패를 구분하지
    못한 관측 공백을 닫는다. 기존 root helper에 인자 없는 `runtime-status` 읽기만 추가하고,
    timer/service의 고정 systemd 속성과 원문 없는 고정 사건 코드만 JSON으로 반환한다. 관측 workflow는
    성공 요약이 없을 때만 이 진단을 읽어 별도 파일로 발행하며 최종 성공 판정은 계속 거부한다.

## 롤백

센티넬을 `armed:false`, 단 0, 자본 0으로 내리고 server timer를 disable한 뒤 기능 커밋을 되돌린다. 기존 주문·체결·감사
행은 삭제하지 않는다. 이미 산 보유분은 기존 위험 축소 경로로만 정리한다. 연구 진단과 과거
오염 장부는 포렌식 자료로 보존한다.
