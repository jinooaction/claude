# 자료 계약

- 서버 저장소는 고정 디렉터리의 `blobs`(원문), `observations`(실제 수신 기록), `runs`(완료 기록)를 추가 전용으로 보관한다. 기존 GitHub 발행사 저장소와 처음부터 다른 사슬이다.
- 예정 시각과 실제 시작·종료는 별개다. 완료 기록이 없으면 성공으로 세지 않는다. 상태 조회는 지난 24시간의 예정 시각과 실제 기록을 비교해 빠진 칸을 표시한다.
- 정상 시도마다 RSS 목록을 새로 요청해 요청·수신·검증 시각을 남긴다. 같은 원문이면 원문 파일은 중복 저장하지 않아도 관측 기록은 새로 남긴다.
- `selection.unchanged`는 동일한 목록, 최근 24시간 안의 선택 본문 전체 성공, 직전 실행 실패 없음이 입증될 때만 양수다. 기존 `unselected`(범위 밖)와 `limit_skipped`(요청 한도 초과)는 별도로 센다. 과거 두 필드 기록도 계속 검증한다.
- 본문 관측은 실제 새 요청과 검증이 있을 때만 추가한다. 이전 원문을 복사해 새로운 관측 시각을 붙이지 않는다.
- 원격 사본은 기존 파일의 지문이 모두 일치할 때만 새 파일을 추가한다. 서버 기록을 기존 GitHub 수집 기록과 섞지 않는다. 복구가 필요하면 원래 시각은 보존하되 복구 때문에 과거에 이용 가능했다고 주장하지 않는다.
- 서버 상태는 마지막 실제 시도·성공·실패, 사슬 지문, 지난 24시간의 누락을 보여 준다. 원격 백업의 최신 결과와 지문은 별도의 GitHub 실행 보고서와 보존 브랜치에서 확인한다.
