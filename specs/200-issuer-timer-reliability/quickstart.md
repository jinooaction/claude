# 검증 순서

1. 목록이 같을 때와 달라질 때, 본문 요청이 실패할 때, 24시간이 지날 때를 모의 시험한다. 저장 한도에 가까우면 외부 요청 전에 중단하는지도 확인한다.
2. Linux에서 새 서비스와 타이머를 분석한다. 서비스가 계좌 환경 파일이나 주문 명령을 읽지 않는지 확인한다.
3. 정확한 풀 리퀘스트 커밋으로 원격 전체 테스트·린트와 엄격 하네스·인계·본문 품질 검사를 통과한다.
4. 일반 병합과 장외 배포를 확인한다. 유닛 설치와 코드 배포는 서로 다른 단계이므로 각각의 결과를 남긴다.
5. 실제 서버 수집 두 번을 확인한다. 두 번째 목록이 같다면 본문 생략 기록을 검사하고, 서버 원본과 원격 사본의 지문을 대조한다.
6. 서버가 정상 가동된 24시간의 예정 시각 96개를 실제 기록과 대조한다. 이 결과가 나오기 전에는 15분 정기 관측이 완료됐다고 말하지 않는다.

수집 범위는 고정된 Microsoft 출처다. 기존 GitHub 수집, SEC 실패 기록,
계좌·주문 경로는 각각 별개로 유지한다.
