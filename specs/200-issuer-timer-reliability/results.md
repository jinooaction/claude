## 실제 파일 크기와 정상 60일 저장량 계산

검증된 최신 18run/72관측 원본의 파일 길이를 직접 읽었다. 목록 18관측은 동일
136,389바이트 원문 1개를 가리키며 최대 영수증은 432바이트였다. 본문 54관측은
서로 다른 54원문을 가리키고 평균 148,082바이트, 최대 169,401바이트이며 최대
영수증은 677바이트였다. 최대 완료 기록 파일은 1,235바이트다.

동일 목록을 15분마다 확인하는 정상 60일(5,760회)에 첫 본문 수집과 하루 단위
재검증을 보수적으로 183본문으로 잡고, 위 **관측 최대값**을 모든 파일에 적용하면
`5,760×(432+1,235)+183×(169,401+677)+136,389 = 40,862,583바이트`
(약 39.0MiB)다. 기존 누적 512MiB와 실행 전 64MiB 예약보다 낮다.
이는 실제 파일 크기를 이용한 상한 계산이지 5,760회의 서버 실행 증거가 아니다.
목록이 자주 바뀌거나 본문이 커지면 다시 계산해야 하며 한도에 닿으면 중단한다.

## 코드 검사·병합·서버 배포

서버 전용 CLI는 같은 목록의 검증 완료 본문만 24시간 이내에 재요청 생략하고
`selection.unchanged`를 기록한다. 기존 두 필드 완료 기록은 그대로 검증된다.
새 타이머는 별도 저장소와 고정 Microsoft 범위만 사용하며 KIS 환경 파일을
주입하지 않는다. 원격 내보내기는 고정 명령·고정 디렉터리·원본 지문 검사를 거치고,
복구 사본은 기존 GitHub 발행사 사슬과 다른 브랜치에 추가 전용으로 둔다.
정확한 코드 커밋 `3a5be4c0307aee828f3c4bd8ec29d9af76d7117e`의 PR862 원격
검사 `36941200854`에서 전체 5175 passed/13 skipped(1167.77초)와 린트 통과를
확인했다. 로컬 경량 검사 59 passed/1 skipped(맥에 systemd 분석기 없음), 셸
구문·YAML·변경점 검사, 엄격 하네스 14/14, HANDOFF 사실 검사와 PR 본문 품질
검사도 통과했다. PR862는 main `2be0bd0fcb253a17b30967d32d4797934dbb52fb`에
병합됐다. 배포 `36943026943`의 상관 ID `f63da32c3d6690cdec60375f792d0214`를
읽기 전용 감사 `36943253742`로 확인했다. 서버 행 19586·19587·19592는
`DEPLOY_STARTED`→`DEPLOY_KERNEL_TOUCHED`→`DEPLOY_COMPLETED`이며 목표 SHA는
해당 main이다. K6에 속하는 제한 SSH 게이트웨이 파일을 수정했고 두 커밋의
안전 경계 변경 문구를 PR 본문에 기록했다.

첫 배포 전 유닛 동기화는 이전 도구를 사용해 새 두 유닛을 설치하지 못했다.
정상 배포 재실행 `36943160980`은 최신 동기화 도구로 새 서비스·타이머를
설치하고 `systemctl enable --now`를 오류 없이 마쳤다. 매번 재실행하지 않도록
배포 뒤 갱신된 도구로 다시 동기화하는 보정을 후속 PR에서 검증 중이다.
