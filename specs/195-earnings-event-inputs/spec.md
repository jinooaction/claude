# Feature Specification: 관측 시점이 보존되는 실적 사건 입력

**Feature Branch**: `codex/195-earnings-event-inputs`  
**Created**: 2026-09-21  
**Status**: Specified  
**Input**: 기존 한국투자 계좌용 단타 프로그램 완성. 가격 조건 반복 대신 실제 공시 자료를 확보하고 검증한다.

## User Scenarios & Testing

### User Story 1 - 실제 문서와 사건을 연결한다 (Priority: P1)

운영자는 실적 발표 예정과 실제 발표를 원문 근거로 구분하고, 출처가 바뀌거나 훼손되면 알아야 한다.

**Why this priority**: 날짜와 종류가 잘못된 사건은 전략 검증에 쓸 수 없다.
**Independent Test**: 확보한 Microsoft 일정과 발표문을 별도 사건 기록으로 읽고 원문 변조를 거부한다.

**Acceptance Scenarios**:
1. **Given** 공식 일정 원문, **When** 예정 사건을 등록, **Then** 실제 발표로 전환하지 않고 예정일과 원문 표현을 남긴다.
2. **Given** 실적 발표문, **When** 회사와 보고 기간을 연결, **Then** 원문 근거와 종목 연결의 미확인 상태를 따로 표시한다.

### User Story 2 - 그때 알 수 있었던 정보만 조회한다 (Priority: P1)

운영자는 정확한 최초 공개 초를 몰라도 실제 문서 관측이 끝난 뒤의 정보만 연구에 사용할 수 있어야 한다.

**Why this priority**: 나중에 확보한 내용을 과거에 알았다고 처리하면 성과 검증이 잘못된다.
**Independent Test**: 옛 날짜가 적힌 현재 사본은 과거 조회에 나타나지 않고, 나중 정정본을 추가해도 과거 조회 결과가 바뀌지 않는다.

**Acceptance Scenarios**:
1. **Given** 2026년에 확보한 2014년 문서, **When** 2014년 기준 조회, **Then** 미관측으로 판정한다.
2. **Given** 관측 완료 구간, **When** 구간 종료 직전/정확히 종료한 시각 조회, **Then** 각각 숨김/노출한다.
3. **Given** 접수 시각이나 게시 메타데이터만 있음, **When** 이용 가능 시각 계산, **Then** 관측 시각 대신 사용하지 않는다.

### Edge Cases

예정과 실제 날짜 불일치, 보고 기간 미기재, 중복 식별자, 뒤늦은 수정본, 시간대 누락,
거꾸로 된 관측 구간, 원본 변조, 없는 인용문, 미확인 종목 연결, 빈 사건 목록,
조회 실패와 사건 없음의 혼동, 관측 후 정정 전후의 조회를 검사한다.

## Requirements

### Functional Requirements

- **FR-001**: 회사 고유 식별자, 사건 종류, 보고 기간(미기재 허용), 예정/실제 사건 날짜와 시각 정밀도를 보존한다.
- **FR-002**: 원문 출처, 원본 지문, 원문 인용, 출처가 주장하는 게시·수정·접수 시각을 별도로 기록한다. 이 주장을 관측 시각으로 승격하지 않는다.
- **FR-003**: 현재 로컬 원문을 읽고 확인한 시작·완료 시각을 기록한다. 이는 로컬 관측 증거이며 원격 접속·과거 버전·전 세계 최초 공개 시각의 증명이 아니다.
- **FR-004**: 사건별로 원문 관측과 내용 확인이 모두 완료된 시각 이후에만 조회한다. 정확한 공개 초나 임의 지연 시간을 만들어내지 않는다.
- **FR-005**: 정정본은 원본을 보존한 새 기록으로 추가한다. 같은 사건·종류의 이전 기록을 명시적으로 연결하고 과거 조회 결과를 보존한다.
- **FR-006**: 종목 연결 확인은 별도 상태로 남기며 미확인 연결을 매매 입력으로 표시하지 않는다. 사건을 찾지 못한 회사는 조사 범위 미확정으로 표시한다.
- **FR-007**: 입력 이상은 오류로 거부하고 성공 보고서를 만들지 않는다. 새 출력만 허용하여 기존 증거를 덮어쓰지 않는다.
- **FR-008**: 실제 두 원문으로 가져오기·과거 조회·현재 조회를 실행하고 반례 자동 검사를 제공한다. 조회 결과는 연구 입력일 뿐 전략 채택·주문·자본 권한이 아니다.

### Key Entities

- 원문 관측: 원본, 출처 주장, 로컬 확인 구간, 파일 지문.
- 사건 버전: 회사·기간·종류·날짜, 원문 근거, 이전 버전, 내용 확인 시각.
- 기준 시점 조회: 그때까지 확인한 사건 버전과 미확인 범위.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 실제 확보한 일정·발표문 두 건을 서로 다른 종류로 재현 가능하게 등록한다.
- **SC-002**: 현재 사본, 미래 정정, 접수 시각 대용, 잘못된 원본 등 반례에서 과거 정보 노출이 0건이다.
- **SC-003**: 같은 원본·조회 시각으로 동일한 결과가 나오고, 모든 노출 사건의 근거를 추적할 수 있다.
- **SC-004**: 원본 덮어쓰기, 주문, 자금 이동은 0건이며 전체 프로그램 미완료 항목을 그대로 유지한다.

## Assumptions

- 위험 등급 2: 새 연구 입력 도구와 다음 세션의 명세 포인터를 추가한다. 실제 주문·안전 관문은 변경하지 않는다.
- 원문 내용과 회사 연결은 사람이 검토한 주장이다. 인용문 존재 검사는 의미·원격 출처 진위를 자동 증명하지 않는다.
- 과거 버전 증명을 임의 입력하는 기능은 제공하지 않는다. 현재 사본으로 과거 성과를 계산할 수 없다는 한계를 보존한다.
- 이번 범위는 재사용 가능한 오프라인 입력·조회다. 웹 수집 자동화, 전체 회사 역사 확보, 수익성 검증은 후속 작업이며 전체 목표에서 제외하지 않는다.
- 제거 기능 없음. 되돌릴 때 새 도구 사용과 명세 포인터만 이전 버전으로 복원하며 기존 원문은 보존한다.
