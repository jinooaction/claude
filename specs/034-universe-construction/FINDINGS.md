# 스펙 034 — 유니버스 구성 역량 + (정정) stale 데이터 백테스트 한계

## ⚠ 중요 정정 (2026-06-03, 운영자 지적 반영)

이 문서의 이전 판은 **2013–2018(8년 묵은) 데이터** 백테스트 결과로 "폭을 넓혀도 엣지가
없다 → 좁은 유니버스 탓 가설을 닫았다"고 **과장 선언**했다. 이는 이 프로젝트가 이미
2026-06-01에 확립한 교리(`FORWARD-VALIDATION.md`)를 정면으로 위반한다:

> 옛 데이터 백테스트는 값싼 과적합 필터일 뿐, 무엇도 정당화하지 못한다. "지금 통하는가"의
> 유일한 정직한 판정은 **현재 데이터 forward 페이퍼**다.

게다가 최근성 가드(`backtest/recency.py`)가 실행 중 **"등급=stale, 단독으로 라이브를
정당화하지 말고 forward 페이퍼로 확인하라"** 고 경고했는데도 무시했다. **stale 데이터로는
"지금 폭이 도움이 되는가"를 닫을 수 없다.** 아래 백테스트 수치는 *옛 강세장 한 구간의
과적합-필터 데이터포인트*일 뿐, 폭(breadth) 가설에 대한 판정이 아니다.

## 한 줄 (정정판)

**유효한 결과물은 데이터 빈티지와 무관한 역량 하나다**: 종목을 손으로 고르지 않고 유동성으로
체계적으로 *구성*하는 `strategy/universe.py` + CLI `build-universe`. 이 도구는 **현재 데이터
forward 페이퍼 트랙**(스펙 032/033)에 적용돼야 가치가 있다. 옛 데이터 백테스트로 폭 가설을
판정하려 한 것은 실수였다.

## 유효한 역량 (데이터 무관, 재사용)

세계 최고 수준 시스템은 종목을 손으로 고르지 않는다. 투자 가능 횡단면에서 **유동성**으로
체계적으로 *구성*한다:

- `strategy/universe.py` — `median_dollar_volume` / `liquidity_rank` / `select_universe`
  (결정론 Decimal, 비커널, 선택 전용). 중앙값 달러 거래대금으로 순위 → 최소 이력·최소
  유동성 필터 → 상위 N 구성. 단위 테스트 13건.
- CLI `auto-invest build-universe` — **임의의 적재 데이터셋**(옛것이든 현재든)에서 유동성
  상위 유니버스를 구성. **핵심은 이걸 인스턴스의 *현재* `price_bars` 에 적용**해 forward
  페이퍼/캐너리 유니버스를 손이 아닌 유동성으로 구성하는 것이다.
- `scripts/fetch_sp500_subset.py --all` — 데이터셋 전체 횡단면 추출.

## stale 데이터 백테스트 (판정 아님 — 한계 시연일 뿐)

데이터: `plotly/datasets/all_stocks_5yr.csv` (2013-2018, 오늘 기준 ~3038일 전 = stale).
최근성 가드가 정상적으로 stale 경고 발동. 4개 365일 표본 외 구간.

| 설정 | 가중 | 보유 | 구간 승 | 평균 샤프(전략 vs 보유) | DSR |
|---|---|---|---|---|---|
| A | equal | top-20 | 0/4 | 0.49 vs 1.41 | 0.81(1시도) |
| B | min_variance | top-40 | 1/4 | 0.49 vs 1.41 | 0.057(3시도) |

이 구간(2013-2018 대형주 강세장)에서 균등가중 단순 보유는 이기기 어려운 벤치마크다. **하지만
이건 8년 전 한 regime의 이야기일 뿐, "2026년에 폭이 도움이 되는가"와는 무관하다.** 이 수치로
어떤 전략 결론도 내리지 않는다(교리: 옛 데이터는 정당화 금지).

## 올바른 다음 단계 (현재 데이터, forward 페이퍼)

1. **유니버스 구성을 현재 데이터에 적용**: 라이브 인스턴스의 `price_bars`(스펙 033 일일
   백필이 매 거래일 채움)에 `build-universe` 를 돌려 forward 페이퍼/캐너리 유니버스를
   유동성으로 구성. 현재 `canary-portfolio.toml` 은 손으로 고른 10종목 — 이걸 체계적 구성으로
   대체(단, 인스턴스가 충분한 종목의 일봉을 백필해야 폭이 생김 → 백필 유니버스 확대 선행).
2. **forward 페이퍼가 판정**: 페이퍼 체결이 쌓이면 스펙 011 성과 + 스펙 027 디플레이티드
   샤프로 "지금 우연 아닌 엣지"를 판정. 이게 유일한 정직한 잣대.
3. **이 컨테이너의 한계 직시**: 라이브 시세(KIS·Yahoo·Stooq) 차단 + github raw 일봉은 전부
   옛것 → **이 컨테이너에서 현재 데이터 다종목 일봉 백테스트는 불가능**. 그래서 옛 데이터
   백테스트로 우회한 것이 애초에 잘못된 선택이었다. 현재 데이터 판정은 인스턴스 forward
   페이퍼에서만 일어난다.
