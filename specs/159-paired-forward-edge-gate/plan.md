# Implementation Plan: Paired Forward Edge Gate

**Branch**: `Codex/159-strategy-usability-energy-replication` | **Date**: 2026-08-25 | **Spec**: `specs/159-paired-forward-edge-gate/spec.md`

## Summary

Correct the forward gate so benchmark-relative evidence is computed from aligned active returns instead of treating an estimated benchmark Sharpe as a fixed independent target. Calibrate the revised statistic against null and planted controls, version the evidence, fail closed downstream on legacy evidence, then replay the deployed forward tracks without orders.

## Technical Context

- **Language**: Python 3.12 and the existing `uv` environment
- **Primary modules**: `portfolio/edge_verdict.py`, `analytics/forward_gate_calibration.py`, downstream tournament/profit/ladder readers
- **Entrypoints**: existing `forward-verdict`; new `forward_gate_calibration_probe.py`
- **Production path**: `rebalance-paper-forward.yml` publishes calibration, versioned verdicts, and leaderboard evidence
- **Tests**: unit property/regression tests, probe integration, workflow contracts, full pytest and ruff
- **Constraints**: unchanged 0.80/0.95 thresholds, exact period alignment, no broker imports/orders/capital changes

## Constitution Check

- Principles I-VII and VIII.A remain unchanged.
- Principle X.2 is strengthened: paper and production now use one correctly specified paired benchmark-relative statistic.
- Principle X.4 thresholds and the `Backtest -> Canary -> Full` ladder are unchanged.
- Grade 4 full SDD is required because corrected evidence can affect capital eligibility.
- Constitution and kernel files are not modified.
- Rollback is one commit revert; new-method requirements then reject stale paired evidence rather than reinterpret it.

## Design

1. Compute strategy and benchmark simple returns on equal-length curves.
2. Compute active returns as the period-by-period difference and run PSR, optional DSR, and MinTRL against zero on that active series.
3. Keep absolute strategy/benchmark Sharpe, total return, drawdown, Calmar, positive excess, and Sharpe superiority as separate required evidence.
4. Add `significance_method=paired_active_return_psr_v1`, active information ratio, and schema 1.2 to verdict JSON.
5. Reject mismatched lengths and zero active variance as `INSUFFICIENT_DATA`.
6. Run a deterministic 48-observation paired simulation with 5,000 null and 5,000 planted repetitions; publish nominal-error and power comparisons.
7. Propagate the method through the tournament and profit evidence; require it in exploration, live-entry revalidation, and direct `EDGE_CONFIRMED` ladder admission.
8. Publish calibration beside the forward leaderboard and replay the production worker only after deployment.

## Verification

- Invariance to common market shocks, alignment failure, zero active variance, positive/null controls, method/schema serialization, and downstream legacy rejection.
- Calibration: paired null false acceptance at 0.80 in `[0.17, 0.23]`, at 0.95 at most `0.06`; planted detection above legacy.
- `uv run pytest`, `uv run ruff check src tests`, YAML parse, strict harness, HANDOFF fact check, PR quality gate.
- After merge: deploy, dispatch forward paper replay, confirm sidecar method/calibration, rerun profit evidence and money path, then KIS no-order smoke.

## Reversal

Revert the feature merge and redeploy. Because downstream readers require the explicit paired method for new forward promotion, evidence generated by the reverted legacy implementation cannot silently retain paired eligibility.
