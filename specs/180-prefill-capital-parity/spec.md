# Feature Specification: 첫 체결 전 검증·실행 자본 정합

**Feature Branch**: `codex/180-prefill-capital-parity`  
**Created**: 2026-09-05  
**Status**: 기능 출시, 생산 예산 정합·실제 체결 검증 진행  
**Input**: 오너 요청 — 시스템을 재점검하고 안전 한도 안에서 실제 자동매매 가능한 상태로 복구한다.

## User Scenarios & Testing

### User Story 1 - 같은 예산으로 검증하고 실행한다 (Priority: P1)

첫 체결이 없는 운영 검증 단계에서는 현재 계좌 기준으로 통과한 예산이 실제 주문 승인에도 반영돼야 한다.

**Why this priority**: 현재 계좌의 10% 검증은 통과해도 과거 예산이 남아 실제 진입만 차단될 수 있다.

**Independent Test**: 순자산 $1434.91, 과거 승인액 $142, 현 검증액 $143에서 단계를 높이지 않고 승인액만 $143으로 갱신한다.

**Acceptance Scenarios**:

1. 현재 10% 예산의 모든 진입 검증과 명확한 전략 체결 0건 증거가 있을 때 10% 미만 변동도 갱신한다.
2. 같은 금액을 재계산하면 상태를 다시 쓰지 않고 진입 날짜를 유지한다.
3. 현재 예산에서 종목별 오차 15%p나 전체 오차 25%p를 넘으면 통과시키지 않는다.

### User Story 2 - 모르는 상태에서는 특별 갱신하지 않는다 (Priority: P1)

**Why this priority**: 과거·전체 계좌 체결과 현재 전략의 체결을 혼동하면 운용 예산의 근거가 깨진다.

**Independent Test**: 체결 증거 누락·오형식·다른 범위·품질 경고·이미 체결됨·다른 단계·자격 미달에서 작은 변동 특별 갱신이 0건이다.

**Acceptance Scenarios**:

1. 현재 운영 검증 1단 이외에는 기존 재계산 규칙을 유지한다.
2. 체결이 있거나 확인할 수 없으면 기존 10% 변동 규칙을 유지한다.
3. 중지 장치·손실 강등·전략 불일치·입력 불능은 갱신보다 먼저 처리한다.

### Edge Cases

- 순자산이 하락하거나 10%를 내림한 금액이 같음; 1달러 미만; NaN/무한/음수.
- `false`, `0.0`, 문자열 `0`은 정수 체결 0건 증명이 아님.
- 가격이나 목표가 바뀌어 현재 10%로도 정수주 구성이 불가능하면 실패 차단한다.
- 미체결·접수 불명·소비된 거래일 선점은 예산 갱신으로 삭제되거나 재시도되지 않는다.

## Requirements

### Functional Requirements

- **FR-001**: 운영 검증 1단에서만 최신 진입 검증이 통과하고 현재 전략의 신뢰 가능한 체결 수가 정확히 0이면 기존 10% 변동 대기 없이 현재 순자산의 10%를 달러 단위 내림한 금액과 승인액을 맞춘다.
- **FR-002**: 새 승인액은 해당 검증의 예산과 같아야 하며, 비율 10%, 단계 1, 진입일, 전략, 손실 예산을 유지하고 변경 이력을 남긴다.
- **FR-003**: 누락·불확실·품질 경고·타 범위 체결 자료에는 특별 갱신을 적용하지 않는다. 다른 경로와 첫 체결 이후 규칙은 바꾸지 않는다.
- **FR-004**: 기존 120개월 이상 시간 분리·50bp 비용·정확 지문·하드닝·대체 ETF 동등성·전 종목 시세·66% 표현 가능 목표·15%p/25%p 오차·현금·최소 주문·노출 한도 검증을 유지한다. 알파 미확정이며 2단 이상 승격하지 않는다.
- **FR-005**: 기존 승인 변경 검토·배포·정규장 자동 주문·미체결·계좌 대사·감사·중복 차단을 재사용한다. 예산 변경은 주문이나 재시도 권한이 아니다.
- **FR-006**: 생산 실패 가격을 재현하는 회귀 시험, 반례 시험, 전체 시험과 배포 후 주문 없는 점검을 통과해야 준비 완료로 보고한다. 실제 체결은 별도 관찰 결과로만 보고한다.
- **FR-007**: 자본 승인 자동화는 최신 main의 인계 전용 머지 부모와 변경 경로를 증명할 수 있는 Git 이력을 가져와야 한다. 이력 조회 실패는 체크아웃에서 차단하며 HANDOFF 사실 검사 자체를 완화하거나 생략하지 않는다.

### Key Entities

- 현재 계좌 순자산과 그 10% 내림 예산, 현재 승인액.
- 현재 전략의 체결 수·측정 범위·품질·식별 증거.
- 갱신 결정: 동일 단계·동일 진입일·새 승인액·새 실행 순번·근거.

## Success Criteria

- **SC-001**: 생산 재현 사례에서 $142의 차단과 $143의 한도 준수를 모두 재현한다.
- **SC-002**: 정상 첫 체결 전 사례는 과거 예산 때문에 차단되지 않고, 모든 반례는 특별 갱신하지 않는다.
- **SC-003**: 배포 후 현재 계좌 기준 승인과 주문 없는 재검증이 일치하고 신규 주문은 0건이다.
- **SC-004**: 다음 유효 자동 실행에서 실제 접수·체결·감사·대사까지 확인하기 전 전체 실거래 목표 완료를 선언하지 않는다.

## Assumptions

- 해외 ETP 신청은 오너가 완료를 확인했다. 중개사 주문 수락은 별도 검증 대상이다.
- 자본 비율 상향, 예산 수동 변경, 전략 교체, 오차 기준 완화, 가격 추격은 비목표다.
- 복구는 기존 10% 위임 안의 예산 정합이며 무조건 주문이나 수익을 보장하지 않는다.
- 되돌림은 검토된 코드 되돌림으로 특별 갱신만 제거한다. 감사·선점·체결 기록은 보존한다.
