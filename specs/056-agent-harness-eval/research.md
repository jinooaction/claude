# Research: Agent Harness Evaluation

## Decision: 첫 버전은 정적 하네스 프로브로 구현한다

**Rationale**: 현재 저장소에는 세션 훅, 동시 작업 방어, PR 품질 관문, SDD 규칙이 이미 있다.
가장 큰 빈틈은 이 장치들이 계속 존재하고 서로 연결되어 있는지 한 번에 확인하는 로컬 평가다.
정적 프로브는 네트워크, 비밀값, 브로커 접근 없이 빠르게 실행되어 모든 PR에서 부담 없이 쓸 수
있다.

**Alternatives considered**:

- 실제 Codex 세션을 여러 개 돌리는 동적 벤치마크: 장기적으로 유용하지만 비용, 비결정성,
  실행 시간 때문에 첫 관문으로 부적합하다.
- 문서만 보강: 행동 회귀를 자동으로 잡지 못한다.

## Decision: 평가 과제 묶음은 TOML로 저장한다

**Rationale**: Python 3.11 표준 라이브러리 `tomllib`로 읽을 수 있어 새 의존성이 필요 없다.
과제별 ID, 위험 등급, 기대 통제, 성공 기준을 구조화할 수 있다.

**Alternatives considered**:

- JSON: 주석과 사람이 읽는 긴 문장에 불편하다.
- YAML: 새 의존성이 필요하다.

## Decision: 등급 2 이상 PR 본문에 strict 하네스 평가 증거를 요구한다

**Rationale**: 운영 체계 변경은 다음 세션의 행동을 바꾸므로, 변경자가 하네스 전체가 아직
정상인지 확인했다는 근거가 PR 본문에 남아야 한다. PR 검사기는 실제 명령 실행을 완전히 증명할
수 없지만, 실행 명령과 결과를 요구해 감사 가능성을 만든다.

**Alternatives considered**:

- 모든 PR에서 strict 평가 강제: 등급 0~1의 작은 변경에는 비용이 과할 수 있다.
- GitHub Actions에서 항상 프로브 실행: 유용하지만 이번 작업의 핵심은 PR 본문 판단 기록과
  로컬 재현성이다. 이후 워크플로 추가는 별도 개선으로 남긴다.

## Decision: 거래 안전 경계는 건드리지 않는다

**Rationale**: 이 작업은 에이전트 작업 품질을 다루며 포지션 한도, 주문 제한, 배포 제한,
비밀값, 돈 경로를 바꾸지 않는다. 위험 등급은 2에 머문다.

**Alternatives considered**:

- 헌법에 하네스 평가 의무 추가: 헌법 변경은 등급 3이며 현재 목표를 넘는다.
