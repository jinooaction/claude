# Feature Specification: Account-Wide Micro GTAA Autonomous Rebalance

**Feature Branch**: `Codex/account-wide-micro-gtaa`  
**Created**: 2026-06-23  
**Status**: Draft  
**Input**: User description: "새 입금 없이 기존 보유와 현금을 모두 수익 관점에서 판단해, 적용 시점부터 실시간으로 지속 자율 운영되는 돈 버는 전략으로 완성한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 계좌 전체를 보고 판단한다 (Priority: P1)

운영자는 새 현금 입금 없이도 현재 KIS 해외계좌의 현금과 기존 보유 종목을 하나의 전략 자본으로 보고, 매도·보유·매수 중 무엇이 수익 관점에서 적절한지 자동 계획을 받고 싶다.

**Why this priority**: 기존 루프가 현금 부족만 보고 멈추면 실제 계좌의 자본을 사용하지 못한다. 돈 경로의 첫 성공은 계좌 전체를 정확히 읽고 위험 한도 안에서 실행 가능한 계획을 만드는 것이다.

**Independent Test**: 브로커 현금이 낮고 기존 보유 종목이 있는 스냅샷을 넣었을 때, 시스템이 대상 전략 종목, 청산 가능 기존 종목, 관리 제외 종목을 분리한 재배치 계획을 만든다.

**Acceptance Scenarios**:

1. **Given** KIS 계좌에 현금과 기존 보유 종목이 있고 목표 마이크로 GTAA 종목이 별도로 정의되어 있음, **When** 계좌 전체 계획을 생성함, **Then** 계획은 기존 보유 종목을 무시하지 않고 매도 후보 또는 보유 제외로 분류한다.
2. **Given** 기존 보유 종목이 전략 목표 종목이 아님, **When** 해당 종목이 청산 전용 허용 목록에 있음, **Then** 시스템은 해당 종목을 매도 후보로만 다루고 매수 후보로 다루지 않는다.
3. **Given** 기존 보유 종목이 청산 전용 허용 목록에도 없음, **When** 계획을 생성함, **Then** 시스템은 해당 종목을 주문하지 않고 관리 제외 사유를 기록한다.

---

### User Story 2 - 현금이 부족하면 매도부터 지속 실행한다 (Priority: P1)

운영자는 매수 현금이 부족한 상태에서도 시스템이 중단하지 않고, 먼저 청산 가능한 기존 보유를 안전하게 줄인 뒤 확인된 가용 현금 안에서 다음 매수를 실행하는 반복 루프를 원한다.

**Why this priority**: 현금 부족은 운영 중단 사유가 아니라 재배치 순서의 제약이다. 매도 체결 전 매수를 강행하면 브로커 거절과 감사 불일치가 반복되므로, 매도 우선과 현금 재확인이 필요하다.

**Independent Test**: 낮은 현금과 청산 가능 기존 보유가 있는 스냅샷에서 첫 실행은 매도만 제출하고, 후속 실행에서 브로커가 확인한 매수 가능 현금이 충분할 때만 매수를 제출하는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 목표 매수 금액이 현재 KIS 매수 가능 현금보다 크고 청산 가능 보유가 있음, **When** 실거래 루프가 실행됨, **Then** 시스템은 매도 주문만 제출하고 매수 주문은 다음 확인 주기로 미룬다.
2. **Given** 이전 실행의 매도가 체결되어 KIS 매수 가능 현금이 목표 매수와 완충금보다 큼, **When** 다음 루프가 실행됨, **Then** 시스템은 한도와 화이트리스트를 통과한 매수 주문만 제출한다.
3. **Given** 매도가 거절되었거나 체결 확인이 없음, **When** 같은 주기의 매수 단계가 평가됨, **Then** 시스템은 매수 주문을 제출하지 않고 거절 상태를 기록한다.

---

### User Story 3 - 실시간 지속 운영 증거를 남긴다 (Priority: P2)

운영자는 적용 이후 매 장중 실행 후보 시점마다 시스템이 무엇을 봤고, 왜 주문했거나 멈췄는지 다음 세션에서 재현할 수 있기를 원한다.

**Why this priority**: 이 기능은 단발성 수동 실행이 아니라 지속 자율 운영이다. 자동 루프가 살아 있는지, 안전장치가 왜 막았는지, 다음 실행이 무엇을 이어받아야 하는지 증거가 남아야 한다.

**Independent Test**: 매수 가능 현금 부족, 매도 전용 실행, 브로커 거절, 정상 매수 대기 상태 각각에서 사이드카와 알림이 동일한 결론을 보여 주는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 루프가 매도 전용으로 실행됨, **When** 실행이 끝남, **Then** 최신 사이드카에는 계좌 총액, 현금, 보유, 계획된 매도·매수, 실제 제출 결과, 다음 기대 단계가 기록된다.
2. **Given** KIS API가 포지션·현금·시세 중 하나를 반환하지 못함, **When** 루프가 실행됨, **Then** 시스템은 실패 폐쇄 상태로 끝내고 주문을 제출하지 않는다.
3. **Given** 브로커 거절이 반복됨, **When** 다음 루프가 시작됨, **Then** 시스템은 거절 사유와 반복 횟수를 기록하고 추가 주문을 보수적으로 제한한다.

---

### User Story 4 - 기존 돈 경로 안전장치를 유지한다 (Priority: P2)

운영자는 계좌 전체 재배치가 새 기능이어도, 기존 포지션 한도, 허용 종목, 감사 로그, 비밀값 분리, 외부 API 장애 대응, 장중 배포 금지, 단계적 전환 원칙을 깨지 않기를 원한다.

**Why this priority**: 더 공격적인 자본 사용은 안전 경계가 보존될 때만 의미가 있다. 기능 성공 기준은 수익 가능성뿐 아니라 잘못된 주문을 내지 않는 것이다.

**Independent Test**: 주문 경로가 기존 위험 게이트와 감사 기록을 우회하지 않으며, 청산 전용 종목이 매수 주문으로 나가지 않음을 테스트한다.

**Acceptance Scenarios**:

1. **Given** 계획에 청산 전용 종목이 포함됨, **When** 주문 제출 단계가 실행됨, **Then** 해당 종목은 매도 방향에서만 허용되고 매수 방향이면 실패 폐쇄된다.
2. **Given** 주문이 포지션 한도, 허용 종목, 장중 배포 제한, 비밀값 요구 중 하나를 만족하지 못함, **When** 루프가 실행됨, **Then** 시스템은 기존 안전장치의 실패를 유지하고 주문을 제출하지 않는다.

### Edge Cases

- 기존 보유 종목의 시세 조회가 실패하면 해당 종목 매도 금액을 추정하지 않고 전체 주문 제출을 실패 폐쇄한다.
- 청산 전용 종목이 목표 전략 종목으로도 잘못 설정되면 시스템은 설정 오류로 중단하고 매수 주문을 만들지 않는다.
- 브로커 포지션과 내부 원장 포지션이 다르면 실거래 계획은 브로커 스냅샷을 우선하되, 차이를 감사·사이드카에 남긴다.
- 매도 체결 후 같은 실행 안에서 매수 가능 현금이 즉시 증가하지 않으면 매수는 다음 실행으로 미룬다.
- 매수 가능 현금은 목표 매수 금액과 1% 완충금을 모두 충족해야 매수 단계가 열린다.
- 반복 실행이 같은 미체결 주문을 중복 제출할 가능성이 있으면 해당 종목·방향 주문을 보류하고 증거를 남긴다.
- 장 휴장, 미국 정규장 밖, KIS 인증 실패, 시세 지연, 환율·현금 조회 실패는 모두 주문 없는 실패 폐쇄로 끝난다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 실거래 재배치 계획을 만들기 전에 최신 KIS 해외계좌 포지션, 매수 가능 USD 현금, 계좌 평가액을 읽어야 한다.
- **FR-002**: 시스템은 브로커 포지션을 전략 목표 종목, 청산 전용 기존 종목, 관리 제외 종목으로 분류해야 한다.
- **FR-003**: 시스템은 청산 전용 기존 종목을 매도 후보로만 사용할 수 있으며, 어떤 경로에서도 해당 종목의 매수 주문을 제출하면 안 된다.
- **FR-004**: 시스템은 관리 제외 종목에 대해 자동 주문을 제출하지 않고 제외 사유를 기록해야 한다.
- **FR-005**: 시스템은 계좌 전체 포지션과 현금을 기준으로 목표 마이크로 GTAA 비중 대비 부족·초과 금액을 계산해야 한다.
- **FR-006**: 시스템은 같은 실행 주기에서 매도 주문을 매수 주문보다 먼저 평가하고 제출해야 한다.
- **FR-007**: 현재 매수 가능 현금이 계획 매수 금액과 1% 완충금을 충족하지 못하고 청산 전용 매도 후보가 있으면, 시스템은 해당 주기를 매도 전용 실행으로 제한해야 한다.
- **FR-008**: 매수 주문은 KIS가 확인한 매수 가능 현금이 계획 매수 금액과 1% 완충금을 충족할 때만 제출할 수 있다.
- **FR-009**: 모든 실주문은 기존 주문 라우터, 지정가 주문, 정규장 제한, 포지션 한도, 전역 노출 한도, 허용 종목 게이트를 통과해야 한다.
- **FR-010**: 시스템은 마이크로 GTAA 목표 종목 외 종목을 새로 매수하지 않아야 한다.
- **FR-011**: 시스템은 청산 전용 종목 목록과 목표 전략 종목 목록이 겹치면 설정 오류로 중단해야 한다.
- **FR-012**: 시스템은 외부 API, 시세, 현금, 포지션 조회 실패 시 주문을 제출하지 않고 실패 폐쇄해야 한다.
- **FR-013**: 시스템은 각 실행의 브로커 스냅샷, 계획, 제출 주문, 체결·거절 결과, 다음 기대 단계를 최신 사이드카에 기록해야 한다.
- **FR-014**: 시스템은 텔레그램 알림에 계좌 전체 모드, 매도 전용 여부, 제출·거절 수, 다음 실행 기대 상태를 포함해야 한다.
- **FR-015**: 시스템은 반복 실행 시 이미 제출되어 아직 확인되지 않은 같은 종목·방향 주문을 중복 제출하지 않도록 보수적으로 제한해야 한다.
- **FR-016**: 시스템은 기존 감사 로그와 일일 조정 흐름을 삭제하거나 우회하지 않아야 한다.
- **FR-017**: 시스템은 새 입금 없이 기존 보유의 매도 가능 금액과 확인된 현금만 사용해야 하며, 마진·공매도·레버리지·시장가 주문을 사용하면 안 된다.

### Key Entities *(include if feature involves data)*

- **Account Snapshot**: 실행 시점의 KIS 해외계좌 상태. USD 매수 가능 현금, 평가 총액, 보유 종목, 수량, 평균단가, 최신 시세, 브로커 조회 시각을 포함한다.
- **Holding Classification**: 각 보유 종목의 실행 역할. 전략 목표, 청산 전용, 관리 제외 중 하나이며, 청산 전용은 매도만 가능하다.
- **Account-Wide Rebalance Plan**: 계좌 전체 스냅샷과 목표 비중으로 만든 주문 후보 목록. 매도 후보, 매수 후보, 현금 부족 여부, 매도 전용 여부, 보류 사유를 포함한다.
- **Execution Cycle Evidence**: 지속 운영 증거. 실행 모드, 안전 게이트 결과, 제출 결과, 브로커 거절, 다음 기대 단계를 사이드카와 알림에 남긴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 낮은 현금과 청산 전용 기존 보유가 있는 테스트 스냅샷에서 첫 실거래 후보 실행은 매수 주문 0건, 청산 전용 매도 주문 1건 이상을 계획한다.
- **SC-002**: 청산 전용 종목이 매수 후보로 들어오는 설정 또는 코드 경로는 테스트에서 실패 폐쇄로 검출된다.
- **SC-003**: 매수 가능 현금이 계획 매수 금액과 1% 완충금을 충족하지 못하면 실주문 매수 제출 수는 항상 0건이다.
- **SC-004**: 매도 후보가 없는 상태에서 매수 가능 현금이 충분하면 기존 마이크로 GTAA 목표 종목에 한해서만 매수 주문이 제출된다.
- **SC-005**: 포지션·현금·시세 중 하나가 실패하는 테스트에서 실주문 제출 수는 0건이고 실패 사유가 사이드카에 남는다.
- **SC-006**: 동일 계좌 스냅샷을 연속 두 번 평가해도 미확인 주문 중복 제출이 발생하지 않는다.
- **SC-007**: 기존 전체 테스트와 린트가 통과하며, 포지션 한도·허용 종목·감사 로그·비밀값·장중 제한 관련 기존 검증이 약화되지 않는다.

## Assumptions

- 현재 적용 대상은 KIS 해외주식 마이크로 GTAA 라이브 카나리 계좌다.
- 새 입금은 사용하지 않는다. 새 자본 배정은 기존 `capital_usd` 한도 안에서만 해석한다.
- 현재 브로커 계좌에 확인된 기존 보유 종목은 초기 청산 전용 후보로 둘 수 있지만, 목표 전략 종목으로 승격하지 않는다.
- 매도 체결 대금은 KIS가 매수 가능 현금으로 확인하기 전까지 후속 매수 재원으로 간주하지 않는다.
- 지속 운영 주기는 기존 라이브 카나리 스케줄과 수동 실행 진입점을 사용하되, push 이벤트에서 실주문은 제출하지 않는다.
- 이 기능은 안전 경계를 완화하지 않는다. 목표는 같은 안전장치 안에서 계좌 전체 자본을 더 정확히 사용하는 것이다.
