# Feature Specification: Evolution Source Diversification

**Feature Branch**: `Codex/089-evolution-source-diversification`
**Created**: 2026-07-03
**Status**: Draft
**Input**: User description: "다음 후보를 목표 스킬과 SDD 기준으로 꼼꼼하게 완수한다. 최신 자율 작업 후보는 `candidate-evolution-source-diversification`이며, 정적 후보 템플릿 밖 증거 기반 후보 공간을 확장한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 닫힌 정적 후보 밖에서 새 후보 합성 (Priority: P1)

운영자는 자율 성장 루프의 정적 후보 9개가 learning ledger와 released-work에 의해 모두 닫힌 뒤에도, 루프가 "남은 후보 없음"으로 멈추지 않고 sidecar 증거 자체에서 새 실행 가능 후보를 합성하기를 원한다.

**Why this priority**: 스펙 088은 closed queue를 감지해 다음 거시 후보를 만들었지만, upstream evolution loop 자체는 여전히 고정 템플릿 후보만 생성한다. 이 상태가 유지되면 다음 후보가 다시 수동 템플릿 추가에 의존한다.

**Independent Test**: 정적 후보가 모두 released/rejected/evidence_dependent로 닫히고 operator review 후보가 없는 learning ledger를 입력했을 때, `scan_evolution` 결과에 새 후보 `candidate-source-diversification-sidecar-bottleneck`이 `new` 상태로 포함되면 검증된다.

**Acceptance Scenarios**:

1. **Given** 기존 정적 후보가 모두 닫혀 있음, **When** autonomous evolution loop가 실행됨, **Then** sidecar 신선도와 병목 신호에서 새 증거 기반 후보가 생성된다.
2. **Given** 기존 정적 후보 중 실행 가능한 후보가 있음, **When** autonomous evolution loop가 실행됨, **Then** 새 후보는 보조 후보로만 남거나 생성되지 않아 기존 실행 가능 후보를 가리지 않는다.

---

### User Story 2 - 반복 실패와 관찰 병목을 후보 입력으로 사용 (Priority: P2)

운영자는 promotion failure, learning ledger 반복 결정, pipeline liveness, capital-path observability issue 같은 운영 증거가 후보 생성 입력으로 쓰이기를 원한다.

**Why this priority**: 현재 실패와 보류 기록은 주로 기존 후보를 닫는 데 쓰이며, 왜 새 후보 공간을 넓혀야 하는지 직접 후보화하지 못한다.

**Independent Test**: learning ledger에 반복 rejected/evidence_dependent 항목이 있고 pipeline/capital sidecar에 관찰 병목 신호가 있으면, 생성 후보의 `problem_ko`, `evidence_refs`, `next_action_ko`에 해당 증거가 반영되면 검증된다.

**Acceptance Scenarios**:

1. **Given** 여러 후보가 promotion failure 또는 rejected ledger로 닫힘, **When** 후보 생성이 실행됨, **Then** 반복 실패 유형을 새 후보 이유에 포함한다.
2. **Given** 관찰 병목 또는 sidecar 신선도 이슈가 있음, **When** 후보 생성이 실행됨, **Then** 후보의 evidence refs가 해당 sidecar를 가리킨다.

---

### User Story 3 - 안전 경계를 보존하고 완료 마커를 남김 (Priority: P3)

운영자는 후보 공간 확장이 자율성을 키우더라도 돈 경로, 주문, 자본, whitelist/caps, live 전략, 비밀값, 헌법, 커널을 건드리지 않기를 원한다.

**Why this priority**: 더 거시적인 자율 성장은 운영 편의를 높여야 하지만 안전 경계나 실거래 권한을 넓히면 안 된다.

**Independent Test**: 변경 파일과 생성 후보가 risk grade 2 안에 있고 `completed_candidate_id: candidate-evolution-source-diversification` 계약을 released-work가 소비하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 새 후보가 생성됨, **When** 후보 payload를 확인함, **Then** risk grade는 2이고 safety impact는 비어 있다.
2. **Given** 스펙 tasks가 완료됨, **When** released-work probe가 실행됨, **Then** `candidate-evolution-source-diversification`이 released 후보로 기록된다.

### Edge Cases

- 기존 정적 후보 중 `new` 또는 `planned` 후보가 있으면 새 후보가 일반 후보를 가리지 않아야 한다.
- evidence sidecar가 누락되면 누락 자체를 안전하게 설명하되, 실거래 복구나 외부 서비스 비용을 자동 요구하지 않아야 한다.
- learning ledger가 malformed이면 기존 후보 생성은 보수적으로 유지하고, 새 후보 합성은 malformed 장부를 근거로 단정하지 않아야 한다.
- 새 후보는 읽기 전용 작업 패킷이며 주문, 브로커 API, 자본 배분, live 전략, whitelist/caps, 비밀값, 헌법, 커널, 외부 유료 서비스를 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST detect when the generated static autonomous evolution candidates have no safe `new` or `planned` work after learning ledger, released-work, and promotion failure application.
- **FR-002**: System MUST synthesize at least one new evidence-derived candidate outside the static template set when the static candidate set is closed.
- **FR-003**: System MUST base the synthesized candidate on existing read-only evidence: learning ledger decisions, promotion failure signals, pipeline liveness, released-work saturation, and capital-path observability.
- **FR-004**: System MUST NOT let synthesized candidates mask existing safe static candidates, operator review candidates, or safety-impact candidates when such candidates are still actionable.
- **FR-005**: System MUST assign synthesized candidates risk grade 2 and empty safety impact unless their title/problem/action text actually touches a safety surface.
- **FR-006**: System MUST keep the candidate deterministic for the same input evidence.
- **FR-007**: System MUST include evidence refs and Korean reason/action text that explain why the candidate was created.
- **FR-008**: System MUST publish a Speckit contract with `completed_candidate_id: candidate-evolution-source-diversification`.
- **FR-009**: System MUST verify focused unit behavior, probe behavior, released-work reproduction, full tests, lint, HANDOFF fact check, strict harness, and PR quality gate before merge.

### Key Entities *(include if feature involves data)*

- **Static Candidate Set**: Existing domain candidates generated by `evolution_loop.py`.
- **Closed Static Candidate Signal**: State where no generated static candidate remains safe and actionable after ledger and promotion failure application.
- **Evidence-Derived Candidate**: New deterministic candidate generated from sidecar and ledger signals rather than a fixed domain template.
- **Source Diversification Marker**: Speckit contract marker consumed by released-work for `candidate-evolution-source-diversification`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: With every static candidate closed by ledger entries, `scan_evolution` produces at least one `new` evidence-derived candidate outside the previous 9 static candidate IDs.
- **SC-002**: With existing safe static candidates still actionable, the synthesized candidate does not outrank or replace them.
- **SC-003**: The synthesized candidate carries evidence refs from at least two existing read-only evidence surfaces.
- **SC-004**: The synthesized candidate has risk grade 2, no safety impact, and no text that requests orders, capital changes, whitelist/caps expansion, live strategy replacement, secrets, paid services, constitution, or kernel edits.
- **SC-005**: `released_work_probe.py --repo-root .` includes `candidate-evolution-source-diversification` after tasks are checked complete and the explicit contract marker is present.
- **SC-006**: Focused tests, probe tests, full pytest, ruff, HANDOFF fact check, strict harness, and PR quality gate pass.

## Assumptions

- `evolution_loop.py` is the correct integration point because it owns the upstream candidate backlog used by downstream promotion and autonomous work execution loops.
- The first evidence-derived candidate should target candidate source diversification rather than strategy changes, because the current selected work is agent-ops and read-only.
- This change is risk grade 2 because it changes autonomous candidate generation and next-session behavior, but it does not change the money path or safety perimeter.
