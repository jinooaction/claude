# Feature Specification: 최초 관측 원문 누적 수집

**Feature Branch**: `codex/199-first-observed-filings`  
**Created**: 2026-09-29  
**Status**: Draft  
**Input**: 기존 한국투자 단타 프로그램 완성. 과거 사건 시각 자료의 빈틈을 지금부터 실제 관측 원문을 보존하는 방식으로 줄인다.

## User Scenarios & Testing

### User Story 1 - 실제 받아 본 원문을 보존한다 (Priority: P1)

운영자는 지정한 회사의 공시 목록과 공시 원문을 받은 사실과 시각을 재확인할 수 있다.
**Why this priority**: 지금 확보한 사본을 과거에 알고 있었다고 오인하는 문제를 막는다.
**Independent Test**: 실제 원문 한 건과 수신 기록을 검증하고 변조 사본을 거부한다.
**Acceptance Scenarios**:
1. **Given** 지정된 회사, **When** 원문 수신 성공, **Then** 원본·출처·확인 구간을 함께 보존한다.
2. **Given** 차단·시간 초과·잘린 응답, **When** 수집 종료, **Then** 실패를 기록하며 사건이 없었다고 판단하지 않는다.

### User Story 2 - 그때 확인한 버전만 조회한다 (Priority: P1)

운영자는 나중에 생긴 정정본과 실패가 과거의 관측 결과를 바꾸지 않았음을 확인한다.
**Why this priority**: 반복 관측을 성과 검증의 재현 가능한 입력으로 남긴다.
**Independent Test**: 두 버전·중간 실패를 추가한 뒤 첫 관측 당시 조회가 불변인지 검사한다.
**Acceptance Scenarios**:
1. **Given** 정정본 추가, **When** 과거 기준 조회, **Then** 그때 확인된 버전만 노출한다.
2. **Given** 기존 원본, **When** 같은 원문 재관측, **Then** 첫 관측 시각을 보존하고 새 관측도 추가한다.
3. **Given** 수집만 완료된 문서, **When** 연구 사건 조회, **Then** 검토된 실적 사건이나 매매 신호로 자동 승격하지 않는다.

### User Story 3 - 맥북 없이 관측을 누적한다 (Priority: P2)

운영자는 원격 실행 결과, 누락 범위, 마지막 성공을 확인하고 수집을 중단해도 기존 원문을 보존한다.
**Why this priority**: 사용자 기기 사용을 방해하지 않고 이후 자료 공백을 줄인다.
**Independent Test**: 원격 연속 실행 두 번으로 첫 기록 보존과 새 기록 추가를 확인한다.
**Acceptance Scenarios**:
1. **Given** 정상 원격 실행, **When** 다음 실행, **Then** 이전 원문과 관측을 삭제하지 않는다.
2. **Given** 요청 한도·장애·저장 충돌, **When** 한도 도달, **Then** 중단 이유와 미관측 범위를 남기고 제한 없이 재시도하지 않는다.

### Edge Cases

시계 역행, 빈 목록, 중복 접수번호, 정정 원문, 악성 문서 경로, 다른 회사 응답,
응답 크기 초과, 기존 원문 변조, 저장 도중 중단, 동시 발행, 비정상 외부 주소,
목록만 관측하고 원문은 실패한 경우, 수집 한도 때문에 남은 문서, 설정 식별정보 유출.

## Requirements

### Functional Requirements

- **FR-001**: 고정 회사 범위와 문서 종류, 한 실행의 요청·용량·시간 한도를 기록한다.
- **FR-002**: 성공 원문과 수신 시작/완료·검증 완료를 보존하고 그 이후에만 조회한다.
- **FR-003**: 원문·관측·실패 기록을 덮어쓰지 않으며 변경본을 별도 버전으로 보존한다.
- **FR-004**: 원문 변조·시계 역행·회사/문서 불일치를 거부한다. 오류를 성공이나 사건 없음으로 바꾸지 않는다.
- **FR-005**: 접수/게시 시각은 출처의 주장으로 분리한다. 임의 지연으로 과거 공개 시각을 만들지 않는다.
- **FR-006**: 수신 성공과 의미 검토 완료를 구분한다. 기존 사건 입력 도구로 연결할 때 원문과 출처를 제공하되 수집 시각을 의미 검토 시각으로 대체하지 않는다.
- **FR-007**: 원격 반복 관측은 이전 기록을 보존하며, 실패·누락·중단 이유와 최신 실행 상태를 노출한다.
- **FR-008**: 외부 요청 속도·제한 재시도·지수 지연·지속 장애 차단 및 재개 대기를 적용한다. 차단 우회는 하지 않는다.
- **FR-009**: 계좌 비밀값·실주문·자본·전략 승격·허용 종목·배포 제한을 변경하지 않는다. 연락 식별정보는 원문 보존물과 공개 로그에 기록하지 않는다.
- **FR-010**: 원격 실제 수집·재조회와 반례 자동 검사로 재현성을 검증한다. 맥북 화면과 무거운 로컬 계산은 사용하지 않는다.

### Key Entities

- 회사 범위: 회사 식별자, 허용 문서 종류와 관측 범위.
- 원문 버전: 출처와 원본 지문, 문서 식별자, 내용.
- 관측 영수증: 요청/수신/검증 구간, 원문 연결, 성공/실패/미시도 상태.
- 실행 기록: 코드·설정 식별, 관측/실패/남은 범위, 이전 기록 연결.

## Success Criteria

- **SC-001**: 실제 지정 회사의 목록과 공시 원문을 원격에서 수집하고 재조회할 수 있다.
- **SC-002**: 연속 실행 후 기존 원문·관측 기록 변경/삭제 0건, 새 관측 추적 가능.
- **SC-003**: 미래 버전·수신 실패·시계 역행 반례에서 잘못된 과거 노출 0건.
- **SC-004**: 실행 한도와 실패 범위가 관측 결과에 남고, 주문·자금 변경·비밀값 출력 0건.

## Assumptions

등급3 새 연구 입력 자동화로 전체 SDD를 적용한다. 새 외부 API의 요청 제한·차단·재시도
경계를 구현하므로 높은 등급으로 분류한다. 초기 검증 범위는 기존195에서 다룬
Microsoft 한 회사이며 회사 범위는 명시적으로 확장한다. 현재 회사/종목 명칭은 역사 연결의 증거가 아니다.
공시 본문 수집은 첨부 전체·예상 실적·실적 의미 검토 완료를 뜻하지 않는다.
정확한 최초 공개 시각·자료 전체성·당일 즉시성은 보장하지 않고 실제 관측만 기록한다.
이 기능은 기존195/196을 보완하며 대체하지 않는다. 실패 시 새 수집 실행을 중단하고
기존 원문·관측은 보존한다. 전체181의 통과 전략·60일 전진 관찰·실제 운영 증거는 여전히 필요하다.
