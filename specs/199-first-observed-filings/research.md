# 설계 판단

## 관측 시각
결정: 요청 시작/수신 완료/구조 검증 완료를 분리하고 최종 완료 이후 조회만 허용한다.
이유: SEC 접수·보통 처리 지연은 최초 관측이나 지연 상한이 아니다.
대안: 접수+고정지연, 현재 파일 시각의 과거 소급은195에서 기각되어 반복하지 않는다.
공식 근거: https://www.sec.gov/search-filings/edgar-application-programming-interfaces
2026-09-28 UTC 원문 확인. 공개 submissions 조회는 인증/API키 없음.

## 저장/통신 재사용
결정: 기존 httpx와 GitHub 연구 실행을 재사용하되 불변 blob/관측 저장은 별도로 둔다.
이유: public_data.fetch_text는 문자열만 반환하며 기존 발행은 orphan+force 최신 교체다.
대안: 기존 경로를 고치면 거시자료 소비자까지 영향이 커져 제외한다.
공식 속도 안내: https://www.sec.gov/about/developer-resources (전체10요청/초 이하).
새 경로는1초 간격·단일 동시 수집·냉각으로 더 적게 요청한다.

## 범위와 의미 검토
결정: 기존195의 Microsoft부터 목록과8-K 본문을 보존한다. 원문은 읽기 전용 연구 입력이다.
이유: 당장 확보하지 못한 과거 문서를 임의 보충하지 않고 이후 관측부터 재현 가능하게 한다.
대안: 전체기업 벌크·첨부 자동 해석·자동 실적 신호는 확인되지 않은 의미/범위를 늘려 이번에 포함하지 않는다.
새 문서·분석 필요성은 전체목표에 남긴다. 이 기능만으로 수익성·전진60일 완료를 선언하지 않는다.

## 장애와 롤백
결정: 원문/관측은 유지, 실패는 별도 실행 기록. 재시작은 새run으로 이루어진다.
이유: 실패한 수집을 무공시로 해석하거나 이미 관측한 기록을 없애면 미래 검증이 왜곡된다.
대안: 수집 중단 시 자료 삭제, 실패 시 성공으로 끝내기, 차단 우회는 제외한다.
스킬 계획 단계의 독립 읽기 전용 검토를 진행하며 발견된 반례는 구현 전에 계약에 반영한다.

## 독립 검토 반영
filing_storage_review가 spec과195실제구현을 읽어8개 반례를 제시했다.
완료manifest 경계, 최종 완료시각과 관측시각의 분리, 실행 간 시계 역행,
기존파일 변경/삭제 검사, 발행 전90일 복구artifact, 부분관측 범위,
195현재검토시각 유지와 문서ID 충돌, 의미검토 중복구현 금지를 설계/자료계약에 반영했다.
