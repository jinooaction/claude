# Feature Specification: 장 마감 전 단일 후보 검증

**Feature Branch**: `codex/198-late-session-research`

**Created**: 2026-09-28

**Status**: 구현·표적 검사 완료 — 실자료 성과·원격 전체 검증 미완료

**Input**: 기존 한국투자 계좌용 단타 실사용 프로그램을 완성하며, 자료 막힘에는 다른 검증 가능한 전략을 찾는다. 사용자의 맥북 화면 조작과 무거운 로컬 작업은 하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 성과를 보기 전에 후보를 고정한다 (Priority: P1)

운영자는 기업 공시의 과거 관측 시각이나 법인 변경 자료 없이 시험할 수 있는
장 마감 전 매수 후보 하나를 얻는다. 이전 실패는 그대로 남긴다.

**Why this priority**: 자료 막힘을 우회하면서 결과에 맞춘 규칙 변경을 막는다.

**Independent Test**: 정상장·조기 폐장·직전 거래일 누락·동일 가격·미래 가격 변경
사례에서 신호 시각과 판단을 독립적으로 확인한다.

**Acceptance Scenarios**:

1. **Given** 직전 거래일 종가와 당일 첫 30분 및 종료 30분 전 가격이 확인됨,
   **When** 두 가격 모두 직전 종가보다 높음, **Then** 종료 30분 전에 단 한 번 매수 신호를 만든다.
2. **Given** 어느 하나가 같거나 낮음 또는 필수 가격이 없음, **When** 판단함,
   **Then** 매수하지 않으며 다른 날 가격으로 대체하지 않는다.
3. **Given** 조기 폐장일, **When** 판단함, **Then** 실제 정규장 종료 기준으로 시각을 당긴다.

### User Story 2 - 비용과 미체결을 포함해 탈락 여부를 판단한다 (Priority: P2)

운영자는 기존 개발 자료에서 두 비용 조건을 모두 견디는지 확인한다.

**Why this priority**: 신호가 있어도 비용을 내고 남는 이익이 없으면 실사용 후보가 아니다.

**Independent Test**: 체결되지 않은 매수, 일부 청산, 마지막 봉 유동성 부족을
포함하는 자료로 모든 시도와 남은 수량이 보고되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 고정 개발 자료, **When** 검증함, **Then** 기본·스트레스 비용 각각의
   순수익, 청산 거래 수, 잔여 수량을 제시한다.
2. **Given** 어느 비용에서든 순수익이 0 이하이거나 기본 청산 거래 200건 미만 또는
   잔여 수량이 존재함, **When** 판정함, **Then** 후보를 탈락시키고 실패 기록을 남긴다.
3. **Given** 개발 기준을 통과함, **When** 결과를 제시함, **Then** 독립 확인이 필요하다고
   표시하며 실주문 가능으로 바꾸지 않는다.

### User Story 3 - 다른 세션에서도 결과를 재현한다 (Priority: P3)

운영자는 계약·코드·자료·거래 장부와 판정의 연결을 확인할 수 있다.

**Why this priority**: 녹색 검사 표시만으로 실사용이 완성되었다고 오인하지 않는다.

**Independent Test**: 같은 입력으로 재계산하면 같은 결과가 나오고, 계약·자료·장부·판정을
변조하면 거부한다. 지정 외 가격 자료는 읽기 전에 거부한다.

**Acceptance Scenarios**:

1. **Given** 보존된 결과, **When** 원자료로 재계산함, **Then** 장부와 판정 전체가 일치한다.
2. **Given** 이미 존재하는 출력 또는 최종 확인 구간 입력, **When** 실행함,
   **Then** 덮어쓰거나 가격을 읽지 않고 거부한다.

### Edge Cases

- 휴일 직후는 실제 직전 거래일을 사용한다. 첫 개발일은 직전 가격이 없으므로 거래하지 않는다.
- 일광 절약 시간 전환과 조기 폐장에도 현지 시각 대신 거래소 달력의 실제 경계를 따른다.
- 장 종료 청산 실패는 거래 삭제나 가상 종가 청산으로 숨기지 않는다.
- 체결 봉 전체 거래량은 사후 유동성 가정이며 신호에 사용할 수 없다.
- 당일 미래 가격이나 종료 뒤 자료가 바뀌어도 이전 신호는 바뀌지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: SPY·QQQ·IWM·TLT·GLD, 기존 개발 1,645거래일(2013-08-23~2020-03-06),
  후보 한 개를 성과 확인 전에 고정한다. 기존 최소 31회 시도에 이번 한 회를 추가한다.
- **FR-002**: 완료된 5분봉만 사용한다. 첫 30분 마지막 종가와 종료 30분 전 마지막
  종가가 모두 직전 거래일 마지막 종가보다 높을 때만 매수 신호를 만든다.
- **FR-003**: 신호 봉 다음 봉 시가를 매수 기준으로 한다. 정상장 신호 완료·다음 봉 시작은
  모두 15:30이며, 마지막 5분봉 시작 15:55에 청산을 시도한다. 이는 종가 경매가 아니다.
- **FR-004**: 종목당 하루 매수 시도는 최대 한 번이다. 미체결도 시도로 센다.
  기존 정수 수량·현금·노출 한도·거래량 참여 조건을 유지한다.
- **FR-005**: 기본 편도 31bp(0.31%), 스트레스 40bp(0.40%) 및 기존 비용 구성을 유지한다.
  개발 통과 조건은 양쪽 순수익 양수, 기본 청산 거래 최소 200건, 양쪽 미청산 수량 0이다.
- **FR-006**: 최종 495거래일(2020-03-19~2022-03-04)은 이번에 열지 않는다.
  통과하더라도 기존 177의 독립 확인·다중 비교 및 181의 전진 관찰·체결 증거가 필요하다.
- **FR-007**: 새 결과만 생성하며 계약·코드·자료·장부의 지문과 원자료 재계산 검증을 제공한다.
- **FR-008**: 실제 주문·자금 배정·운영 전략 교체·비밀값 접근은 수행하지 않는다.
  실거래 적격 여부는 항상 거짓, 배정 자본과 제출 주문은 0이다.
- **FR-009**: 사용자 화면을 조작하지 않는다. 무거운 전체 검증은 서버 또는 CI에서 수행한다.
- **FR-010**: 조정 가격의 실제 체결 동등성 미확인, 봉 전체 거래량 가정, 선행 연구와 최종
  확인 구간의 일부 중복, 이전 개발 구간 반복 사용을 결과의 한계로 표시한다.
- **FR-011**: 전체 검증을 계좌 비밀값과 배포 권한 없는 원격 환경에서 수행한다.
  검사 대상 코드 버전과 실제 종료 결과를 남기며, 검사 성공을 전략 수익성으로 해석하지 않는다.

### Key Entities

- **후보 계약**: 대상·기간·시각·판정·비용·누적 시도 수를 성과 확인 전에 고정한 기록.
- **거래 시도 장부**: 신호·매수·청산·부분 체결·미체결 수량과 적용 비용.
- **개발 판정**: 두 비용 결과, 탈락 사유, 재현 지문, 후속 증거 필요 여부.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 고정 후보 한 개를 두 비용 조건으로 평가하고 모든 거래 시도와 잔여 수량을 추적한다.
- **SC-002**: 독립 재계산의 결과와 장부가 모두 일치하며 변조 및 다른 입력은 거부한다.
- **SC-003**: 최종 확인 가격 자료 접근, 실제 주문, 자금 배정, 화면 조작은 각각 0건이다.
- **SC-004**: 통과 또는 탈락 이유가 재현 가능하게 남는다. 연구 도구 완성과 실사용 프로그램
  완성을 구분하며, 181의 미완료 항목을 근거 없이 완료 처리하지 않는다.

## Assumptions

- 연구 후보의 수익성을 약속하지 않는다. 실패하면 이 후보를 보존하고 다음 근거를 찾는다.
- 기존 다섯 ETF 가격 자료와 비용·한도 계약을 재사용한다. 194의 DD·UTX 자료를 사후 삭제하지 않는다.
- 새 기능이므로 전체 명세 절차를 따른다. 위험 등급은 2(연구 기능과 운영 명세 포인터 변경)다.
- 기존 기능과 안전장치를 제거하지 않는다. 되돌림은 새 연구 명령 사용 중단과 변경 커밋 되돌림이며,
  이미 생성한 연구 증거와 실패 기록은 보존한다.
