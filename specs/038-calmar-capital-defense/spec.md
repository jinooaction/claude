# 스펙 038 — 칼마 비율 (자본 방어 측정) in forward-verdict

## 문제 (왜 샤프만으론 부족한가)

스펙 035 forward-verdict 는 **샤프**(변동성 대비 수익)로 엣지를 판정한다. 그런데 스펙 036 의
추세 필터가 더하는 가치는 *변동성*이 아니라 **드로다운(최대낙폭) 방어**다 — 폭락 전·중에
현금으로 빠져 자본을 지킨다. 추세추종은 raw 수익이 단순 보유보다 낮아도 *낙폭이 훨씬 작아*
한 사이클의 위험조정 성과가 낫다. 샤프만 보면 이 자본 방어가 잘 안 드러난다.

운영자 원칙: **"돈을 못 벌면(잃으면) 이 고도화는 의미 없다."** 돈을 *잃지 않는* 능력(낙폭
방어)을 직접 재는 지표가 필요하다 — 그게 **칼마 비율(연환산수익률 / 최대낙폭)**이다.

## 목표

forward-verdict 에 칼마 비율을 일급 지표로 추가한다. 전략·벤치마크 각각의 칼마와 "전략이
벤치마크보다 칼마가 높은가(드로다운 방어 우위)"를 산출·보고한다.

## 한 일

- `calmar_ratio(total_return_pct, max_drawdown_pct, n_obs)` — 연환산수익률(CAGR%)/최대낙폭(%).
  낙폭 0(방어 완벽/무거래)·전손·기간 0 이면 None(정의 불가, 정직히).
- `EdgeVerdict` 에 `strategy_calmar`·`benchmark_calmar`·`beats_benchmark_calmar` 추가
  (schema 1.1). JSON·text 출력·판정 사유에 반영.
- **게이트는 약화하지 않는다**: EDGE_CONFIRMED 판정은 통계적으로 엄격한 샤프+PSR+DSR 기준을
  유지한다. 칼마는 *보고*만 해 운영자가 드로다운 방어를 직접 보게 한다(특히 추세 필터가
  샤프-엣지는 못 넘어도 칼마 우위가 있으면 사유에 명시).

## 안전 경계

- **Kernel 터치 0건.** 순수 측정 함수 추가 + dataclass 필드. 주문 경로·게이트 무변경.
- **돈 0 이동.** 측정/분석 전용. 페이퍼·라이브(`--mode live`) 양쪽 트랙에 똑같이 적용된다 —
  실거래 캐너리의 자본 방어도 같은 잣대로 잰다.

## 합격 기준 (SC)

- **SC-C01** 칼마 = CAGR/낙폭, 낙폭 작을수록 칼마 큼(단위 테스트).
- **SC-C02** 낙폭 0·전손·None 입력 → None(정의 불가 정직 처리).
- **SC-C03** 판정 JSON(schema 1.1)·text 에 전략·벤치 칼마 + 칼마 우위 플래그 포함.
- **SC-C04** 게이트 판정 로직 불변(샤프+PSR+DSR) — 칼마는 보고 전용. 전체 테스트·린트 통과.
