# Feature Specification: Parallel Regime Edge Challenger

**Feature Branch**: `codex/171-parallel-regime-edge-challenger`  
**Created**: 2026-08-27  
**Status**: Preregistered  
**Input**: User description: "다음 우선순위를 진행하고, 수많은 전략이 모두 탈락하는 원인이 전략인지 시스템 오류인지 함께 확인한다."

## Problem Definition

### Request

현재 자동 매매 시스템이 유망 전략을 지나치게 거르는지, 아니면 최근에도 재현되는 수익 엣지가
실제로 부족한지 분리해 확인한다. 동시에 최신 자동 점검이 KIS 토큰을 불필요하게 재발급하다
실패하는 운영 결함을 고치고, 기존 최우수 추세 전략과 공정하게 비교할 저회전 국면 대응 전략군을
사전등록한 뒤 시간 분리 백테스트를 수행한다.

### Root Cause

1. 현재 최우수 `globalfixed-ensemble-3-6-9-12`는 1971년 이후 장기 보유 구간에서는 양호했지만,
   최근 고정 5년 비교에서 기준 전략보다 샤프 비율이 높은 구간이 3개 중 0개였다. 장기 성과와
   현재 엣지가 서로 다른 질문인데 하나의 합격/불합격처럼 보였다.
2. 기존 전략 탐색은 752개 원시 조합을 17개 경제적 전략군으로 재분류했고, 모의실험으로 보정한
   `holdout PSR >= 0.95`, `family PBO <= 0.25` 관문은 16·64개 후보군 모두에서 거짓 합격 1% 이하와
   연 샤프 0.60 신호 탐지 80% 이상을 보였다. 따라서 기준 자체가 전면 고장났다는 증거는 없다.
3. `execution_proxy_parity()`는 바 데이터베이스를 임시 폴더에 만들면서 토큰 캐시도 같은 임시
   폴더로 암묵 결정한다. 첫 수정은 새 `--token-cache` 옵션을 helper에서 즉시 사용했지만 장중
   배포 연기로 CLI는 구버전, helper만 신버전이 되어 `No such option`으로 다시 실패했다. 즉
   장기 캐시 재사용뿐 아니라 helper와 패키지의 한 버전 배포 시차도 견뎌야 한다.
4. 기존 추세 전략은 상관 구조가 악화되고 주식·채권이 함께 약한 국면을 별도로 다루지 않는다.
   이는 기존 신호를 무한 확장하지 않고 독립적으로 검증할 수 있는 좁고 설명 가능한 후보군이다.
5. 병합 후 주문 없는 자동 판정에서 자본값 `0`이 비어 있지 않다는 이유만으로 라이브 전략
   성과 조회가 호출돼 `capital must be positive` 오류를 남겼다. 단 0에서는 해당 성과가
   의사결정 입력이 아니므로, 양수 자본일 때만 조회해야 한다.
6. 양수 조건 보정 후 첫 생산 재실행은 두 수명주기 결함을 드러냈다. 건너뛴 성과 조회의
   stderr 파일이 없어 마지막 출력 명령이 실패했고, 동등성 임시 DB의 `RETURN` 트랩을
   해제하지 않아 바깥 `main` 함수가 끝날 때 사라진 지역변수를 다시 참조했다.

### Non-goals

- 현재 통계 관문을 결과에 맞춰 낮추거나 이미 실패한 전략을 소급 합격시키지 않는다.
- 16개 사전등록 조합 밖의 파라미터를 결과를 본 뒤 추가하지 않는다.
- 실거래 전략, 라이브 설정, 자본 사다리, 종목 허용 목록, 주문 상한을 바꾸지 않는다.
- 실제 주문, 모의 주문 제출, 자본 배분, 유료 데이터 구독을 발생시키지 않는다.
- 이번 역사 백테스트만으로 `Backtest -> Canary -> Full` 단계를 건너뛰지 않는다.

## User Scenarios & Testing

### User Story 1 - Reuse the Shared KIS Token Cache (Priority: P1)

운영자는 임시 바 저장소를 쓰는 읽기 전용 동등성 점검도 운영 데이터의 유효 토큰 캐시를 재사용해
불필요한 토큰 발급과 403 실패를 피한다.

**Independent Test**: 새 CLI는 명시적 토큰 캐시를 지원하고, 관찰 스크립트는 무작위 임시 DB를
`data/` 바로 아래에 만들어 구버전 CLI도 `data/kis_token.json`을 사용한다. 캐시가 없거나 만료된
뒤 갱신도 실패하면 증거를 통과시키지 않는다.

### User Story 2 - Compare a Frozen Regime Family Fairly (Priority: P1)

운영자는 기존 3·6·9·12개월 추세 앙상블과 국면 대응 후보 16개를 같은 자료, 같은 비용, 같은
시점 정보만으로 비교한다.

**Independent Test**: 결과 계약의 16개 식별자와 지문이 사전등록 JSON과 일치하고, 2007년 1월
한 달을 비운 뒤 2007년 2월 이후 보유 구간에서 개발기간 승자 하나만 재선택 없이 평가한다.

### User Story 3 - Distinguish Gate Failure from System Failure (Priority: P1)

운영자는 결과가 `NO_RESEARCH_EDGE`여도 어느 관문에서 왜 떨어졌는지, 비용 전후와 최근 구간에서
어떤 차이가 났는지 확인할 수 있다.

**Independent Test**: 보고서가 가족 PBO, 보유 PSR, 수익률·샤프·낙폭, 최근 3구간 승수, 최근
60개월 샤프, 회전율, 비용 스트레스와 모든 개별 불리언을 함께 출력한다.

## Requirements

> **위험 등급 4**: 첫 자본 후보에 연결될 수 있는 전략 증거와 운영 실행 준비성에 닿는다. 단,
> 이번 기능은 연구 보고서까지만 만들며 실제 주문과 승격은 명시적으로 금지한다.

### Functional Requirements

- **FR-001**: `backfill-bars`는 선택적 `--token-cache` 경로를 받아야 하며, 생략 시 기존 DB 인접 캐시를 사용해야 한다.
- **FR-002**: 인스턴스 대체 ETF 동등성 점검은 `data/` 바로 아래의 무작위 임시 DB를 사용해 구·신 CLI 모두 `data/kis_token.json`을 재사용해야 한다.
- **FR-003**: 토큰 또는 바 수집 실패는 계속 실패 닫힘으로 처리하고 이전 동등성 결과를 재사용하지 않아야 한다.
- **FR-004**: 비교 기준은 `globalfixed-ensemble-3-6-9-12`의 3·6·9·12개월 월말 추세 비중이어야 한다.
- **FR-005**: 후보군은 상관 창 `{12,24}`개월, 상관 임계값 `{0.0,0.2}`, 공동 약세 창 `{3,6}`개월, 방어 행동 `{cash,gold}`의 정확히 16개 조합이어야 한다.
- **FR-006**: 모든 t월 비중은 t-1월 말까지의 수준·수익률만 사용해야 한다.
- **FR-007**: 주식·채권 상관이 임계값 이상이고 두 자산 누적 수익률이 모두 0 이하일 때만 국면 방어가 작동해야 한다.
- **FR-008**: `cash` 행동은 주식·채권 비중을 현금으로, `gold` 행동은 같은 약세 창의 금 모멘텀이 양수일 때만 금으로 옮기고 그렇지 않으면 현금으로 옮겨야 한다.
- **FR-009**: 주식·채권·금·현금 비중 합은 항상 1이고 공매도·레버리지는 없어야 한다.
- **FR-010**: 개발기간은 공동 표본 시작부터 2006-12까지, 엠바고는 2007-01, 최종 보유기간은 2007-02 이후여야 한다.
- **FR-011**: 개발 승자는 개발 샤프, 개발 CAGR, 낮은 최대낙폭, 후보 ID 순으로 한 번만 선택해야 한다.
- **FR-012**: 후보와 기준 모두 연 50bp 고정 마찰비용과 편도 회전율 10bp를 같은 방식으로 차감해야 한다.
- **FR-013**: 편도 회전율 25bp와 50bp 결과는 진단으로 함께 표시하되 주 관문을 소급 변경하지 않아야 한다.
- **FR-014**: 가족 PBO는 개발기간 8개 시간 구간의 16개 후보 행렬로 계산하고 0.25 이하여야 한다.
- **FR-015**: 선택 후보의 최종 보유기간 기준 대비 능동수익 PSR은 0.95 이상이어야 한다.
- **FR-016**: 주 비용 기준 후보 CAGR·샤프는 기준보다 높고 최대낙폭은 기준 이하여야 한다.
- **FR-017**: 최종 보유기간 최근 3개 동등 구간 중 후보 샤프가 기준보다 높은 구간이 2개 이상이어야 한다.
- **FR-018**: 최근 60개월 후보 샤프는 기준보다 높고 연 편도 회전율은 4.0배 이하여야 한다.
- **FR-019**: DSR과 원시 다중비교 보정 값은 진단으로 남기되 합격 차단 기준으로 사용하지 않아야 한다.
- **FR-020**: 새 전략군을 포함한 연구 가족 수는 18, 프로그램 거짓 합격 예산 상한은 `18 * 0.01 = 0.18 <= 0.20`으로 기록해야 한다.
- **FR-021**: 결과가 모든 관문을 통과해도 `promotion_allowed=false`, `orders_submitted=0`, `capital_changed=false`여야 한다.
- **FR-022**: 자율 작업 완료 식별자는 `candidate-parallel-edge-challenger-0520a80c0525`여야 한다.
- **FR-023**: 자본 사다리 자동 판정은 현재 자본이 숫자이며 0보다 클 때만 라이브 전략 성과를 조회하고, 0·음수·비숫자 값에서는 빈 증거로 안전하게 건너뛰어야 한다.
- **FR-024**: 건너뛴 라이브 전략 성과의 JSON과 stderr 파일을 모두 결정론적으로 만들어 출력 단계가 성공해야 한다.
- **FR-025**: 동등성 임시 DB 정리 트랩은 함수의 모든 성공 경로에서 파일을 지운 뒤 해제돼 바깥 함수 종료 시 지역변수를 다시 참조하지 않아야 한다.

## Success Criteria

- **SC-001**: 집중 테스트가 임시 DB와 공유 토큰 캐시의 분리를 재현하고 회귀를 막는다.
- **SC-002**: 사전등록 계약과 생산 결과의 가족 크기, 후보 ID, 지문, 기간, 비용, 임계값이 정확히 일치한다.
- **SC-003**: 같은 데이터로 다시 실행하면 같은 선택 후보와 소수점 여섯 자리 결과가 나온다.
- **SC-004**: `RESEARCH_EDGE`는 FR-014~FR-018을 모두 만족할 때만 가능하고, 하나라도 실패하면 `NO_RESEARCH_EDGE`다.
- **SC-005**: 양성·음성·시간순서·비용 증가 통제가 보고되어 계산 방향 오류를 탐지한다.
- **SC-006**: 전체 pytest, Ruff, 엄격 하네스, HANDOFF 사실, PR 품질 관문과 무주문 운영 확인이 통과한다.
- **SC-007**: 단 0 생산 재실행 로그에 `capital must be positive`가 없고 판정·자본·주문은 변하지 않는다.
- **SC-008**: 생산 재실행에서 동등성 JSON 3/3 통과 후 `unbound variable` 없이 자본 결정과 sidecar 발행까지 완료한다.

## Assumptions

- 월별 실질 총수익 자료와 금 가격 자료는 기존 저장소의 공개 데이터 어댑터를 재사용한다.
- 상관 국면은 장기 추세의 대체물이 아니라 주식과 채권이 동시에 약해지는 드문 구간의 위험 축소 덮개다.
- 합격은 미래 수익 보장이 아니라 다음 종이거래 관찰 단계로 갈 통계적 근거만 뜻한다.
