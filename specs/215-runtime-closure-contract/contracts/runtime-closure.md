# Runtime closure contract — 설계용, 실행 API 아님

## 폐쇄형 연결 범위
후속 구현은 schema/scope와 정확 code_commit/tree/source_identity, lock 지문,
원래 install input 지문·출처와 신뢰 근거, image manifest/config/layer/platform 지문,
actual unpack root·base runtime·startup config·host/mount/hook·관측 구간 연결을 모두 선언한다.
알 수 없는 필드·누락·중복·현재 대상과 다른 세대·다른 digest·다른 platform은 거절한다.
실제 값이 아직 없는 입력은 null과 미관측 사유로 남기며 예시 digest·시각·서명을 실제로 쓰지 않는다.
이번 문서는 schema 구현/서명 형식/새 키 경로/권한 API를 만들지 않는다.

## 소스와 설치 원본
후보 소스는 정확 detached/clean Git 저장소와 검토된 모듈 ROOT를 보존한다.
저장소 경로·src 위치를 바꾸어 기존 ROOT/HEAD 검증을 우회하거나 시스템 Git 설정을 대신 읽게 만들지 않는다.
이미지 빌더의 임의 최신 tag·유동 패키지 인덱스는 원래 입력 봉인이 아니다.
실제 wheel/패키지·기반 이미지의 입력 바이트 지문과 lock→전이 설치물 연결을 별도 원래 증거로 요구한다.
선언자 신뢰는 digest와 별도 문제다. 당사자 자신이 즉석 생성한 기대 목록을 독립 인증으로 삼지 않는다.
신뢰 주체·검토 지문·기존 서명 경계와의 연결은 후속 등급3 명세에서 고정한다.

## 기동·배포 독립성
main /opt/auto-invest와 후보의 고정 root를 겹치게 두지 않는다. main 자동배포는 계속 유지한다.
허용된 외부 쓰기 영역은 상태/추가전용 장부·기존 토큰 캐시 목적과 분리하며 소스/Python/설치파일을 덮지 않아야 한다.
실제 장부 경로/세대·권한·키는 이 계약만으로 새로 만들거나 복사하지 않는다.
root 읽기 전용만으로 외부 bind mount·호스트 배포 프로세스·namespace 상속을 차단했다고 인정하지 않는다.
검증 뒤 경로 교체·mount 추가·실행기 교체/설정 변경·native loader 바깥 경로는 연결 부재/변경으로 거절한다.
단순 pid/mtime/최신hash/설치 목록 일치만으로 비교와 실제 기동 사이 불변을 단정하지 않는다.
namespace/파일시스템 경계는 host 커널 및 관리자에 대한 무조건적 적대적 보호를 뜻하지 않는다.

## 기존 관문과의 관계
환경 증거는 기존 정확 등록·HMAC·독립 연구 재계산·실제 수집 증명·90초/60세션을 대체하지 않는다.
기존 verify_registration의 REGISTRATION_IDENTITY_CHANGED를 그대로 보존한다.
문서만 변경한 커밋의 자동 예외·등록 변환·재서명·관찰 시작 초기화는 없다.
가격 성과 전에 운용/제공자/당시 관측/체결/현금·최소36 선행시도·495미개봉을 고정한다.
실제 통과 전략/독립 확인/동일 후보60세션/생산 체결·청산·대사 없이 실주문·자금·전체181 완료를 선언하지 않는다.

## Failure / 되돌림
관측 실패·원본 부재·다른 플랫폼·환경 지원 미확인 시 미평가로 남기고 활성화를 진행하지 않는다.
실행 중 변경 증거가 있으면 해당 구간을 새로 유효하다고 재서명하지 않는다. 기존 장부·실패 원본은 보존한다.
기동·폐기 구현 및 기존 단계와의 실패 처리는 후속 등급3 명세의 완료 대상이다.
이번215를 되돌리면 설계/인계 포인터만 되돌아가며 기존 코드·등록·정기 진단·자동배포는 유지된다.
