# 기능 명세: 모바일 자금·전략 운영판

**기능 브랜치**: `codex/183-mobile-capital-strategy`  
**작성일**: 2026-09-08  
**상태**: 구현 승인  
**입력**: 운영자가 기존 읽기 전용 Flutter 앱에 자금 현황과 전략 현황을 구체화한 설계대로 구현하라고 요청함.

## 문제 정의

현재 모바일 앱은 시스템과 자동화의 생존 상태를 보여주지만, 서로 뜻이 다른 총계좌 자산,
운용 한도, 준비 예산, 실제 투자금과 손익을 구분하지 않는다. 활성 전략도 이름, 역할,
증거 진행도, 최근 실행 결과와 차단 사유를 한 화면에서 확인할 수 없다. 상태 자료는 자동
발행되지만 핵심 돈·전략 원본보다 늦게 갱신될 수 있고, 묶음 생성 시각이 오래된 개별 원천을
신선하게 보이게 할 수 있다.

운영자는 휴대폰에서 돈의 의미와 전략의 실제 단계를 몇 초 안에 구분해야 한다. 확인되지 않은
계좌 값은 추측하지 않고, 기존 읽기 전용·비밀값 분리·실거래 안전 경계를 그대로 유지한다.

## 사용자 시나리오 및 시험 *(필수)*

### 사용자 이야기 1 - 자금 상태를 오해 없이 확인 (우선순위: P1)

운영자는 자금 화면에서 총계좌 자산, 전략 준비 예산, 현재 실거래 운용 한도, 실제 투자금,
손익과 위험 한도를 서로 다른 개념으로 확인한다. 검증되지 않은 총계좌 자산이나 현금은 숫자
0이 아니라 확인 대기로 표시된다.

**이 우선순위인 이유**: 서로 다른 금액을 하나의 자산으로 오해하면 실제 돈에 관한 잘못된
판단으로 이어질 수 있다.

**독립 시험**: 검증된 값, 부분 확인 값, 전부 확인 불가인 세 자료를 각각 열고 5초 안에
운용 한도와 실제 투자금, 미확인 계좌 값을 구분할 수 있는지 확인한다.

**인수 시나리오**:

1. **Given** 준비 예산 600달러와 기존 저빈도 운용 한도 143달러가 함께 있음,
   **When** 운영자가 자금 화면을 봄, **Then** 두 금액은 각각 준비 예산과 현재 운용 한도로
   분리되고 합산 자산처럼 표시되지 않는다.
2. **Given** 계좌 순자산 집계가 검증되지 않음, **When** 계좌 요약을 봄,
   **Then** 총자산·주문 가능 현금·평가액은 확인 대기로 표시되고 0달러로 표시되지 않는다.
3. **Given** 전략 범위에서 체결·투자·손익이 명시적으로 0으로 검증됨,
   **When** 운용 자금 카드를 봄, **Then** 0의 측정 범위와 기준 시각이 함께 표시된다.
4. **Given** 자금 자료가 허용 시간을 넘김, **When** 화면을 봄,
   **Then** 해당 카드만 오래됨으로 바뀌며 묶음 생성 시각이 이를 정상으로 덮지 않는다.

---

### 사용자 이야기 2 - 활성·준비·연구 전략을 구분 (우선순위: P1)

운영자는 전략 화면에서 실제 운영 중인 저빈도 캐너리, 아직 실거래가 꺼진 단타 준비 경로,
연구 중인 후보를 서로 구분한다. 각 전략의 역할, 자본 범위, 증거 진행도, 최근 실행, 다음 실행,
승격 차단 사유를 확인한다.

**이 우선순위인 이유**: 운영 검증용 전략을 수익성이 확정된 전략으로 오해하거나 준비 예산을
실제 배치 자금으로 오해하면 안 된다.

**독립 시험**: 운용·준비·연구 상태가 섞인 예제에서 운영 중인 전략과 실거래가 꺼진 전략,
승격 불가 사유를 5초 안에 찾을 수 있는지 확인한다.

**인수 시나리오**:

1. **Given** 저빈도 전략이 운영 검증용 캐너리로 무장됨, **When** 전략 카드를 봄,
   **Then** 전략 식별자, 운영 검증 역할, 알파 미확정, 자본 한도와 체결 상태가 함께 표시된다.
2. **Given** 단타 준비 기준만 확정되고 실제 주문 권한은 없음, **When** 준비 중 전략을 봄,
   **Then** 실거래 꺼짐, 실제 주문 0건과 남은 증거 조건이 표시된다.
3. **Given** 연구 자동화가 오래됐거나 후보가 없음, **When** 연구 영역을 봄,
   **Then** 지연 또는 승격 후보 없음이 명시되고 기존 운영 전략 상태와 섞이지 않는다.

### 사용자 이야기 3 - 최신 자료인지 항목별로 판단 (우선순위: P1)

운영자는 앱을 열거나 다시 전면에 띄우거나 직접 새로고침할 때 최신 공개 자료를 읽는다.
앱이 열려 있는 동안에도 주기적으로 확인하며, 시스템·자금·전략은 각 원천 시각을 기준으로
신선도를 판단한다.

**이 우선순위인 이유**: 최신 묶음 안에 오래된 자금 또는 전략 요약이 포함될 수 있으므로
묶음 시각 하나만으로 신뢰하면 안 된다.

**독립 시험**: 묶음은 새롭지만 자금 원천만 오래된 자료, 앱 복귀, 네트워크 단절과 원본 갱신
상황을 재현해 각 영역의 표시와 갱신 동작을 확인한다.

**인수 시나리오**:

1. **Given** 앱이 전면에 있음, **When** 1분이 지남, **Then** 새 상태를 다시 조회한다.
2. **Given** 앱이 배경에서 전면으로 돌아옴, **When** 복귀함, **Then** 즉시 새 상태를 조회한다.
3. **Given** 핵심 돈·전략 원본 보고가 완료됨, **When** 발행 경로가 정상임,
   **Then** 5분 안에 앱용 상태 자료가 새 원천 시각을 포함한다.
4. **Given** 네트워크가 끊김, **When** 마지막 성공 자료를 봄, **Then** 오프라인과 각 원천의
   기준 시각을 표시하고 과거 정상 상태를 현재 정상으로 승격하지 않는다.

---

### 사용자 이야기 4 - 작은 화면에서 핵심 운영판 사용 (우선순위: P2)

운영자는 `홈`, `자금`, `전략`, `시스템` 네 영역을 하단에서 이동하고, 앱 설명은 별도 정보
화면으로 연다. 선택한 `Claymorphism + Vibrant & Block-based` 스타일은 유지하되 상태와 숫자의
의미가 장식보다 먼저 읽힌다.

**이 우선순위인 이유**: 중요한 자금·전략 정보가 추가되어도 작은 휴대폰과 큰 글자에서 빠르게
탐색할 수 있어야 한다.

**독립 시험**: 작은 화면과 200% 글자 크기에서 네 영역, 정보 화면, 경고·시간·금액이 겹치거나
잘리지 않는지 확인한다.

**인수 시나리오**:

1. **Given** 앱이 정상 자료를 읽음, **When** 홈을 봄, **Then** 전체 상태 다음에 현재 운용
   한도·실제 투자금·활성 전략·단타 준비·시스템 요약이 순서대로 표시된다.
2. **Given** 글자가 200%로 확대됨, **When** 네 영역을 이동함, **Then** 좌우 스크롤 없이
   핵심 문구와 값이 읽히고 터치 영역이 유지된다.
3. **Given** 운영자가 정보 버튼을 누름, **When** 설명 화면이 열림, **Then** 읽기 전용 범위,
   출처, 기준 변경과 앱이 하지 않는 일이 표시된다.

---

### 사용자 이야기 5 - 금융 화면의 사생활 보호 (우선순위: P2)

운영자는 자금 화면을 기기 인증으로 열고, 앱이 배경으로 이동했을 때 앱 전환 화면에 금액이
남지 않게 한다. 인증 기능을 사용할 수 없는 기기에서는 비공개 계좌 값을 노출하지 않는다.

**이 우선순위인 이유**: 읽기 전용이라도 계좌 금액과 보유 정보는 개인 금융정보다.

**독립 시험**: 인증 성공·실패·취소·지원 불가와 앱 배경 전환을 재현해 금액 노출 여부를 확인한다.

**인수 시나리오**:

1. **Given** 기기 인증을 사용할 수 있음, **When** 자금 화면을 처음 엶,
   **Then** 인증 성공 후에만 보호 대상 내용을 표시한다.
2. **Given** 인증이 실패하거나 취소됨, **When** 자금 화면을 봄,
   **Then** 잠금 안내만 보이고 보호 대상 금액은 나타나지 않는다.
3. **Given** 앱이 배경으로 이동함, **When** 앱 전환 미리보기가 만들어짐,
   **Then** 전체 화면이 불투명한 보호막으로 덮이고 복귀 시 다시 인증한다.

### 경계 상황

- 총계좌 자산은 미확인인데 전략 범위 0달러가 검증된 경우 두 상태를 따로 표시한다.
- 통화가 USD가 아니거나 숫자 형식이 잘못되면 금액으로 변환하지 않고 확인 불가로 표시한다.
- 자금·전략 요약이 누락돼도 기존 시스템 자동화 화면은 계속 사용할 수 있어야 한다.
- 새 자료와 캐시 자료의 개별 원천 시각이 미래이면 해당 영역을 신선하다고 판단하지 않는다.
- 전략 식별자나 차단 사유가 없으면 임의 이름·정상 사유를 만들지 않는다.
- 같은 실행에서 HTML과 앱용 자료가 서로 다른 자금·전략 의미를 보여주면 발행을 실패 처리한다.
- 인증 과정은 주문·자본·전략 변경 권한으로 사용되지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 `홈`, `자금`, `전략`, `시스템` 네 탐색 영역을 제공하고 설명은 별도
  정보 화면으로 제공해야 한다.
- **FR-002**: 홈은 전체 상태 다음에 현재 운용 한도, 실제 투자금, 활성 전략, 단타 준비와
  시스템 요약을 표시해야 한다.
- **FR-003**: 자금 화면은 총계좌 자산·주문 가능 현금·보유 평가액, 준비 예산, 현재 운용 한도,
  실제 투자금, 실현·미실현·총손익과 위험 한도를 의미별로 구분해야 한다.
- **FR-004**: 확인되지 않은 계좌 금액은 `확인 대기`로 표시하고 0 또는 기존 참고값으로
  대체하지 않아야 한다.
- **FR-005**: 0으로 표시되는 금액에는 명시적인 측정 성공 상태, 측정 범위와 기준 시각이
  있어야 한다.
- **FR-006**: 시스템은 준비 예산과 현재 운용 한도를 합치거나 전체 자산처럼 표현하지 않아야 한다.
- **FR-007**: 전략 화면은 운용 중, 준비 중, 연구 중 전략을 분리하고 전략 식별자, 역할,
  실거래 상태, 알파 확정 여부, 자본 범위, 대상 종목, 최근·다음 실행과 차단 사유를 표시해야 한다.
- **FR-008**: 전진·라이브 관측의 현재값과 요구값을 함께 표시하고 요구값이 확인되지 않으면
  진행률을 임의 계산하지 않아야 한다.
- **FR-009**: 시스템은 묶음, 시스템, 자금, 전략에 각각 기준 시각을 포함하고 기기 현재 시각으로
  경과 시간을 다시 계산해야 한다.
- **FR-010**: 앱은 시작, 전면 복귀, 수동 새로고침과 전면 사용 중 1분 간격으로 상태를 조회해야 한다.
- **FR-011**: 핵심 자금·전략 원본이 완료되면 정상 발행 환경에서 5분 안에 앱용 자료가 갱신돼야 한다.
- **FR-012**: 네트워크 실패 시 마지막 성공 자료를 오프라인 표시와 함께 제공하되 개별 원천의
  오래됨을 숨기지 않아야 한다.
- **FR-013**: 앱용 자료와 화면은 KIS 키, 계좌번호, 접근 토큰, SSH 정보, 원시 감사 장부를
  포함하지 않아야 한다.
- **FR-014**: 비공개 계좌 값은 인증된 읽기 전용 자료가 검증된 경우에만 표시할 수 있고,
  공개 자료나 예제 값으로 대체하지 않아야 한다.
- **FR-015**: 자금 화면은 기기 인증 뒤에만 보호 대상 값을 표시하고 앱이 배경으로 이동하면
  즉시 다시 잠겨야 한다.
- **FR-016**: 기기 인증을 사용할 수 없거나 실패·취소되면 보호 대상 값을 가리고 기존 공개
  운영 요약만 계속 제공해야 한다.
- **FR-017**: 앱 전환 미리보기에서는 전체 화면을 불투명한 보호막으로 덮어야 한다.
- **FR-018**: 앱, 상태 발행과 인증은 주문, 실거래 활성화, 중단 해제, 자본 배분, 전략 변경,
  종목·한도 변경 기능을 포함하지 않아야 한다.
- **FR-019**: 기존 HTML 상태판, 텔레그램 알림, 자동매매 worker와 기존 `status.json` 소비자는
  새 기능 실패와 관계없이 계속 동작해야 한다.
- **FR-020**: 추가된 카드와 탭은 아이콘·문구·색상으로 상태를 표현하고 작은 화면과 200%
  글자 크기에서 핵심 값이 잘리거나 가려지지 않아야 한다.
- **FR-021**: 상태 자료는 자료 형식과 읽기 전용 선언을 확인하고, 필수 필드가 손상됐을 때
  해당 영역을 정상으로 표시하지 않아야 한다.
- **FR-022**: 운영자가 보는 각 금액은 통화, 의미, 측정 범위, 검증 상태와 기준 시각을 통해
  재현 가능해야 한다.
- **FR-023**: 실계좌 집계가 검증되기 전에는 총자산·주문 가능 현금·평가액을 외부에 발행하지
  않아야 하며, 미검증 사유만 정제하여 표시해야 한다.
- **FR-024**: 앱은 인증이나 네트워크 실패를 자동매매 시스템 장애로 바꾸지 않아야 한다.

### 핵심 개체

- **자금 요약**: 계좌 확인 상태, 준비 예산, 현재 운용 한도, 전략 범위 투자·손익,
  위험 한도와 각 원천 시각을 가진 읽기 전용 자료.
- **계좌 확인 상태**: 총자산·현금·평가액의 검증 가능 여부, 미확인 사유와 보호 수준.
- **전략 요약**: 활성 전략, 준비 중 경로, 연구 상태, 증거 진행도, 실행 상태와 차단 사유.
- **자료 신선도**: 묶음이 아니라 각 원천의 기준 시각, 허용 시간과 현재 기기 시각으로 계산한 상태.
- **사생활 잠금**: 기기 인증 가능 여부, 현재 잠금 상태, 앱 생명주기와 보호막 상태.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 운영자는 앱을 연 뒤 5초 안에 현재 운용 한도, 실제 투자금, 미확인 계좌 값과
  활성 전략 단계를 구분한다.
- **SC-002**: 준비 예산, 운용 한도, 참고 자산과 실제 투자금이 합산 자산으로 표현되는 시험이 0건이다.
- **SC-003**: 미확인·누락·손상·미래 시각 자료 시험의 100%가 0 또는 신선한 정상 이외로 표시된다.
- **SC-004**: 핵심 돈·전략 원본 완료 후 정상 발행 환경에서 5분 이내 앱용 자료 반영률이 100%다.
- **SC-005**: 앱 시작·전면 복귀·수동·1분 주기 갱신 시험이 모두 통과하고 중복 동시 조회가 없다.
- **SC-006**: 작은 화면과 200% 글자 크기에서 네 탐색 영역과 핵심 상태·금액·시간이 잘리거나
  가려지는 경우가 0건이다.
- **SC-007**: 인증 실패·취소·지원 불가·배경 전환 시험에서 보호 대상 값 노출이 0건이다.
- **SC-008**: 공개 발행물에서 비밀값·계좌번호·접근 토큰·원시 감사 자료 검출 건수가 0건이다.
- **SC-009**: 앱 또는 발행 실패가 만든 주문, 자본 변경, 전략 변경과 기존 자동화 중단이 0건이다.
- **SC-010**: 자동 시험, 정적 검사, 운영 하네스, 인계 사실 검사와 실제 iPhone 설치·실행 확인이
  모두 통과한다.

## 가정

- 사용자는 한 명의 운영자이며 기존 앱과 같은 iPhone을 우선 지원한다.
- 공개 자금·전략 요약은 이미 정제되어 발행되는 자동화 보고와 확정 준비 설정만 사용한다.
- 현재 계좌 조회는 행 수집까지 검증됐지만 집계 순자산 계약은 미완료이므로 총계좌 금액은
  확인 대기가 정상 상태다.
- 정확한 계좌 값은 집계 계약과 인증된 비공개 조회 경로가 모두 검증된 뒤 같은 화면의 보호
  영역에 채울 수 있다.
- 기기 인증은 금융정보 가림을 위한 것이며 자동매매 권한이나 서버 인증을 대신하지 않는다.
- iOS의 배경 실행 제한 때문에 앱이 닫힌 동안 1분 주기 조회를 보장하지 않고, 중요한 변화는
  기존 텔레그램 경로를 계속 사용한다.

## 비목표

- 휴대폰에서 주문, 실거래 재무장, 중단 해제, 자본·전략·허용 종목·한도를 변경하지 않는다.
- 미검증 USD 행을 합산하거나 대표 행을 골라 총계좌 자산을 만들지 않는다.
- 기존 저빈도 전략과 새 단타 준비 경로의 자본 승인이나 실거래 단계를 바꾸지 않는다.
- 앱이 닫힌 동안 운영체제가 보장하지 않는 1분 백그라운드 갱신을 주장하지 않는다.
- 새 외부 서비스 비용, 새 브로커 권한 또는 별도 원격 제어 기능을 추가하지 않는다.

## 위험 등급과 안전 의미

공개 요약·상태 발행·탐색 구조 변경은 **등급 2(운영 체계 변경)**다. 기기 인증과 향후 비공개
계좌 값 경계는 **등급 3(비밀값·개인 금융정보 안전 경계)** 기준으로 검증한다. 실제 주문,
자본 배정, 전략 승격과 돈 경로는 바꾸지 않으므로 등급 4 실행은 없다.

기존 `status.json`, HTML 상태판, 텔레그램과 worker를 보존한다. 새 요약이 누락되거나 손상되면
자금·전략 영역만 확인 불가로 실패 폐쇄하고 기존 시스템 화면은 계속 제공한다.

## 되돌림

새 자금·전략 요약 발행과 네 탭 UI를 이전 앱 버전으로 되돌려도 기존 HTML·`status.json`,
텔레그램, 자동화, worker와 거래 장부는 그대로 동작해야 한다. 인증·보호막 코드를 제거할 때도
비공개 계좌 값을 공개 자료로 옮기지 않는다. 되돌림은 자본, 전략, 주문, 허용목록, 위험 관문,
비밀값과 감사 로그를 수정하지 않는다.
