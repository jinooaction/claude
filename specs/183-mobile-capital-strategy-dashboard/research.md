# 조사 결과: 모바일 자금·전략 운영판

## 결정 1: 기존 `status.json`을 하위 호환 확장한다

- **결정**: 최상위 `schema_version: "1.0"`과 기존 필드를 유지하고 선택 필드
  `capital_summary`, `strategy_summary`를 추가한다.
- **근거**: 현재 앱은 모르는 필드를 무시하지만 최상위 버전이 달라지면 문서 전체를 거부한다.
  기존 앱과 정적 HTML 상태판을 멈추지 않으면서 새 앱만 확장 필드를 사용할 수 있다.
- **기각**: 새 `/v2/status.json`은 발행·캐시·운영 링크를 중복시키고 두 문서의 의미가 갈라질
  위험이 있다.

## 결정 2: 공개 원천에서 허용 필드만 새 문서로 조립한다

- **결정**: `money-path`, `rebalance-live-canary`, `autonomous-strategy-factory` 사이드카와
  기능 182의 확정 준비 계약을 읽되, 출력은 명시된 필드만 새 사전으로 구성한다.
- **근거**: 원문 사이드카에는 실행 번호·상세 주문 로그·참고 NAV처럼 모바일 공개 화면에
  그대로 옮기면 안 되는 정보가 섞일 수 있다.
- **기각**: 원문 JSON을 통째로 중첩하면 향후 원천 필드 추가가 곧 공개 범위 확대로 이어진다.

## 결정 3: 계좌 집계 미완료는 숫자가 아닌 `UNVERIFIED`다

- **결정**: 총자산, 주문 가능 현금, 보유 평가액은 `null`과 정제된 한글 사유를 발행한다.
  `money-path.account_nav_usd`는 현재 자본 사다리의 참고 기준일 뿐 검증된 총계좌 집계로
  승격하지 않으며 모바일 출력에 포함하지 않는다.
- **근거**: KIS 조회 행 수집은 검증됐지만 여러 USD 행을 총계좌 값으로 집계하는 계약은 아직
  완료되지 않았다.
- **기각**: 참고 NAV나 대표 행을 계좌 총액으로 보여주면 운용 한도와 총자산을 혼동시킨다.

## 결정 4: 전략의 역할을 상태보다 먼저 표시한다

- **결정**: 저빈도 전략은 `OPERATIONAL_CANARY`, 단타는 `PREPARATION_ONLY`, 자동 전략
  공장은 `RESEARCH_ONLY`로 고정 분류하고 각각 실제 주문 가능성, 알파 확정, 증거 진행도와
  차단 사유를 별도 표시한다.
- **근거**: 운영 배관 검증용 10% 캐너리는 수익 우위 확정이 아니며, 단타 600달러는 준비
  파라미터 승인이지 배치 자본이 아니다.
- **기각**: `ACTIVE/INACTIVE` 한 축만 쓰면 운용 중과 수익성 확정을 같은 뜻으로 오해할 수 있다.

## 결정 5: 원천별 신선도를 앱에서 다시 계산한다

- **결정**: 자금·전략 요약은 각각 `as_of_utc`와 `max_age_minutes`를 내보내고, 앱은 현재 기기
  시각과 비교해 `신선함/오래됨/확인 불가`를 계산한다. 미래 시각은 확인 불가다.
- **근거**: 새로 생성된 묶음 안에 오래된 원천이 들어갈 수 있다.
- **기각**: `generated_at_utc` 하나만 사용하면 과거 돈 상태를 현재 상태처럼 보이게 한다.

## 결정 6: 주요 워크플로 완료 이벤트에 발행을 연결한다

- **결정**: 기존 일일 예약과 수동·push 발행을 유지하고, 돈 경로·라이브 캐너리·첫 수익
  증거·전략 공장 완료를 `workflow_run`으로 받아 정적 자료를 다시 만든다.
- **근거**: 5분 목표를 일일 1회 스케줄만으로는 만족할 수 없다. 발행은 읽기 전용이며 원천
  워크플로를 재실행하거나 거래 경로를 호출하지 않는다.
- **기각**: 모바일 앱이 각 사이드카 브랜치를 직접 읽으면 GitHub 권한과 원천 해석이 앱에
  새어 나가고 발행 계약이 분산된다.

## 결정 7: 기기 인증은 UI 잠금이며 서버 권한이 아니다

- **결정**: Flutter `local_auth`로 자금 화면을 메모리 내에서만 열고, 배경 이동 즉시 잠그며
  전체 화면에 불투명 보호막을 올린다. 인증 불가·실패·취소 시 공개 운영 요약만 유지한다.
- **근거**: 현재 검증된 비공개 계좌 조회 API가 없으므로 토큰이나 계좌 비밀값을 앱에 넣을
  이유가 없다.
- **기각**: 인증 성공을 서버 주문 권한이나 영구 로그인으로 사용하면 읽기 전용 경계를 깨뜨린다.

## 결정 8: 200% 글자 크기는 세로 흐름으로 흡수한다

- **결정**: 고정 높이와 가로 금액 행을 피하고 `Wrap`, 세로 카드, 스크롤, 최소 48px 터치
  영역을 사용한다. 선택한 Claymorphism 색·그림자·굵은 블록은 유지하되 의미 라벨을 생략하지 않는다.
- **근거**: 작은 iPhone에서 네비게이션과 큰 글자가 동시에 유지되어야 한다.
- **기각**: 글자 크기를 강제로 제한하면 접근성 성공 기준을 만족하지 못한다.
