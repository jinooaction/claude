# Feature Specification: 실행 검증의 코드 연결 보완

**Feature Branch**: `codex/197-execution-source-identity`
**Created**: 2026-09-28
**Status**: Draft
**Input**: 기존 한국투자 단타 프로그램 완성. 실제 코드 변경 검출 누락을 재현했으므로 과거 검증과 현재 실행의 연결을 보완한다.

## User Scenarios & Testing

### User Story 1 - 변경된 실행에 옛 검증을 재사용하지 않는다 (Priority: P1)

운영자는 주문·취소·인증·위험 검사·시세 정규화·장부 코드가 바뀌면 이전 실행에 대한 검증이 그대로 유효한 것으로 처리되지 않기를 원한다.

**Why this priority**: 다른 실행 방식에 대한 체결·관찰 증거를 현재 코드의 증거로 오인하면 안 된다.
**Independent Test**: 네 경로의 코드 변경을 각각 주입하면 실행 지문이 달라지고 과거 지문에 묶인 자격이 거부된다.

**Acceptance Scenarios**:
1. **Given** 검증된 실행 지문, **When** 공통 주문·취소·인증·위험·시세·장부 코드를 변경, **Then** 지문이 바뀐다.
2. **Given** 과거 지문에 묶인 등록·실행 자격, **When** 현재 코드가 다름, **Then** 새 권한으로 자동 갱신하지 않고 기존 불일치 거부를 유지한다.

### User Story 2 - 재현 가능하고 제한된 코드 범위를 확인한다 (Priority: P1)

동일한 코드와 후보는 같은 실행 지문을 만들며, 관련 없는 연구 문서 변경으로 실행 검증이 무효화되지 않는다. 필수 코드의 부재나 읽기 실패는 성공으로 숨기지 않는다.

**Independent Test**: 동일 입력의 반복 계산·다른 체크아웃 경로는 같고, 필수 파일 누락·교체·목록 중복은 실패한다. 연구 문서 변경은 영향을 주지 않는다.

**Acceptance Scenarios**:
1. **Given** 같은 후보·공급자·코드, **When** 지문을 재계산, **Then** 동일하다.
2. **Given** 필수 파일 누락·읽기 불가·변경 중인 파일, **When** 검사, **Then** 과거 성공 지문을 반환하지 않는다.
3. **Given** 새 실행 의존 코드, **When** 검증, **Then** 검토 목록의 누락을 감지한다.

### Edge Cases

같은 이름의 다른 경로, 경로 순서·중복, 파일 삭제·읽기 실패·링크 교체, 검사 중 변경, 기존 지문에 묶인 자격, 문서만 변경, 외부 라이브러리·동적 적재와 로컬 소스 범위의 혼동.

## Requirements

- **FR-001**: 기존 실행 지문에 묶인 파일을 모두 보존하고, 공통 주문·취소·인증·위험·시세·장부의 검토된 의존 코드를 추가한다.
- **FR-002**: 파일의 저장소 상대 경로와 내용 지문을 함께 고정하고, 같은 코드의 체크아웃 위치 차이는 무시한다.
- **FR-003**: 필수 파일 부재·중복·읽기 실패·비정상 교체에는 성공 지문을 반환하지 않는다.
- **FR-004**: 변경 전후의 실행 지문을 구분한다. 기존 등록·전진 관찰·체결 동등성·서버 권한을 자동 재발급하거나 허용하지 않는다.
- **FR-005**: 지원하는 로컬 의존 관계의 목록 누락을 회귀 검사로 감지한다. 동적 적재·외부 라이브러리까지 검증했다고 주장하지 않는다.
- **FR-006**: 같은 후보·공급자·코드의 재현성과 관련 없는 문서 변경의 비영향을 확인한다.
- **FR-007**: 실제 실행 자격의 변경 거부와 주문·청산·재시작 자체 시험을 검증한다. 승인 파일이나 계좌 자본을 변경하지 않는다.

### Key Entities

실행 소스 목록, 상대 경로별 내용 지문, 후보·공급자 결합 지문, 과거 지문에 묶인 자격.

## Success Criteria

- **SC-001**: 재현된 네 누락 경로와 검토 목록의 코드 변경을 모두 검출한다.
- **SC-002**: 필수 파일 누락·읽기 실패와 과거 지문을 사용하는 자격에서 거짓 성공이 없다.
- **SC-003**: 관련 없는 연구 문서 변경의 지문 영향은 없다.
- **SC-004**: 기존 위험·주문·자본 제한과 전진 관찰 조건을 보존하며 실제 주문·자본 배정은 0이다.

## Assumptions and boundaries

위험 등급3: 실행 자격의 검증 경계를 강화한다. 기존 184의 주문/종목20%, 전체80% 한도와 고정 예산, 허용 종목, 감사, 비밀 분리, 외부 API 방어, 장중 배포 제한을 변경하지 않는다. 금액이나 자본 비중을 새로 설정하지 않는다. 단타 반복 실거래 권한을 발급하지 않는다.
코드 파일 지문은 실행 중인 메모리·공급망 전체의 인증이 아니다. 외부 패키지 버전과 운영 환경·모형 동등성은 독립 조건이다. 정적 의존 관계만으로 동적 적재까지 완전히 증명하지 않는다.
되돌림은 코드 배포를 되돌리되 새 지문을 옛 권한으로 자동 변환하지 않는 것이다. 기존 원본·등록·관측·감사를 삭제하지 않는다. 전체181 T013~T016은 이 수정으로 완료되지 않는다.
