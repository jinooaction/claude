# 원본 범위 현금과 관측 구간 모델

## 시장 수집 출처

FR049의 collect_attested_kis는 고정 KIS 경로의 인증·GET과 수집 시계를 직접 소유하며,
고정 root 소유32바이트 키로 수집 코드/정규화된5종목 봉/수집 시작·수신 시각을 묶는다.
--attest-market-data에서만 사용하고 사용자 원본 파일을 서명하는 명령은 없다.
증명을 모의 사건 해시에 포함하고 독립 재생 때 서명과 실제 봉, 현재 수집 코드, 수신
시각을 검사한다. 모든 완결 세션의 모든 봉이 통과할 때만 수집 출처 확인이 참이다.
서명 없는 진단 기록은 보존하며 출처 확인에는 사용하지 않는다. 서버 키 관리자와
수집 코드/시계를 신뢰하는 증명이지 KIS가 발급한 서명은 아니다. 자격 소비 결과에
TRUSTED_SERVER_COLLECTOR를 표시하며 전체 계좌/실행 모델 검증이나 운영 승인은 별개다.

## 보고 현금

실제 foreign-margin 응답을 기존 observe_account가 USD로 분류·정규화한 뒤 계산한다.
USD 행 하나, 미분류 행0, 미결제매수/매도·미수·증거금0인 경우에만 frcr_dncl_amt1을
해당 행의 보고된 결제 현금으로 제공한다. 모든 값은 문자열 소수로 검증한다. 기존
구매가능액은 이 식에 사용하지 않는다. 다른 통화·계좌 상품·부채의 부재를 이 행으로
추론하지 않으며 full_account_verified=false다. 그 외에는 금액 없음과 오류 원인을
반환한다. 공개 진단에는 상태/범위/원인만 있고 금액은 없다.

## 관측 구간

하한은 order_state_history의 SUBMITTING 기록이다. OrderRouter는 실제 HTTP 전송
전에 이 상태를 기록한다. 상한은 실제 인증된 양수 체결 조회가 끝난 직후의 로컬 시각이다.
통신 전에 저장한 과거 FILL 관측 시각이나 주문 접수 시각은 사용하지 않는다. 같은 주문의
기록이 여러 번이면 가장 이른 전송 전 시각을 사용한다. 누적 체결 수량 전체가 그 구간
어디서든 발생할 수 있다고 가정한다. 계좌/주문번호/전략 대응은 기존 비용 대조가 검사한다.
로컬 시계와 원본 장부, 동일 계좌의 응답 진실성은 이 모델의 명시적 신뢰 전제다.

FR047 이후 신규 FILL 감사의 broker_response_received_at_utc는 실제 체결 GET 완료
직후 시각이다. 같은 주문의 모든 체결번호/수량/가격과 감사의 주문/종목/전략을 대조하고,
모든 수신 시각이 전송 전 시각 이상·현재 조회 수신 이하인 경우만 그중 가장 늦은 시각을
상한으로 사용한다. 재시작해도 이 근거는 남는다. 기존 observed_at_utc는 요청 전 논리적
시각일 수 있으므로 대신 사용하지 않는다. 누락/중복/불일치/잘못된 시각이면 현재 GET의
넓은 구간을 유지한다. 과거 감사나 체결 시각은 변경하지 않는다.

각 주문의 닫힌 시간 구간에 걸치는 모든5분 봉이 필요하다. 상한이 봉 경계와 같으면 다음
봉도 필요하다. 각 봉에는 그 봉에서 체결됐을 수 있는 같은 종목 주문들의 수량 전체를
합산하고 `합산수량 <= 봉거래량 * 참여율`을 검사한다. 매수/매도도 같은 거래량 예산을
쓴다. 빈 봉·미완결/미래 봉·중복 봉·누락 구간·불명확한 시각은 통과하지 않는다.
구간은 최대7일, 주문1만개, 입력 봉/평가 봉16만개로 제한해 계산 자원을 제한한다.

이 방식은 정확한 체결 시각 없이도 구간 전체에서 거래량 한도를 만족하는지를 계산한다.
다만 supplied bars의 원본 인증·완결성 증명, 기존 다음 봉 가격/수량 연구 모델과의
동등성, 수수료/순현금/실제 운용 승인을 대신하지 않는다. 따라서 비용 증명의 미충족
조건을 삭제하지 않으며 full_execution_parity_verified=false를 유지한다.
구간·봉·참여율·검사 시각은 기존 비용 지문과 함께 별도 interval_digest에 묶는다.
현재 조회가 늦어 구간이 넓거나 봉이 부족하면 모델은 실패하며 임의로 구간을 좁히지 않는다.

## 검증과 되돌림

모의 HTTP→실제 계좌 분류/계산, 실제 체결 GET→SQLite 전송 전 기록→구간 생성,
두 봉 중 하나의 낮은 거래량·동시 주문의 합산·봉 경계·누락/중복/미래·소수 정밀도·
범위 밖 잔고를 검사한다. 실행 권한은 변경하지 않으며 코드 복구로 되돌릴 수 있다.
기존 실행 장부나 감사 행을 수정/삭제하지 않는다.
