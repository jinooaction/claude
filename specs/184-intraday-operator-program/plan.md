# 구현 계획: 단타 실행 프로그램

## 기술 환경

Python 3.11+, httpx, SQLite, asyncio, websockets 15~17의 asyncio 전송.
기존 `scripts/intraday_runtime.py`와 `PaperRuntime` 장부를 재사용한다.
새 시세 입력은 기존 기본 비활성 `realtime.py`와 분리해 기존 워커 동작을 바꾸지 않는다.

## 헌법 점검

등급 4(기존 계좌 재사용 후속 포함). 허용 종목, 현금·계좌 검증, 주문 권한, 단계별 자본, 공용 거래 DB와
계좌 잠금, 감사 로그, 장중 배포 금지는 그대로 유지한다. 공식 시세 접속과
외화 구매력 GET만 새로 실행 가능하다. 모의 장부는 실거래 공용 장부와 구분한다.
전체 계좌 NAV를 임의로 만들거나 사용자 기준선을 브로커 검증값으로 승격하지 않는다.

## 조사 및 결정

계획 기술의 독립 조사 두 건(operator_runtime_research, kis_inputs_research)을 수행했다.
결과와 공식 출처는 research.md에 기록한다. 주입형 시세 코드에는 실제 전송·발생시각이
없었고, 고정 AAPL/1 구매력 조회는 주문별 상한으로 사용할 수 없었다.
전체 NAV 입력과 실제 단타 권한은 미완료이며 시세 연결 성공으로 완료 처리하지 않는다.

## 구조

- src/auto_invest/broker/intraday_inputs.py: 엄격한 체결 파서, 실제 전송, 외화 구매력.
- scripts/intraday_operator.py: run/status/stop/quotes/buying-power의 단일 진입점.
- tests/unit/test_intraday_inputs.py: 프로토콜·수량·시각·비밀 오류 경계.
- tests/integration/test_intraday_operator.py: 실제 로컬 전송, 수명주기, 명령 연결.

## 순서와 검증

1. 명세·입력 계약·작업 목록을 작성한다.
2. 순수 파서와 외화 구매력 조회를 구현하고 반례 테스트한다.
3. 실제 웹소켓 전송·해지·연결 종료와 캐시 무효화를 검증한다.
4. 기존 모의 실행기를 단일 명령의 지속 운용·상태·중지로 연결한다.
5. 문서 명령을 실제 실행하고 관련 주문 엔진 회귀, 전체 테스트, 린트, 하네스를 확인한다.
6. 사용자 전체 목표의 미완료 실주문 연결은 숨기지 않고 초안 PR에 남긴다.

## 복구

신규 모의 프로세스를 협조적으로 중지하고 기존 실행 명령으로 돌아갈 수 있다.
기존 장부·봉 자료·감사 기록을 삭제하거나 재작성하지 않는다. 실거래 배포·가동은 하지 않는다.

## 기존 계좌 재사용 후속 구현

운영자는 기존 한국투자 계좌 사용을 확정했다. 새 계좌 개설을 요구하지 않는다.
기존 일일 대조의 외부 보유 기준표 계약을 단타 엔진에도 적용한다. 위험 등급4이며
명세 FR-009~011, 자료 모델, 실행 계약과 작업 목록을 함께 확장한다.

입력은 기존 `load_external_holdings`의 정규화된 종목·정수 수량 매핑이다.
엔진은 검증한 복사본을 읽기 전용으로 보관한다. `_refresh`는 공용 체결 장부와
기준표 합계가 증권사 수량과 같은지 대조한다. `_owned`는 자기 전략 실제 체결만
추적하는 계약을 유지한다. 일별 기준과 주문 결과에 기준표 해시를 추가한다.
기존 보유 가격도 신선도·전체 노출 검사 대상이다. 기준표 파일 자체는 수정하지 않는다.

실제 KIS 관측과 전략 권한 연결을 이 변경으로 대체하지 않는다. 소수 수량과 미확인 자산은
현재 정수 수량 계약을 통과시키지 않는다. 복구는 엔진 중지 후 변경 커밋 되돌림이며
기본 빈 기준표는 이전 엄격 대조와 동일하다. 신규 테스트에서 기존 보유가 있는
매수·부분 체결·취소·청산·재시작과 미신고 변동 및 노출 한도를 실제 주문 엔진으로 검증한다.

## 실주문 운용 수명주기

등급4, FR-012~016. 기존 엔진에 봉 없이 실행하는 관리 주기를 추가한다.
신규 매수는 전략 판단 경로에서만 가능하며 관리 주기는 보유·미체결 확인, 만료 취소,
기존 손실 방어와 장 마감 정리를 담당한다. 중지 요청과 완료는 추가 전용 DB 기록으로
보존하고, 최종 주문 직전 진입 검사에 중지 상태를 더한다.

새 `execution/intraday_runtime.py`는 DB 경로에 묶인 수명주기 잠금, 실행 식별자 상태,
독립 봉 수집 작업, 관리 우선 주기를 제공한다. 기존 모의 실행기는 그대로 보존한다.
시세 공급 실패 시 진입을 막되 관리 작업은 계속한다. 종료 시 보유가 남으면 정리 완료를
주장하지 않는다. 설정상 주기 제한은 시험·운영 종료 경계이며 실제 잔여 주문을 삭제하지 않는다.
실행 식별자의 소스 해시에 새 운용기 파일도 포함해 운용 제어 변경을 과거 코드의
전략 검증 결과로 실행할 수 없도록 한다. 중지 요청마다 별도 정리 식별자를 사용하므로
같은 날 중지·재개·재중지 시 이전 청산 주문과 충돌하지 않는다.
실행기는 기존 엔진의 관측·권한 계약을 완화하거나 임의 정상값으로 대체하지 않는다.
실주문 운용 모듈의 버전 복구는 새 대조로 STOPPED를 확인한 뒤 진행한다.
미정리 주문·보유가 남으면 이전 코드로 교체하지 않고 같은 코드·식별자로 관측과 권한을
복구하여 정리를 이어간다. 공용 장부·중지 기록·감사 이력은 삭제하지 않는다.

## 보관 자료의 연구 연결

등급2, 기존184 SDD의 FR017/018 확장. 날짜별 KIS 보관 자료가 기존177 검증기로
이어지지 않는 연결 공백을 없앤다. analytics/intraday_archive.py가 원본 지문과
고정 파일명을 확인한 뒤 비공개 임시 스냅샷에서 기존 자료 검증기를 사용한다.
모든 날짜가 완결되고 공급자·수정 정책·합성 여부가 같을 때만 새 연구 폴더에 결합한다.
기존 후보·756세션 기준·판정 로직은 그대로 호출한다. 명령은 자격값이나 네트워크가
필요 없으며 실행 장부를 열지 않는다. 오류는 고정 코드로 공개하고 원본을 보존한다.
동일·누락·변조·공급자 혼합·중복 날짜·기존 출력·CLI 무자격값 시험을 수행한다.
실패 시 신규 명령 사용을 중지하면 되며 기존 수집기·모의 운용·주문 경로는 유지된다.
