## 기술 환경

기존 잔고 점검의 --execution-db는 두 날짜 옵션과 기존 파일을 요구하고 동일 계좌 인증으로

입증하지 않으므로 실행 자격 값은 계속 false다. 결과는 고정 사유와 건수만 공개한다.
모의 HTTP/실제 SQLite를 연결해 누적 부분 체결·중복/외부 주문·수량/금액 차이·미생성 DB·
장부 바이트 보존을 검증한다. 기존 기능/안전장치 제거 없음. 복구는 선택 옵션 사용 중지이며
원본 DB/감사/권한은 수정하지 않는다.

FR-030/031, 등급4. intraday_launch.launch가 기존 설정/비밀값 로더, 이미 생성·변경 적용된

build_kis_program의 내부 자격 검사가 성공한 뒤에만 운용기를 호출한다. 시세는 운용기
소유이며 봉 수집은 기존 ReadTransport/collect_kis를 사용한다. 시작 명령의 신호는
기존 지속 정리 요청으로 전달하고 종료 시 HTTP/DB를 닫는다. 인증 갱신 콜백을 체결
조회 앞에 추가해 초기 빈 토큰·만료 토큰을 체결 조회에 보내지 않는다.
승인에 운용 설정 지문을 추가하여 다른 DB/중지 파일/한도/기준표로 재사용하지 못하게 한다.
오류 결과의 주문0 단정을 제거하고 시작 명령의 종료 코드0은 검증된 STOPPED에만 준다.
실제 계좌 계산/체결 동등성이 미검증인 현 상태는 시작 거절이며 프로그램 전체 완료가 아니다.
모의 계좌/자격으로 실행 시작→중지→동일 장부 재개, 실패 전 네트워크0, 자료 보존과
핸들 닫기를 확인한다. 기존 run/status/stop과 기존 장부/안전장치를 제거하지 않는다.

## 전략 자격 재검사와 운영 승인 구분

FR-028/029, 등급4. prepare_qualification은 현재 코드 커밋을 읽고 select_research와
assess_registered_forward를 순서대로 호출한다. 원본 재계산·60세션·체결 동등성 검사를
통과해야 계좌/전략/자본에 묶인 동기 검사를 반환한다. KIS 구성은 이 내부 공급자를
사용하며 외부 qualify 콜백을 더는 받지 않는다. 일반 모의 조립용 build_program은 유지한다.
서버 root 소유의 고정 승인 파일은 별도 운영자 승인만 증명한다. 관련 검토 지문을 적었다고
실제 체결·캐너리 증거를 머신이 검증한 것으로 해석하지 않는다. 현재 전진 재계산기의
execution_parity_verified=false는 거절되며 생산 자격 전체가 완성됐다는 뜻이 아니다.
승인 파일은 매 호출 다시 읽어 삭제·변경·만료가 즉시 반영된다. 비밀 오류는 고정 코드만
반환한다. 새 검사를 사용 중지하면 기존 내부 모의 조립으로 되돌릴 수 있으며 어떤 장부도
변경하지 않는다. 시험은 합성 승인/의존성 결과로 검사 연결을 검증하고 실제 승인은 발급하지 않는다.

## 생산 계좌 인증 연결

FR-027: 운용기의 장부 잠금 안에서 비동기 자원 수명을 관리한다. KIS 구성 함수는
StrictQuoteFeed와 같은 계좌의 구독 인증을 고정 연결한다. 종료된 시세 작업이나
불완전 시세는 마지막 진입 검사에서 차단하고 원래 검사를 제거하지 않는다.
종료 순서는 봉 수집 취소→시세 연결 취소/닫기→진입 검사 복구→장부 잠금 해제다.
실행 중복·시세 작업 종료·실행 취소·정리 요청 재시작을 실제 엔진/임시 장부로 검사한다.
신규 구성 함수를 사용하지 않으면 기존 운용 수명은 유지되며 원본 장부는 보존한다.

FR-026, 등급4. `build_kis_program`은 같은 라우터의 주문 권한 객체에서 계좌와
인증 정보를 가져와 `KISExecutionObserver`로 연결한다. 기존 인증 캐시/갱신을
재사용하고 매 조회의 토큰을 같은 권한 객체에 갱신한다. 별도 계좌 입력이나
임의 계좌 정상값 주입 경로를 추가하지 않는다. 호스트·계좌·키·연결 변경은 조회
전후에 검사하고 인증 실패는 고정 오류로 숨긴다. 인증 외 계좌 요청은 GET이다.
전체 잔고 계약 검증과 전략 자격·CLI 시작 구현은 별도 잔여 작업이다.
되돌림은 신규 구성 함수 사용 중지이며 기존 수동 조립과 모의 경로는 보존한다.
모의 HTTP로 토큰 발급/캐시 재사용, 계좌 일치, 인증 중 계좌 변경, 오류 비노출,
조회 성공의 미검증 상태 유지와 기존 엔진 통합을 검증한다.
