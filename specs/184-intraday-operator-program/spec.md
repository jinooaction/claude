# 기능 명세: 단타 사용자 실행 프로그램

**Feature Branch**: `codex/184-intraday-operator-program`  
**Created**: 2026-09-08  
**Status**: 구현 중 — 실주문 연결 완료와 구분  
**Input**: “실 사용 가능한 프로그램을 만드는거라니까?”

## User Scenarios & Testing

### 사용자 이야기 1 — 한 실행 창에서 운용 (P1)

사용자는 한국투자 기반 모의 운용을 시작하고, 다른 창에서 상태를 보거나 중지한다.
기존 장부를 그대로 이어 쓰며 중복 실행은 거절한다. Alpaca 계정은 필요 없다.

**독립 검증**: 임시 작업 폴더에서 시작·중복 시작·상태·중지·재시작을 실행하고
이전 장부가 유지되며 중지 요청 후 새로운 수집 주기가 시작되지 않는지 검사한다.

### 사용자 이야기 2 — 실제 발생시각이 있는 시세 (P1)

사용자는 실제 KIS 웹소켓에서 허용 종목의 가격과 발생시각을 확인한다.
끊김·잘못된 응답·오래된 가격은 현재 정상 시세로 표시하지 않는다.

**독립 검증**: 로컬 웹소켓 서버가 복수 체결·구독 응답·연결 종료·이상 프레임을
보내며 실제 네트워크 전송, 신선도 검사, 캐시 폐기를 검증한다.

### 사용자 이야기 3 — 해당 주문의 구매가능 상한 (P2)

사용자가 종목과 지정가를 입력하면 그 요청 그대로 외화 구매가능 금액과 정수 수량을 조회한다.
종목을 고정한 샘플 조회나 통합증거금 대체값을 사용하지 않는다.

**독립 검증**: 요청 파라미터와 금액·수량 계약, 오류·누락·지연 거절을 가짜 HTTP로 검증한다.

### 경계 사례

- 장 휴일·폐장에는 다음 거래 시간을 기다리며 프로세스 생존과 가격 신선도를 구분한다.
- 중지 요청은 모의 운용의 수집 중지다. 보유 청산이나 실제 주문 취소로 표시하지 않는다.
- 구독하지 않은 종목, 25필드 예제, 암호화 프레임, 틀린 건수, NaN, 시간대 불일치는 거절한다.
- 체결 발생시각과 수신시각은 별도 보존한다. 미래·30초 초과·역행 체결은 실행용 캐시에 없다.
- 비밀값·계좌번호·원본 오류 본문은 공개 상태에 남기지 않는다.

## Requirements

### Functional Requirements

- **FR-001**: `scripts/intraday_operator.py`는 `run/status/stop/quotes/buying-power`를 제공한다.
- **FR-002**: `run`은 기존 KIS 모의 장부·봉 수집을 재사용하고 파일 잠금·지속 상태·협조적 중지를 제공한다.
- **FR-003**: 실제 시세 전송을 구현하고 구독 대상·26필드·건수·발생시각을 검증한다.
- **FR-004**: REST 토큰과 웹소켓 키는 기존 비밀값 처리와 공식 호스트를 사용한다.
- **FR-005**: 구매력은 요청 종목·거래소·지정가에 묶으며 현금 또는 전체 순자산으로 이름을 바꾸지 않는다.
- **FR-006**: 테스트는 실제 체결 엔진 기존 회귀와 새 전송·명령 진입점·운영 수명주기를 포함한다.
- **FR-007**: 실제 주문 연결의 미완료 사유를 개발 상태에 기록한다. 모의 운용 성공을 실주문 완료로 승격하지 않는다.
- **FR-008**: 기존 주문 권한, 공용 거래 장부·잠금, 자본 사다리, 장중 배포 제한, 비용 가정, 단계별 자본을 그대로 둔다.
- **FR-009**: 기존 한국투자 계좌를 계속 사용한다(2026-09-08 운영자 확정). 기존 외부 보유 기준표를
  실행 엔진에 명시적으로 전달해 공용 체결 장부 수량과 합산 대조한다. 차이는 자동 흡수하지 않는다.
- **FR-010**: 기존 보유분은 단타 소유·손익·청산 수량에서 제외하고 계좌 전체 평가·노출에는 포함한다.
  동일 종목을 추가 매수해도 단타 실제 체결 수량만 관리하며 재시작·부분 체결·종료에도 보존한다.
- **FR-011**: 기준표는 시작 시 검증하고 복사하여 실행 중 외부 수정으로 바뀌지 않게 한다.
  주문 결과와 일별 기준 기록에 기준표 해시를 남기며 체결을 합성하지 않는다.

### Key Entities

- `SourceQuote`: 구독키, 종목, 거래소, 가격, 한국·현지 원문 시각, UTC 발생시각, 수신시각.
- `BuyingPower`: 요청 종목·시장·지정가, 외화 주문가능 금액·수량, 조회 시작·완료시각.
- `OperatorStatus`: 실행 상태, 마지막 완료 주기, 모의 장부 경로, 중지 여부, 실제 주문 건수 0.

## Success Criteria

- **SC-001**: 문서의 단일 실행 명령으로 기존 18개 사전 등록 전략의 KIS 모의 운용을 시작·재개한다.
- **SC-002**: 중복 실행은 두 번째 수집 전에 거절되고 중지 신호는 대기 중 1초 안에 반영된다.
- **SC-003**: 신선도·구독·복수 레코드 반례가 모두 차단되며 실제 로컬 웹소켓으로 수신한다.
- **SC-004**: 구매력 조회는 올바른 요청만 GET으로 보내고 주문 API를 호출하지 않는다.
- **SC-005**: 가짜 브로커로 기존 보유와 단타 체결의 합산 대조, 기존 보유 미매도,
  재시작·부분 체결·마감 청산, 미신고 수량 변동 차단, 전체 노출 한도를 검증한다.

## Assumptions 및 남은 실주문 작업

- 위험 등급 4: 기존 주문 엔진의 계좌 대조 경로까지 확장했다. 사용자 지시에 따라
  소프트웨어를 구현·검증하며 실제 주문 활성화는 수행하지 않는다.
- 현행 계좌 조회는 전체 현금과 장중 순자산의 완전성을 아직 증명하지 않는다.
  시작 잔고 수동 입력은 외부 입출금·환전·수수료 누락을 자동 해결하지 않아 채택하지 않는다.
- 전략·권한·전체 계좌 관측을 `IntradayExecutor`에 연결하는 실주문 운용은 별도 미완료 항목이다.
  이번 사용자 목표 전체가 완료됐다고 보고하지 않는다.
- 기존 기능 제거 없음. 되돌림은 신규 실행기 중지 및 변경 커밋 되돌림이며 원본 모의 장부를 보존한다.
