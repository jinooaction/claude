# 원본 순자산을 사용하는 대안 검토

상태: 검토 중. 현재 입력기의 검증값이나 T009/T010 완료 상태를 변경하지 않는다.

## 다시 확인한 근거

공식 투자계좌자산현황 예제는 결제 기준 화면에 대응하는 대상을 **output1**으로
명시한다. 이 설명만으로 output2까지 결제 기준이라고 확정하거나 반대로 현재 기준이라고
확정할 수 없다. 두 부분은 따로 검증해야 한다.

- 공식 예제: https://raw.githubusercontent.com/koreainvestment/open-trading-api/main/examples_llm/domestic_stock/inquire_account_balance/inquire_account_balance.py
- 공식 응답 정의의 output2에는 nass_tot_amt(순자산총금액), evlu_amt_smtl(유가평가금액),
  ovrs_stck_evlu_amt1(해외주식평가금액1), 총자산/대출/원화·외화 항목이 있다.
- 현재 비공개 수집기는 이미 이 숫자 필드를 엄격히 읽으며 두 번 조회한다.
- 실제 관측에서 output1의 순자산 합과 output2의 순자산총금액은 다르다. 따라서
  두 숫자를 같은 범위로 취급하거나 합계 차이를 임의 오차로 허용하지 않는다.

## 검토할 대안

현금 구성의 미확인 포함 관계를 추정해 합산하는 대신, 같은 보고의 명시적 계좌
순자산과 주식 평가 부분을 분리하는 방법을 확인한다. 계좌 원본 순자산에서 **같은
범위·통화·기준의 주식 평가**를 뺀 잔여값을 비주식 순자산으로 보존하고, 현재 확인한
보유의 실행 시세/보고 평가를 다시 더하는 방식이다. 기존 내부 net_cash 계약은
비주식 자산과 채무를 포함하지만, 별도 주문가능금액은 실행 가능 현금으로만 사용한다.

이는 아직 채택된 계산식이 아니다. 공식 순자산 필드가 있다는 사실만으로 전체
현재 계좌 범위, 원화 환산 규칙, 주식 평가의 포함 관계가 증명되지는 않는다.

## 채택 전에 확인할 사항

1. 전체 국가 현재 보유와 일반 미국 보유/OTC 보유의 수량·통화·시장 범위가 일치한다.
2. 원본 순자산과 차감할 주식 평가가 같은 보고·통화·포함 범위인지 확인한다.
   evlu_amt_smtl에 해외 평가가 이미 포함됐는지 모르면 별도 해외 평가를 다시 더하지 않는다.
3. 현재 보유와 보고 주식 평가의 대조 및 전후 안정성을 확인한다. 체결 후 오래된
   자산 보고를 현재 상태로 통과시키지 않는 반례를 검증한다.
4. 원화→USD에는 출처가 있는 명시적 보고 환율 정책이 필요하다. 임의 환율이나
   숫자가 맞도록 고른 환율을 쓰지 않는다. 조회 시각을 환율 발생 시각으로 만들지 않는다.
5. 비주식 잔여에 남은 투자자산이 전역 노출 계산에서 빠지지 않아야 한다. 현재 지원
   범위 밖의 자산·채무가 발견되면 이를0으로 없애거나 현금으로 간주하지 않는다.
6. 실제 정상 입력→시작·중지·재시작·복구 시험과 모의 체결 후 순자산 대조가 필요하다.

원본 현금 대조 PR813은 포함 관계의 보조 근거다. 일치 결과만으로 이 계약을 승인하지
않는다. 대안이 충분히 검증되지 않으면 원래 현금 분리 경로를 계속 조사하며, 어느
경로를 채택해도 실제 투자·승인 파일 발급·자금 배분을 수행하지 않는다.
