# 전체 계좌 순현금 의존을 줄이는 대안

상태: 운영자의 이어서 진행 지시에 따라 대안1(전체 보유 노출 제한 유지)을 구현했다.
사용자 시작은 고정 예산 경로를 선택하며 전체 회귀4751개와 린트를 통과했다.
원격 머지/배포 확인은 별도다.
운영 승인 발급·자금 배정·실제 주문은 수행하지 않았다.

## 판단 정정

현재 자료로 기존 전체 계좌 순현금 제공자를 인증하지 못한다는 사실은 한국투자
단타 프로그램을 만들 수 없다는 증명이 아니다. 같은 자료 재조회와 미완료 보고만
반복한 것은 진행이 아니었다. 기존 방식의 불확실성과 다른 설계의 가능성을 구분한다.

## 추천 후보: 기존 계좌의 고정 예산 단타 장부

기존 confirmed-budget.json의 준비 기준은 예산600달러, 주문/종목120달러,
총 노출480달러, 하루 손실 정지 발동12달러다. 이 숫자를 다시 승인된 실제 자금이나
보장된 최대 손실로 해석하지 않는다.

전체 계좌의 정확한 장중 순현금을 주문 크기의 필수 분모로 삼는 대신, 승인된
단타 예산과 해당 프로그램이 생성한 주문·체결·비용·포지션을 별도 관리하는 후보다.
계좌 분리나 실제 이체는 아니며 다른 거래와 같은 증권사 잔고를 공유한다.

- 예산 상태는 확정 지출, 미체결 주문 예약액, 확인된 환급, 비용 미확정 예약액을
  구분한다. 재시작은 저장 장부와 증권사 주문을 대조한 뒤 진행한다.
- 매수 직전 같은 계좌·종목·거래소·지정가의 매수가능금액/수량을 별도 조회한다.
  이것은 해당 주문의 증권사 제약이며 전체 순현금이나 담보 없는 현금의 증명이 아니다.
  요청이 달라지거나 자료가 오래되면 다시 조회한다. 최종 주문 거절도 정상 처리한다.
- 원본 거래대금과 비용은 별개로 기록한다. 비용이 확인되기 전 매도대금을 전액
  새 예산으로 돌려놓지 않는다. 비용 예약 정책의 근거와 상한을 정하지 못하면
  해당 순환의 추가 진입을 보류한다. 정산 완료·해제 기준은 구현 명세에서 확정한다.
- 기존 보유는 단타 소유로 가져오지 않고 임의로 매도하지 않는다. 같은 종목의
  수동 매매나 외부 거래로 소유 수량이 맞지 않으면 신규 진입을 막고 대조한다.
- 주문/종목/총 노출 한도, 허용 종목, 지정가, 거래 시간, 중복 방지, 감사 기록,
  권한, 비밀값 분리와 단계별 검증을 유지한다. 신용·자동환전·미수 사용 가능성을
  매수가능금액 하나로 배제했다고 주장하지 않는다. 계좌 설정과 사용할 응답 필드를
  명시적으로 검증해야 한다.

## 기존 방식과 달라지는 안전 범위

현재 intraday.py는 min(전체 계좌 NAV, 단타 예산)을 기준으로 기존 보유까지
합친 노출을 검사한다. 단타 소유분만 검사하는 고정 예산 방식은 이 검사와 동등하지
않다. 전체 계좌 위험을 관리하던 책임 일부가 프로그램 밖에 남는다. 기존 플래그를
참으로 바꾸거나 view.nav에600을 넣는 수정은 이 대안의 구현이 아니다.

다음 둘 중 어떤 정책을 적용하는지 명세에서 분명히 결정해야 한다.

1. 전체 보유와 예약 주문을 계속480달러 총 노출 한도에 포함: NAV 분모 의존은
   줄일 수 있으나 기존 보유가 한도를 넘으면 새 단타 주문은 불가하다.
2. 단타 소유분에 별도 한도를 적용: 같은 계좌를 계속 쓸 수 있지만 전체 계좌
   노출 제한을 대체하지 않는다. 별도의 계좌 전체 통제와의 역할, 기존 명세·권한·
   단계 검증 변경을 먼저 설계해야 하며 기존 승인으로 자동 활성화하지 않는다.

이 차이를 숨기고 정책2가 기존 안전 범위를 그대로 보존한다고 설명하지 않는다.

## 다른 후보

| 방식 | 장점 | 실제 남는 조건 |
| --- | --- | --- |
| 기존 계좌 고정 예산 | 기존 한국투자 계좌와 실행 장부 재사용 | 위 안전 범위 결정, 현금 전용 여부, 비용 예약/정산 정책 |
| 한국투자 내 단타 전용 별도 계좌 | 기존 보유·외부 거래와 실제 계좌 단위로 분리 | 사용자의 계좌 개설/연결/자금 배정. 미결제·비용·재시작 검사는 여전히 필요 |
| 기존 전체 계좌 방식 유지 | 현재 명세의 전체 위험 통제 유지 | 미결제·수수료 반영과 전체 순자산 범위 근거 확보 |

다른 증권사 가입은 필수 대안이 아니다. 별도 계좌를 임의로 개설하거나 이체하지 않는다.

## 구현 전 확정 및 검증 항목

위 후보를 채택하면 spec/plan/tasks에서 기존 T009/T010의 대체 범위와 완료 기준을
먼저 수정한다. 잔고 인증 플래그를 재사용하지 않는 별도 관측/권한 계약으로 구현한다.
다음 반례가 실행 엔진과 실제 DB 재열기까지 검증돼야 한다.

1. 매수가능금액이 예산보다 크더라도 예산/주문/종목/총 노출 한도 준수.
2. 외부 주문 또는 환전으로 여력이 줄었을 때 새 조회/거절 처리, 자동 재전송 금지.
3. 부분 체결·취소 타임아웃·늦은 체결 중 예약액 조기 해제 및 이중 사용 금지.
4. 미확정 비용·매도 정산액을 확정 현금으로 처리하거나 이익으로 예산 자동 확대 금지.
5. 재시작·중복 인스턴스에서도 동일 주문 및 예산 예약이 한 번만 적용.
6. 외부 보유의 소유 혼합·무단 청산 금지와 정책1/2 각각의 노출 범위 검증.
7. 모의 증권사로 시작·중지·재시작·잔여 주문 관리, 이후 전체 회귀와 별도 운영 검증.

## 구현 현황

BudgetObservation에는 cash/nav가 없다. 예산 장부는 기존 모든 intraday 주문·체결을
사용하며 재시작/날짜/전략 지문 변경으로 초기화하지 않는다. 실제 주문 직전 종목별
매수가능금액·수량과 쓰기 직전 신선도/예산 초과를 검사한다. 부적격 보고는 예산
복구에 쓰지 않고 취소·보유 정리는 비용 수집을 기다리지 않는다.

정산 복구는 같은 거래 보고로 앞뒤를 감싼 거래명세에서 USD·날짜·원래 수량·
거래소·장부 체결량/대금과 보고된 순정산 산술이 맞는 닫힌 그룹만 사용한다. 보고
결제일 당일과 미래는 보류한다. 계산은 누적 가산 대신 원본 장부에서 매번 다시
수행하고 실제 받은 보고를 비공개 추가 전용 사건에 남긴다. 이익으로 예산을 늘리지
않으며 계좌 전체 현금, 향후 비용 부재나 현금 전용 계좌 설정을 인증하지 않는다.

기존 계좌 NAV 모드는 보존한다. 새 모드는 계좌 전체 NAV 손실률 대신 단타 손익의
정지 기준을 사용하므로 두 기능이 같다고 주장하지 않는다. 운영 승인 식별자와 코드
지문이 달라져 예전 승인으로 새 방식을 시작할 수 없다. 새 경로를 되돌릴 때에도
기존 체결·예산 사용 이력·정산 원본·감사 기록은 보존한다.
