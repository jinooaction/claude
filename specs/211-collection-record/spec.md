# Feature Specification: 저장된 수집 시각의 같은 봉 연결

**Feature Branch**: `codex/211-collection-record`  
**Created**: 2026-10-10  
**Status**: 구현·전체검증·병합·예약반영·실제 부재 보존 확인 완료(전체181 미완료)
**Input**: 기존 한국투자 프로그램의 수집 기록과 실제 모의 진단을 구분하고, 최초 처리에 저장된 같은 봉의 원래 시각만 검증한다.

## User Scenarios & Testing

### User Story 1 - 기록된 수집 시각과 관측 시각 구분 (Priority: P1)

운영자는 같은 최초 처리 기록에 수집 시작·반환 시각이 있으면 원래 두 시각과 관측까지의 차이를 확인한다. 이것은 증권사 수신·처리 완료·실거래 자격 판정이 아니다.

**Why this priority**: 다른 재수집의 시각을 첫 처리에 붙이면 관측이 제때였다는 잘못된 결론을 낼 수 있다.
**Independent Test**: 저장된 같은 봉을 읽어 두 원래 시각과 차이를 재현하며 가격·서명 전문 없이 결과를 확인한다.
**Acceptance Scenarios**:
1. 같은 기록에 구조가 맞는 수집 증명과 자료 지문이 있다면 그 시각만 표시하고 인증은 미확인으로 유지한다.
2. 증명이 없다면 시각을 만들지 않고 `PROOF_ABSENT`와 빈 값을 남긴다.
3. 나중의 재수집에 증명이 있어도 처음 저장된 기록에 없으면 최초 기록의 부재를 그대로 남긴다.

### User Story 2 - 잘못된 연결과 과장 방지 (Priority: P2)

운영자는 다른 봉·다른 자료·미래 시각·손상 기록·쓰기 중인 기록을 확인 불가로 받는다. 기존 진단과 손실 제한은 유지한다.

**Independent Test**: 반례마다 구체적 비밀 없이 확인 불가가 되고 기존 장부 파일이 바뀌지 않는지 검사한다.
**Acceptance Scenarios**:
1. 다른 봉 지문, 중복 종목, 시각 역전, 구조 오류는 원래 관측 진단을 보존하면서 수집 연결만 거절한다.
2. 잠금·장부 읽기 실패는 기존 읽기 제한 안에서 확인 불가가 된다.
3. 원래 수집 연결을 출력 영수증에 보관하며 이를 인증 성공이나 전략 합격으로 수정하면 영수증 검증이 실패한다.

### Edge Cases

- 수집 증명 부재·명시 null·잘못된 서명 형식·1초 이하/60초 경계·시계 역전.
- 최신 상태와 장부가 다르거나 마지막 봉이 없음; 야간 게시 및 90초 초과 관측.
- 동일 봉 재처리 생략; 오래된 수집 자료의 최신 파일 시각을 오용함.
- 키·가격·계좌·서명 전문 또는 알 수 없는 필드가 출력에 섞임.

## Requirements

### Functional Requirements

- **FR-001**: 최신 진단과 같은 마지막 장부 기록만 연결한다. 전체 사슬·당시 게시·증권사 인증을 주장하지 않는다.
- **FR-002**: 원래 수집 증명이 있으면 정확한 구조·자료 지문·5개 허용 종목·같은 봉·시각 순서와 최대60초 호출 구간을 확인한다.
- **FR-003**: 수집 시작은 봉 종료 이전일 수 있다. 수집 반환은 모형 봉 종료 이상이고 관측 이하이며 시작 이하 역전은 금지한다. 늦은 관측을 숨기지 않는다.
- **FR-004**: 증명 부재·손상·읽기 실패를 다른 이유와 빈 시각으로 표시한다. 시각·서명·자료를 생성하거나 재수집하지 않는다.
- **FR-005**: 결과는 가격·계좌·키·서명 전문이 없는 4KiB 이하이며 인증·처리완료·제공자게시·정식전진·주문 권한은 미평가다.
- **FR-006**: 기존 읽기 잠금·장부 한도·신선도·모의 손실제한·운용 지문·장부 세대를 보존한다.
- **FR-007**: 기존 영수증은 호환 유지하고 새 수집 결과가 있으면 엄격히 확인한다. 부재를 인증 성공으로 바꾸지 않는다.
- **FR-008**: 중요한 경계의 합성 반례와 전체 원격 검사·린트·하네스·인계·실제 호출 경로 확인 뒤 병합한다.

### Key Entities

- 최초 처리 기록: 저장된 봉·관측 시각·자료 지문·선택적 수집 증명.
- 수집 연결 결과: 원래 시작/반환 시각·관측까지의 차이·국소 연결 범위·인증 미평가.
- 확인 불가 결과: 정해진 사유와 빈 세부 값.

## Success Criteria

- **SC-001**: 정상 원본의 두 수집 시각과 관측 차이가 재현되고, 다른 최초 처리에 연결되는 사례는0이다.
- **SC-002**: 누락·손상·잠금·과장 반례를 모두 거절하며 원래 장부·상태·키 변경은0이다.
- **SC-003**: 정상/부재/손상 결과 모두 가격·계좌·키·서명 전문 노출0, 새 수집·주문0이다.
- **SC-004**: 전체 검사 실패0, 필수 반례 무생략·린트·품질 관문 통과와 정확한 병합 근거를 남긴다.

## Assumptions and Boundaries

위험 등급2: 읽기 전용 진단·영수증·검사 경로 확장이다. 새 기능이므로 풀 SDD를 적용한다.
기존 서버 수집 증명·검증기는 이미 구현돼 있다. 이번 결과는 그 서명을 검증하지 않으며 키를 읽지 않는다.
기존 전체181·1645세션·최소36시도·미개봉495세션·60세션·90초·생산 체결 관문은 보존한다.
계좌 자본·모드·전략·헌법·커널·실주문·비용·수집기 변경은 비목표다. 실제 서버 관측은 합성과 구별한다.
