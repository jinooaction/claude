# Data Model: Candidate Pending Next Actions

## CandidateSupportInputs

Read-only support files prepared before candidate package execution.

| Field | Type | Description |
|------|------|-------------|
| `pipeline_sidecar_dir` | path | `/tmp/candidate_result_sidecars` |
| `public_data_dir` | path | `/tmp/candidate_result_public_data` |
| `source_refs` | list | Git sidecar branches read by workflow |
| `missing_refs` | list | Optional inputs absent at runtime |

## CandidateCommandContract

The generated command string and the result executor allowlist rule that permits it.

| Field | Type | Description |
|------|------|-------------|
| `package_kind` | string | Candidate package kind |
| `command` | string | Exact no-live command generated by factory |
| `allowed_prefix` | list[string] | Token prefix accepted by result executor |
| `requires_support_input` | boolean | Whether workflow staging is required |

## PendingClosureOutcome

Current-sidecar validation result used to decide whether this feature reduced actionable pending causes.

| Field | Type | Description |
|------|------|-------------|
| `pass_count` | integer | Candidate result pass count |
| `pending_count` | integer | Candidate result pending count |
| `diagnostic_counts` | object | Diagnostic code counts |
| `history_candidates_remaining` | integer | Strategy/portfolio candidates still pending on price history |
| `safety_note` | string | No-live safety confirmation |

## Relationships

- Candidate factory creates `CandidateCommandContract`.
- Workflow creates `CandidateSupportInputs`.
- Result executor consumes both and emits `PendingClosureOutcome`.
- Candidate factory consumes result evidence again without changing strategy pass semantics.
