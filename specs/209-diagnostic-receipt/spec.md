# 기능 명세: 읽기 전용 진단 원본 영수증

**Feature Branch**: `codex/209-diagnostic-receipt`
**Created**: 2026-10-07
**Status**: 구현·합성54개·린트·하네스 완료. 원격 전체 검사/실제 영수증/병합 전.
**Input**: 기존 한국투자 프로그램의 실제 운용 증거를 가린 로그의 추측 복원 없이 검증한다.

## User Scenarios & Testing

### US1 — 원래 숫자와 지문을 검증한다 (P1)

운영자는 서버의 읽기 전용 진단을 다시 확인할 때 로그에서 가려진 값을 추측하지 않는다.
독립 시험: 숫자나 해시 일부가 가려진 입력은 거절하고 원래 응답은 정확한 값으로 보관한다.
1. 정상 응답은 원래 생산 지문·모의 수량·관측 시각으로 검증할 수 있다.
2. 중복 필드·가린 값·잘못된 형식·미래 시각·오래된 관측은 유효한 영수증이 아니다.

### US2 — 진단 범위를 보존한다 (P1)

운영자는 모의 보유·체결을 실제 투자 또는 프로그램 전체 완료로 읽지 않는다.
독립 시험: 실주문 수·자격·정식 전진 또는 전체 준비 상태가 바뀐 응답은 거절한다.
1. 기존 상태·0 실제 주문·자격 거짓·전체 준비 미평가를 그대로 보존한다.
2. 관측 프로그램 지문과 서버 생산 지문은 별도이며 불일치는 실제 반영 완료가 아니다.
3. 계좌·가격·키·원래 응답 전문과 알 수 없는 필드는 보관 출력에 들어가지 않는다.

### US3 — 관측 절차를 계속 사용할 수 있다 (P2)

기존 정기/수동 읽기 전용 진단은 계속 실행되고 원격 보관물의 실제 지문을 확인할 수 있다.
독립 시험: 합성/전체 검사에서는 서버 권한을 사용하지 않고 정상 관측에서 작은 영수증만 보관한다.

### Edge Cases

부분 출력, 중복 접두사, 중복 JSON 키, 가림 문자열, 비정상 수량/부울, 무한수, 잘못된 시각,
관측 코드와 다른 서버, 경로/키가 섞인 미지 필드, 실패한 관측, 기존 출력 파일 덮어쓰기.

## Requirements

- FR-001: 읽기는 기존 제한된 서버 진단 명령만 사용한다. 화면·주문·자본·설정·타이머 조작 없음.
- FR-002: 입력 크기는 64KiB 이하이며 원래 응답에서 타입·필수 필드·코드 지문을 검증한다.
- FR-003: 현재1.1 진단 범위·전체 준비 미평가·실주문0·정식 전진0·자격 거짓을 요구한다.
- FR-004: 원래 생산 지문과 관측 프로그램 지문을 구분하고 누락/가린 값을 복원하지 않는다.
- FR-005: 실제 관측 시각·현재 신선도180초·닫힌 마지막 봉을 검증한다. 당시 게시 지연이나 체결 동등성을 추론하지 않는다.
- FR-006: 허용 필드만 작은 원본 영수증으로 보관하며 가격·계좌·키·원래 응답 전문은 제외한다.
- FR-007: 실패하면 안전한 사유만 남기며 유효한 영수증을 만들지 않는다. 기존 파일 덮어쓰기 없음.
- FR-008: 전체 검사/계산과 실제 서버 관측은 GitHub에서 한다. Mac은 합성/작은 증거만 처리한다.
- FR-009: 기존 정기 관측을 유지하고 변경된 관측 경로의 검사·원본 보관 지문을 확인한다.
- FR-010: 전체181 T013~T016·통과 전략·독립 검증·60세션·생산 체결은 별도로 미완료다.

## Key Entities

원래 진단 응답, 관측/생산 코드 지문, 모의 상태와 수량, 관측 시각과 신선도, 추가 전용 검증 영수증.

## Success Criteria

- SC-001: 실제 서버 관측의 지문과 원래 모의 수량을 가림 값 추측 없이 검증한다.
- SC-002: 가림·중복·잘못된 시각·부울 수량·실주문/자격 주장 반례가 모두 거절된다.
- SC-003: 정상/실패에서 키·계좌·가격 원본 누출과 파일 덮어쓰기0이다.
- SC-004: 전체 검사·린트·실제 영수증 지문·병합으로 기능 완료를 재현한다.
